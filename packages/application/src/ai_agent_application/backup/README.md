# Backup / restore gate / migration guard — M5-02

Согласованные копии, восстановление через staging с применением независимого ledger удалений
и защита миграций. Не подключено к composition; агент не запускает, модель не вызывает.

## Копии

- `create(kind)`: консистентный снимок через backup API SQLite (не копия файла: коммиты в `-wal`
  иначе теряются), проверка `integrity_check`/`foreign_key_check`, манифест (форматы, SHA-256,
  размеры, версия схемы, `ledger_id` и счётчик ledger), запись «целиком или никак» (временный
  каталог + rename, права 0700/0600). `.env` не входит; индекс не копируется (пересобирается).
- 7 ежедневных + 2 копии перед миграцией + 2 страховочные перед restore; копия не живёт дольше
  30 дней (сырой текст в копиях подчиняется сроку текста). Квота: предупреждения 80%/90%, при
  заполнении новая копия не создаётся, старые не стираются «ради места». Удалённые копии
  перезаписываются нулями перед unlink (best effort, не гарантия на SSD/CoW).
- Копия ledger на каждый backup кладётся в отдельный каталог (`ledger_dir`), не внутрь копии.

## Restore

`preview_restore(id)` → проверки: checksum/размер/integrity; схема (новее ПО — блок; старее —
нужен мигратор, выполняется в staging); **ledger gate**: нужен тот же ledger (id) и счётчик не
меньше записанного в копии, иначе копия не допускается; агент должен быть `STOPPED`. В предпросмотре:
число областей, незавершённые операции (исход после копии неизвестен), события outbox
(будут заморожены). `restore(preview, decision_id)`: решение оператора, неизменность предпросмотра,
повторная проверка STOPPED → страховочная копия текущей БД → staging: применение ledger,
sweep сроков, повторная проверка (ничего заблокированного не осталось), пересборка индекса,
заморозка outbox, integrity → закрыть живое хранилище → переключение файлов. Старые файлы
остаются в `replaced/` (оператор стирает после проверки). Агент не запускается.
Ошибка на любом шаге staging оставляет живую БД нетронутой.

## Миграции

`guarded_migration(upgrade)`: агент остановлен → копия перед миграцией → проверка → только затем
upgrade; при сбое отчёт называет копию для восстановления (тип ошибки без текста).
`rehearse_migration(upgrade_copy)`: прогон на снимке, живая БД не затрагивается.
