# Задания и доставка (M1-04)

JobOwner — единственный core-владелец Job/попыток. SQLiteJobs использует
принятые repositories/UoW и линейную миграцию 0003. Worker не получает DB.

- Behavior сначала сохраняет ExecutionCommand. submit создаёт Job, scheduling,
  receipt и outbox одной транзакцией. Повтор возвращает состояние.
- Redis передаёт только ID/версию/scope. prepare — явная настройка одной
  consumer group. В заполненный поток нельзя добавить запись; pending не
  обрезаются. XACK+XDEL допускаются только для единственной группы.
- claim требует доверенную WorkerAuthority (из M1-05), текущую Policy,
  исходный cancellation_id и живой запуск. Claim.acquired=True разрешает
  единственное начало этой попытки; False сообщает о уже выданной аренде.
  Повторный False не запускает вычисление и не разрешает ACK до терминального
  состояния. После потери ответа worker сначала читает состояние/сверяет
  попытку; новый процесс не присваивает идентичность прежнего исполнителя.
- Перед I/O worker вызывает verify, heartbeat каждые 5 с вызывает renew.
  Аренда до 20 с, задание до 180 с; refresh сохраняет ID/Event отмены и
  проверяет readiness. Старый snapshot Admission нельзя использовать для
  finish: resolve возвращает текущий snapshot по прежнему cancellation_id.
- Проверка Policy обязательна: scope, версии capability/permission/profile/
  policy/sources, права конкретного действия/передачи данных, условия и
  точная модерация при необходимости. Недоступная проверка закрывает исполнение.
  ExecutionPolicy — доверенный внутренний proof, не worker/LLM JSON.
- accept сохраняет технический результат и owner outbox, затем возможен XACK.
  Это не применение результата/публичный выход. Следующий владелец проверяет
  актуальные права, источники, lease и исходный admission через supervisor
  непосредственно перед собственным handoff/воздействием. История результата
  сама по себе не выдаёт такой допуск. Владелец команды retire после последнего
  потребителя; jobs не отзывает общий admission раньше его handoff.
- Повтор безопасной завершившейся попытки ограничен двумя попытками/сроком,
  с задержкой и jitter 0.75–1.25. FAILED окончателен; transient FAILED может
  перейти WAITING. Для неизвестного/неидемпотентного эффекта нет слепого retry.
- Reclaim Redis не выдаёт lease. Reconcile проверяет DB, run/epoch/admission/
  deadline, старую аренду и retry safety. Порции имеют cursor, чтобы живые
  первые jobs не закрывали доступ к хвосту. Restart закрывает старые задания.
- Истечение lease не подтверждает отмену ресурса. cancel_receipt принимает
  фактическое завершение старого исполнителя, не отменяя новую попытку.
  OUTCOME_UNKNOWN занимает квоту; settle_unknown сохраняет отдельную
  metadata-only квитанцию, оставляет первоначальный результат/историю и
  не возобновляет агента/задание. Usage и канальные статусы остаются у своих
  владельцев (M2-05 и позднейшие задачи).

Все функции вызываются явной композицией. HTTP/service identity — M1-05,
планировщик/полосы нагрузки/циклы poll — M1-06. Bootstrap остаётся STOPPED;
сервисные HTTP handlers, LLM, persona/memory/dialogue не добавлены.
