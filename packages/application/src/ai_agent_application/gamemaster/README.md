# Внутренний гейммастер (M3-02)

`GameMaster` (владелец `Owner.GM`) ведёт линии (`StoryArc`) и возможности (`Opportunity`). Он только
**предлагает**: у него нет канала, API реплик и права писать исход.

- Допуск предложения по порядку: GM открыт (допуск, не пауза, интенсивность > 0) → линия открыта →
  уже открытая та же ситуация → cooldown линии (15 мин, делится на интенсивность) → отдых семейства
  (2 отказа в этой сессии) → окно (3 за 2 ч, × интенсивность) → одно неразрешённое предложение →
  повтор (нужны новое основание и пауза 1 ч) → основания (хотя бы один независимый первичный источник;
  реплики, сводки, рефлексия, модельные источники не основание) → сюжетный допуск.
- Сюжетные правила (`StoryRules.layered`): project > profile > session, hard/soft/desired; нижний слой не
  переопределяет id верхнего. `screen`: маркеры оператора + необязательный классификатор; hard → отказ,
  soft/неуверенность/сбой классификатора → закрыто для оператора (предложение `BLOCKED`, линия `paused`).
- Кубики (`Dice`) вне LLM и только после фильтра: семейство, вариант, сила из диапазона семейства.
  Результат зависит только от seed и контекста (воспроизводимо), `Roll` хранит seed/варианты/веса/результат.
  `suggest`: кубики → модель формулирует ситуацию (без исхода и чужих реакций) → `propose`.
- Жизненный цикл: OFFERED → ACCEPTED (собственный выбор) → REALIZING (контроллер начал действие) →
  RESOLVED только с `resolve(..., evidence)` — независимый первичный источник фактического результата,
  затем `Episode`. Задуманный исход не пишется; персонаж видит `CharacterOffer` без направления линии.
- Пауза GM отменяет ожидающие предложения, сохраняет линии и уже выбранное; STOP/нет допуска закрывает
  всё. Таймеры сами предложений не создают.

Не здесь: панель, хранение seed/Roll в БД (нет типа записи), хранение интенсивности, реальные каналы,
рефлексия и развитие (M3-03). Просроченные записи storage скрывает сам, поэтому статус EXPIRED виден
только до истечения TTL записи.
