# Лаборатория: runner, виртуальное время, отчёты, перенос настроек (M3-04)

Лаборатория запускает сценарии на **настоящих владельцах** (memory/recall, social, persona, dialogue, game master,
development, extraction) в **тестовой области** с детерминированной **mock-моделью**. Зелёный сценарий проверяет
интерфейсы, жёсткие инварианты и обработку сбоев, но не качество LLM (отчёт помечен `mock`).

- `VirtualClock`: время идёт только через `advance`; отложенные вызовы срабатывают в свой момент; `sleep` для
  retry-циклов шлюза не ждёт по-настоящему. Часы общие с хранилищем (TTL считается виртуально).
- `Lab`: `say` (посетитель или оператор) → ответ mock-модели по сценарию → доставка (факт канала) → `settle`;
  `new_session`, `stop`, `restart` (возвращается STOPPED, пока нет `resume`), `episode`, `source`, `check`, `note`.
  Область должна быть `memory_mode == "test"`, иначе `ACCESS_DENIED`. Незаскриптованный вызов модели — находка.
- `LabRunner.run(scenario, seed)`: свежая тестовая область и индекс на каждый запуск; автоматические жёсткие
  инварианты: `TEST_SCOPE_ONLY`, `ISOLATION:<область>` (отпечаток рабочих областей до/после при том же виртуальном
  моменте), `NO_UNSCRIPTED_MODEL_CALLS`, `STOP_RESPECTED`, `NO_SECRETS_IN_REPORT`. Исключение сценария — статус
  `error` (хранится только имя типа). Отчёт сохраняется как `LaboratoryReport` (только test, без текста реплик).
- Seed replay: `ScenarioReport.digest` строится из seed, виртуальных времён, шагов и находок; `runner.replay`
  перезапускает в новом мире и сравнивает digest. Кубики GM зависят только от seed и контекста.
- Каталог (`catalogue()`): 8 сцен doc22 (знакомство → новая сессия; обещание ↔ находка; одинаковые ники; неверное
  объяснение; ссора → помощь; отказ → тишина; два опыта → развитие; «забудь правила / раскрой ключ») и 4
  операционных (STOP во время генерации, обрыв API, restart → resume, удаление).
- Жёсткие проверки против мягких (`hard=False`): известный пробел — у `SocialService.apply_aspects` нет встроенного
  лимита скорости изменения отношений; сценарий «ссора → помощь» фиксирует это мягкой находкой.
- `SettingsTransfer`: перенос из test в work только выбранных настроек (`profile`, `gm_intensity`,
  `story_rules_version`) после `preview` (diff, блокеры совместимости, список того, что не переносится никогда:
  источники, эпизоды, утверждения, люди, отношения, темы/обещания, состояние персонажа) и решения оператора с digest
  предпросмотра. Профиль идёт через обычный create/apply владельца persona.

Не здесь: панель лаборатории, реальные платные вызовы (отдельная явная операция), оценка 20 сценариев × 3 повтора
оператором (нужна реальная модель), хранение отчёта как артефакта.
