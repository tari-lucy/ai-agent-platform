# Локальный host: подготовка и запуск

Одна рабочая область, один активный персонаж, только loopback. Режим `mock` —
технический. Явный private API pilot подключает только роль character к живому
Chat Completions API; возможности и ограничения описаны ниже.

## Требования

- Python 3.14 и окружение из `uv.lock`: `uv sync --locked` (uv ровно `0.12.23`,
  как требует `pyproject.toml`). Системные Python и чужие окружения не менять.
- Каталог данных — **новый** и **абсолютный**. Относительный путь отклоняется.

## 1. Подготовка (один раз)

```text
python -m ai_agent_core.local_host init --root /abs/path/to/host
```

Параметры: `--profile-file` (Markdown профиля; по умолчанию вымышленный пример),
`--workspace-id`, `--persona-id`, `--port` (по умолчанию 8765), `--test-scopes`
(1..7, по умолчанию 4), `--permission-days` (1..90, по умолчанию 30),
`--migrations` (по умолчанию `migrations/` репозитория, не от cwd).

Для ручных решений по развитию и проверки переноса настроек подготовьте новый
каталог с явным opt-in:

```text
python -m ai_agent_core.local_host init --root /abs/path/to/host --operator-controls
```

Режим добавляет отдельную `persona-settings-test` с независимым начальным
CharacterState и копией данных принятого профиля, пустыми памятью/отношениями и
своими GM-настройками. Пул `persona-test-N` остаётся пустым для лаборатории;
при этом режиме `--test-scopes` ограничен 1..6 (всего не больше восьми областей).
Не используйте каталог с существующими данными: автоматической миграции прав
и команды включения режима для старого runtime в этой задаче нет.

В панели выберите TEST settings → «Персонаж» для правки канона/стиля с проверкой
и digest, либо «Сюжет и развитие» для интенсивности. Отдельный запуск TEST не
нужен. Пауза GM управляет единственным рабочим run, из TEST она недоступна.
Затем «Лаборатория» → выбрать ключи → предпросмотр → подтверждение переноса.
Рабочий агент при применении переноса должен быть остановлен. Биография,
отношения и накопленные значения CharacterState не переносятся.


`init` применяет существующие миграции, создаёт профиль и состояние через
`PersonaService`, Workspace/GM/Connection/LLMAssignment/Capability/Permission,
права каталога и пул пустых TEST-областей. Ничего не перезаписывает: непустой
каталог отклоняется. Незавершённая подготовка оставляет файл `INIT-UNFINISHED`,
и `serve` её не откроет; для повторной попытки нужен новый каталог.

Создаётся `secrets/operator-password.txt` (пароль входа) и `.hash`. Пароль
не выводится в консоль: файл читает оператор. Каталог — `0700`, файлы — `0600`,
`umask 077` на время команд. `serve` отказывается работать, если секрет доступен
другим пользователям.

## 2. Запуск

```text
python -m ai_agent_core.local_host serve --root /abs/path/to/host --provider mock
```

- Слушает только `127.0.0.1:<port>`; порт можно переопределить `--port`.
- Не мигрирует, не создаёт grants, не запускает агента: после старта и после
  каждого перезапуска состояние `STOPPED`. Запуск агента — явная команда
  `agent.start` из панели/API после входа.
- `--panel-dir /abs/path/apps/panel/dist` (необязательно) раздаёт уже собранную панель
  с того же адреса, что и API. Без параметра режим только API (корень отвечает 404).
  Сборка (`npm run build` в `apps/panel`) вне этой команды.
  - Каталог должен быть абсолютным, содержать `index.html` с корнем `#root` и все
    локальные `src`/`href` из него; иначе отказ с кодом `PANEL_DIR_NOT_ABSOLUTE`,
    `PANEL_DIR_MISSING`, `PANEL_BUILD_INCOMPLETE`. Каталог, содержащий каталог host или
    лежащий внутри него, отклоняется (`PANEL_DIR_OVERLAPS_HOST`).
  - Раздаются только обычные файлы внутри сборки; точечные файлы, символические ссылки
    наружу, `..` и соседние каталоги дают 404. `/api/*` и `/internal/*` панель не
    перехватывает: неизвестный API-путь остаётся JSON-ошибкой. Пути без расширения
    (переходы по страницам) получают `index.html`.
  - Аутентификация, `STOPPED` после перезапуска и loopback не меняются.
- `--provider` обязателен. `live` требует отдельной подготовки `init --live-model`
  и явного `--env-file`. Старый mock host в live не переводится при serve;
  `LIVE_NOT_PREPARED` и неверные credentials/bindings закрывают запуск до открытия БД.
  Обратное переключение live host в mock также закрыто (`PROVIDER_MODE_MISMATCH`).

## Что даёт mock

Ответы диалога и рефлексии детерминированы; роли extractor/consolidator/game-master/
story-screen mock не отвечают (`UNSUPPORTED`). Usage не сообщается и остаётся
unknown; тарифов нет.

## Права (см. `local_host/rights.py`)

Оператор только читает (с api_transfer) у PERSONA, MEMORY, GATEWAY, CHANNEL, JOBS,
LLM, GM; в TEST-области — MEMORY, CATALOGUE, LABORATORY. Запись в WORKSPACE
(Capability/Permission/Connection) в обычном режиме доступна только во время
`init`. Явный `--operator-controls` сохраняет запись trusted WORKSPACE owner для
ConsequencePlan/proof/OwnerOperation/журнала переноса и даёт оператору чтение
этого owner с api_transfer. PERSONA и GM получают чтение MEMORY для проверки
оснований. Оператор не получает прямой записи в storage.

Важно: текущие storage grants имеют гранулярность owner, не kind. Поэтому trusted
WORKSPACE owner в этом режиме технически может записывать и Permission;
отдельный HTTP `permission.edit` остаётся закрытым. Это явный выбор init, а не
скрытая выдача прав в serve. TEST settings получает только PERSONA/GM/WORKSPACE
owner writes для метаданных, без model/jobs/channel capabilities. Простая правка
флага в host.json не создаёт grants и не включает отсутствующие возможности.

После
`permission_expires_at` старт закрыт (`serve` пишет уведомление); продления
командой пока нет.

## Проверка

`tests/local_host` — сквозной smoke и guards (`python -m pytest tests/local_host`).
Native Windows приёмка координатора: init/serve, реальный HTTP mock-диалог,
лаборатория/отчёт, STOP/restart и браузер с собранной панелью проверены. На Windows
init назначает владельца и защищённый DACL через icacls. Serve только проверяет
SID владельца/allow rules у hash, каталога secrets и root через штатный Windows
PowerShell; при лишних правах или недоступности проверки — SECRET_PERMISSIONS.
Serve не исправляет ACL сам. В выводе используется относительное имя файла
пароля без локального имени пользователя. Подробно: [combined review](implementation-reports/Integration-local-host-review.md).

Обычный режим покрывает private mock dialogue/laboratory; `--operator-controls`
добавляет проверенные ручные development plans/receipts и settings transfer.
[Приёмка](implementation-reports/Integration-host-controls.md). Полный запуск с
пользовательским профилем и настоящим API этой проверкой не объявляется готовым.


## Приватный API pilot

Пока поддерживается только роль character через существующий адаптер
`openai-compatible-chat`. Live лаборатория и другие live роли не открыты;
публичных выходов, игры и голосового канала нет. Остальные назначения сохраняют
технический mock, и его ответы не являются рефлексией/развитием живой модели.

1. Локально подготовьте `.env` по `.env.example`: заполните только свои
   `AI_PLATFORM_LLM_ENDPOINT` и `AI_PLATFORM_LLM_API_KEY`. Не передавайте файл
   в чат и не коммитьте его. Endpoint — HTTPS base URL, заканчивающийся `/v1`
   (в том числе `/api/v1`); для origin без пути добавляется `/v1`.
   Полный `/chat/completions`, `/responses` или `/messages` не является base URL.
2. Один раз подготовьте **новый пустой абсолютный** каталог данных с
   `init --root <новый-каталог> --profile-file <абсолютный-Markdown-профиль>
   --live-model <точный-ID-модели>`. По желанию добавьте `--operator-controls`.
   Ни `.env`, ни сеть на этапе init не используются. Старые данные не меняются.
3. Запустите `serve --root <тот-же-каталог> --provider live
   --env-file <абсолютный-путь-к-.env> --panel-dir <абсолютный-built-dist>`.
   Части команд здесь перенесены для чтения; в терминале каждая команда — одна строка.
   `.env` выбирается явно; значения из process env не подменяют его содержимое.
4. Войдите в панель паролем из `<root>/secrets/operator-password.txt` и явно
   нажмите Start. Сам serve не делает API-вызов и оставляет состояние STOPPED.

Стартовые пределы pilot: **10 попыток**, 512 выходных токенов на попытку,
24000 символов всего model context, 60 секунд на запрос. Первые два предела
задаются при init опциями `--live-attempt-limit` (целое число от 1) и
`--live-max-output-tokens` (32..1024). Другие пределы входят в закрытую
nonsecret конфигурацию host. Модель выбирается оператором, не зашита в код.

Перед API сначала проверяются права/версии/источники/epoch, затем в журнале
резервируется попытка. Её число ограничено за всю жизнь подготовленной области,
а не за сообщение или сессию: рестарт лимит не сбрасывает. Консервативно считаются
все уже записанные LLM attempts, включая running, unknown и mock; новые live
попытки после лимита закрыты. Для pilot нет автоматических повторов или fallback.
Изменение модели/роли/подключения сверх подготовленного binding отклоняется.

Это ограничение числа запросов, **не гарантия суммы в валюте**. Точный тариф
пока не введён, стоимость неизвестна; отсутствующий usage также остаётся unknown.
До долгой работы задайте дополнительный лимит ключа в кабинете агрегатора.
Кеш, reasoning и правила тарификации зависят от провайдера. STOP закрывает
допуск и поток, но не обещает возврат средств за уже начатую удалённую генерацию.

Проверки и остающиеся ограничения:
[Integration-live-api](implementation-reports/Integration-live-api.md).


Совместимость wire-формата private pilot: некоторые модели возвращают корректный
JSON в одном Markdown-блоке. Только для private character adapter разрешено снять
одну полную обёртку `json` (или без метки), если внутренний объект уже проходит
существующую закрытую DialogueDecision-схему. Общий parser не меняется. Текст до/
после блока, несколько блоков, неизвестные поля, duplicate keys и незавершённый
объект отклоняются. Чтобы не преобразовывать неполный stream, содержимое этой
ветки буферизуется до успешного окончания upstream (конечный предел 200000
символов); текстовые чанки панели здесь появляются после завершения ответа.
Usage/start metadata продолжают поступать, STOP закрывает и underlying stream.
Это адаптация текстового формата, а не выдача прав или исполнение tool calls.


Для выбранного claude-sonnet-5 реальная короткая проба потребовала более 512
выходных токенов на JSON-ответ (usage включает provider generation). При подготовке
такого pilot укажите `--live-max-output-tokens 1024`; этот предел укладывается в
существующий Permission. Truncated ответ не сохраняется и не дополняется догадкой.


## Повседневный запуск панели на Windows

1. Скопируйте `config/launcher.example.json` в игнорируемый
   `config/local.launcher.json`. Укажите абсолютные пути к своему установленному
   Python из `.venv`, подготовленному host, `.env` и собранной панели. Если
   окружение живёт в checkout, путь `python` указывает туда. Значения ключа и
   endpoint в launcher не добавляются. Для mock: `provider: "mock"`, `env_file: ""`.
2. Откройте `Start-Panel.cmd` двойным щелчком. Сервер откроет браузер после
   успешного старта. Окно оставьте открытым; авторизация и START — в панели.
3. Для закрытия сервера нажмите STOP в панели, затем Ctrl+C в его окне.
   Закрытие вкладки браузера само по себе сервер не завершает.

Launcher ничего не устанавливает, не пересобирает панель и не читает значения
`.env`. Повторный сервер для того же каталога закрыт (`HOST_ALREADY_RUNNING`),
даже на другом порту. Занятый порт — `PORT_UNAVAILABLE`. Обе проверки проходят
до открытия БД и восстановления supervisor: чужой/второй процесс не остановит
действующего владельца. Файл `host.lock` остаётся после завершения; ОС освобождает
блокировку автоматически, вручную удалять файл не нужно.

CLI-эквивалент: добавьте `--open-browser` к `serve` с `--panel-dir`.
Без готовой панели этот флаг отклоняется. При недоступном браузере сервер
продолжает работать, адрес выводится в консоли. Windows launcher проверен без
изменения execution policy (локальная RemoteSigned); корпоративную политику
скрипт не меняет.

## Суточный предел API

Обратно совместимый default остаётся 10 попыток за всё время. После остановки
**сервера**, а не только агента, можно явно изменить предел без изменения модели,
прав, профиля, памяти и журнала usage:

```text
python -m ai_agent_core.local_host configure-api-budget --root <абсолютный-host> --attempt-limit 300 --period utc_day
```

`utc_day` означает календарные сутки UTC, сброс в 00:00 UTC (03:00 Москвы).
`lifetime` сохраняет ограничение за всю историю. Предел — положительное целое число; фиксированной бизнес-границы 100 нет.
Значение хранится в локальном `host.json` (`live.attempt_limit`), не в коде.
Для следующего изменения повтори ту же команду с другим `--attempt-limit`.
Рестарт, новая сессия или смена операции счётчик не обнуляют. Учитываются все
записанные попытки области за выбранный период, включая ошибки/отмену/unknown
и технический mock. Будущие записи при откате часов учитываются консервативно.
Остаток и время обновления доступны в диалоге; при исчерпании отправка закрыта,
сервер независимо проверяет предел перед резервированием новой попытки.
Это предел запросов, не денег; фактические списания агрегатора пока не сверяются.

## Продолжение приватного разговора

Контекст получает до восьми последних доступных реплик из своей области, в том
числе после перезапуска. Ответ персонажа включается лишь после подтверждения
получения точной редакции. Видимая панель отправляет его автоматически, когда
сохранённый окончательный ответ попал в видимую часть ленты; черновой stream,
скрытая вкладка и ответ за пределами экрана не подтверждаются. Ручная кнопка
остаётся для проверки при ошибке связи. Пока получение
не подтверждено, ответ сохранён как draft и не считается произнесённым опытом.

История читается из авторитетного storage с целью `api_transfer`, без кэша текста:
ACL, права передачи, TTL, удаления и версии проверяются повторно. История и recall
проверяют также доставку и основания ответа; производный ответ сохраняет эти
основания. Содержимое — недоверенные данные в `<turn>`, не системные инструкции.
WORK/TEST и личности разделены. Выборка ограничена 200 недавними источниками,
восемью репликами, бюджетом контекста и 64 основаниями истории/recall; при нехватке
бюджета неподходящий фрагмент исключается. Это ограниченная недавняя история,
не обещание отправлять всю биографию или гарантировать качество модели.


## Автономная память и рефлексия приватного host

Требуются live-host, подготовленный с `--operator-controls`, явное разрешение
передавать исходные разговоры и производную память выбранному API, суточный
лимит и отдельный резерв для фоновых вызовов. Для существующего host сервер
должен быть остановлен; команда не читает `.env`, не вызывает сеть и не выдаёт права:

```text
python -m ai_agent_core.local_host enable-memory --root <абсолютный-host>
```

Она переводит только роли extractor/consolidator/reflection/story-screen на
уже выбранную приватную модель и включает `live.memory_processing` в host.json.
Существующие назначения вне известного mock/live binding закрывают операцию.
Незавершённое включение отмечено `MEMORY-ENABLE-PENDING`: serve откажется;
после устранения причины повтори ту же offline-команду. Restart остаётся STOPPED.

По умолчанию `live.memory_daily_calls=8` — это часть общего суточного лимита,
а не дополнительные запросы. При общем пределе 300 до 292 доступны диалогу;
остальные зарезервированы для памяти. Резерв задаётся в nonsecret конфигурации
host и проверяется как целое 3..32, меньше общего лимита. Неудачные, отменённые
и неизвестные попытки учитываются. Автоматических платных retry/fallback нет.

После 00:00 UTC (03:00 Москвы), при ACTIVE/OPEN/autonomous, существующий tick
подбирает подтверждённые эпизоды предыдущих суток. Проверка — не чаще раза
в минуту; работа в диалоге имеет приоритет. STOP, пауза, observation и TEST
не запускают фоновые model jobs. Пропущенная обработка возможна после следующего
явного START; сам restart агента не включает.

Одна порция — до 10 эпизодов, 20 первичных источников и 8000 символов.
Последовательно выполняются извлечение утверждений, сводка и рефлексия.
Изменения характера проходят существующую bounded policy профиля и внутренний
story-screen. Это не модератор для публичного выпуска; публичные каналы закрыты.
Остаток работы при исчерпании резерва переносится на следующие сутки.
Частичный сбой сохраняет уже принятые записи и стадию; порция не повторяет
платные этапы автоматически и требует проверки. Raw-опыт при этом сохраняется
по своему TTL. Metadata-квитанции содержат только непрозрачные ID, хэш и статусы,
не копии разговора или выводов; они не являются источниками опыта.

В приватном ответе дополнительно учитываются до трёх доступных элементов
производной памяти, в общем бюджете контекста: последняя сводка и релевантные
утверждения из ограниченной недавней выборки. Большая сводка передаётся
помеченным фрагментом в бюджете контекста. Это интерпретации с атрибуцией,
а не новые первичные факты или системные инструкции. Права передачи, версии,
TTL, удаление и точная доставка оснований перепроверяются перед использованием
и сохранением результата. Панель показывает стадии, ошибки и расход резерва;
