# Открыть консоль OpenCode с рабочего стола Windows

Ярлык **«Опечатка — OpenCode»** открывает PowerShell и подключает установленный
клиент OpenCode к существующему серверу агента в Docker. Это та же личность,
те же инструменты и серверные сессии, что в Web OpenCode.

Сначала нужны Docker Desktop, запущенный сервер платформы и явный START в панели.
Ярлык не запускает агента, не меняет профиль и не создаёт отдельную локальную среду.
Закрытие терминала отключает только клиент; для остановки агента используется STOP.

Лаунчер читает host_root из локального launcher JSON и порт из host.json.
Пароль берётся из data/harness/password в окружение только дочернего процесса,
не из .env и не в аргументы/историю PowerShell. Подключение только к loopback,
с рабочей директорией сервера `/workspace`; внешние плагины клиента отключены.

```powershell
powershell.exe -NoProfile -NoExit -ExecutionPolicy Bypass -File C:/abs/open-opencode.ps1 -Config C:/abs/local.launcher.json
```

ExecutionPolicy Bypass действует только для этого процесса. Для проверки пути,
настроек и доступности порта без открытия TUI добавьте `-CheckOnly`.
Версия клиента на Windows при подготовке: 1.19.3; команда и флаги проверены
по `opencode attach --help`. Агентские API и платные вызовы проверкой не запускаются.

На Windows проверены синтаксис PowerShell и подключение клиента к поддельному
локальному серверу: `/workspace` уходит как удалённый directory, не превращается
в путь Windows. Короткий тест не обращался к личному агенту. Полное открытие TUI
на живой сессии оставлено пользователю; если порт закрыт, лаунчер объясняет,
что сначала нужен START, и ничего сам не запускает.
