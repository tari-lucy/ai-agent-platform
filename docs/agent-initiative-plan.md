# План: инициатива и воля агента (наблюдатель событий)

Статус: план, ничего не реализовано. Решения оператора отмечены словом «оператор».

## Цель

Агент реагирует на жизнь, а не только на расписание: замечает события, сам решает, что важно,
ставит себе цели. Это относится не только к игре, а ко всем областям (игра, канал, работа,
личное), и должно годиться для будущих агентов оператора.

## Схема

```
источники событий -> наблюдатель (без модели) -> политика -> действие
```

- **Наблюдатель** это обычная программа в хосте платформы, не в контейнере агента. Модель не
  использует. STOP останавливает его вместе со всем, агент не может его выключить.
- **Источники** подключаемые модули с одним интерфейсом («опроси, верни события»): игра
  (`getGameState` из мода), канал (комментарии, уже есть `CommentsWatch`), оператор (сообщения,
  тикеты), время, ресурсы (бюджет, контейнеры, ошибки), её собственные напоминания (`wake_me`).
- **Политика** решает: проигнорировать, ответить по правилу без модели, разбудить агента.

## Срочность (уточнение оператора)

Важность события зависит от того, чем агент занят сейчас.

- **Фокус**: `игра`, `канал`, `работа`, `свободна`. Определяется по фактам (игра подключена и
  агент в мире, идёт тикет), агент может выставить его сам.
- **Базовые уровни**: критично (смерть, HP ниже порога, STOP или бюджет, упавший контейнер);
  высокая (удар, сообщение оператора); обычная (комментарий, упоминание, новый тикет);
  низкая (новости, серфинг, напоминание о дневнике).
- **Поправка по фокусу** (таблица настраивается): в игре всё игровое срочно, комментарии в
  пачку; в канале срочны комментарии; серфинг по интернету низкий, когда есть дела; сообщение
  оператора высокое везде.
- **Что значит уровень**: срочно прерывает и будит сразу; высокая будит на ближайшей паузе;
  обычная копится в пачку до следующего пробуждения; низкая идёт в журнал и будит только когда
  агент свободен.
- **Защиты**: старение (долго лежавшее событие поднимается на уровень), склейка дублей со
  счётчиком, дневные лимиты пробуждений по уровням, общий денежный бюджет, видимая в панели
  очередь с причиной уровня.

## Универсальность (несколько агентов)

- Отдельный наблюдатель на каждого агента: свои источники, таблица, фокус, лимиты, бюджет.
  События помечены id персоны.
- Таблица и набор источников лежат в конфиге агента, не в коде. Ядро (очередь, уровни, склейка,
  лимиты, будильник) не знает про Minecraft.
- Вне этого плана: хост сейчас запускает одну персону (один контейнер, порт OpenCode, бюджет).
  Несколько агентов потребуют отдельной работы над запуском и панелью.

## Этапы

1. **Очередь событий с уровнями и фокусом**, источники «игра», «канал», «оператор».
2. **Цели и воля**: общий `GOALS.md` по областям, в промпте первый шаг при пробуждении «чего я
   хочу сейчас» без запроса разрешений (запреты безопасности остаются), дневник после каждого
   отрезка, режим жизни `quiet` на `normal` на пробу 2-3 дня (оператор должен согласиться).
3. **Правила** (`standing_orders`): агент сам ведёт файл «кто бьёт -> что делаю -> при каком HP»
   для игры и «на какие комментарии отвечать» для канала; исполнитель на стороне платформы
   вызывает в моде `punk` или `runAway` без пробуждения модели. Драка с игроками по умолчанию
   выключена, включает оператор.
4. **Новые источники по очереди**: время, тикеты, ресурсы.
5. **Jev** (TypeSafe AI, облачная модель решений: выбор из вариантов с уверенностью, цена
   $0.042 за миллион входных токенов, выход бесплатный) как необязательный судья в политике:
   «драться или бежать», «отвечать на комментарий», «брать тикет сейчас». Низкая уверенность
   будит агента. Вызывает только платформа через шлюз (ключ и учёт у нас, STOP работает).
   Включается по слову оператора после проверки на записанных событиях. Данные о Jev
   взяты у производителя и в пересказах, независимых тестов нет.

## Нужно от оператора

1. Можно ли драться с игроками (этап 3).
2. Согласие на `normal` на пробу (этап 2).
3. Решение о регистрации и оплате Jev (этап 5).
4. Выкатка на сервер, как всегда, по слову оператора.
