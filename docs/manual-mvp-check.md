# Самостоятельная проверка текущего MVP на Windows

## Запуск уже настроенной панели

1. Открой Docker Desktop и дождись готовности.
2. Дважды нажми `C:\ai-pers2\Start-Panel.cmd`. Уже подготовленный локальный
   launcher находится в `config/local.launcher.json`; пересоздавать его не нужно.
3. Оставь окно сервера открытым. Браузер откроется автоматически; если нет,
   адрес панели написан в этом окне. Войди своим паролем оператора.
4. Нажми «Старт» в панели. После запуска сервера персонаж намеренно остановлен.
   Для фона и памяти нужен автономный режим; включённость конкретных функций
   зависит от настроек этого host.

Start-Panel использует пути из локального launcher. Он не пересобирает панель
и не переносит личные данные на новую версию автоматически. Если там указан
старый checkout, свежие commits main сами этот путь не заменят.

## Что можно проверять

- **Диалог:** голос/характер Опечатки, связность нескольких реплик, учёт того,
  что ты уже рассказала. У реального API действуют настроенные лимиты и стоимость.
- **Память:** сохранённый опыт, сводки, факты и их основания. Не каждый текст
  должен становиться отдельным фактом; отсутствие записи само по себе не ошибка.
- **Люди и развитие:** узнавание текущего оператора, обещания, подтверждённый
  опыт и изменения. Другие игровые/Telegram-личности ещё требуют интеграции.
- **Остановка:** нажми «Стоп», затем Ctrl+C в окне сервера. Одна закрытая
  вкладка браузера сервер не останавливает. После нового Start-Panel снова
  должно быть STOPPED; до явного «Старт» новая работа не начинается.

При ошибке запиши экран, время, действие перед ошибкой и видимый код/статус.
Ключи, содержимое `.env`, operator password и личные диалоги в Git не добавляй.
Если есть HOST_ALREADY_RUNNING, сначала проверь уже открытое окно сервера;
вторую копию на тех же данных запускать и host.lock удалять не нужно.

## Где OpenCode

В текущей поставке OpenCode 1.19.3 — CLI внутри изолированного Docker-образа.
Он проверен в технических сессиях через общий model gateway, owner MCP,
permissions и бюджет платформы. Это ещё не отдельное пользовательское окно
OpenCode и не готовый launcher рабочего контура на личном host Опечатки.

Наличие вкладки «Работа» не доказывает, что выбранный host уже подключён к
OpenCode. Самостоятельный `opencode`/`docker run` с отдельным API-ключом создаст
другой маршрут: он не будет проверкой этой личности, её памяти и наших допусков.
Для интегрированного использования осталось подготовить production launcher,
явно настроить нужные возможности и проверить реальный рабочий разговор.
Этот перенос личного host в текущем этапе не выполнялся.

Технический restore опубликован отдельно:
[R4 staged restore и передача Claude](implementation-reports/R4-staged-restore.md).
Самостоятельное восстановление личных данных не нужно для проверки диалога;
не удаляй RESTORE-PENDING и не запускай вручную БД из резервной копии.
