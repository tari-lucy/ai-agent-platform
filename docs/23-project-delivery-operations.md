# Структура проекта, конфигурация и эксплуатация

Дата: 2026-10-13. Статус: план реализации; каркас каталогов и Compose scaffold созданы M0-02/M0-04. Миграции и CI ещё не созданы. Правила работы нескольких кодинговых
агентов описаны [отдельно](27-coding-agents-workflow.md).

## 1. Планируемая структура

```text
AGENTS.md / CLAUDE.md          инструкции разработчикам, без секретов
docs/                         архитектура, задачи, отчёты реализации
apps/core/                    API, композиция владельцев, supervisor
apps/worker/                  dispatch ограниченных фоновых вычислений
apps/panel/                   React SPA
packages/contracts/           версии конвертов, схемы команд/результатов
packages/domain/              модели и правила без HTTP/Redis/LLM SDK
packages/application/         владельцы, use cases, порты, политики
packages/adapters/            SQLite, Redis, LLM, recall, mock
extensions/                   позднее: мосты и подключаемые инструменты
profiles/examples/            только вымышленные публичные примеры
config/defaults/              несекретные defaults и их схемы
migrations/                   единственная линейная история схемы БД
tests/                        unit, contracts, scenarios, failures, UI
deploy/                       Docker/Compose, runtime manifests
scripts/                      ограниченные developer/backup tools
data/ runtime/ logs/           локальные данные, исключены из Git
backups/ artifacts/            локальные копии/экспорты, исключены из Git
.env                          локальные ключи/endpoint/служебные секреты
```

Python-часть начинается одним uv-проектом с явными пакетами/точками входа;
сложный монорепозиторий независимых distributions не нужен. Панель имеет
свой lockfile. Физическая раскладка уточняется M0 без изменения границ.

Domain не импортирует адаптеры. Application зависит от domain/contracts и
портов; adapters реализуют порты; apps связывают их конфигурацией.
Игровой код, названия моделей, особенности Telegram, личность и темы сюжета
не попадают в domain как ветвления по конкретной интеграции. API/DB/queue
schemas изменяются через единственного владельца задачи по контрактам.

## 2. Конфигурация и расширения

Порядок: версионированные defaults → выбранный несекретный профиль workspace →
локальные override → секретные ссылки из `.env`. Валидация при старте,
safe summary ошибок, без печати значений секретов. Панель меняет разрешённые
несекретные настройки через владельца/версию; не редактирует `.env` и не
возвращает его содержимое. Env передаётся только нужному сервису, не целиком
в каждую модель/контейнер. Browser bundle не содержит серверных env.

Группы настроек: storage/retention, broker/jobs, service resources, ports,
LLM bindings/roles/capabilities, rates/budgets, permissions, persona/development,
recall, logging, backup; позже voice/game/avatar/channels/media.
Проверенные runtime-значения и фактическая версия сохраняются в безопасном
manifest запуска. Изменения, требующие restart, помечены; канон применяется
отдельной версией, не подменяется при очередном чтении файла.

Manifest расширения: `extension_id`, версия API/возможности, input/output
schema, тип побочного эффекта, запрошенные подключения/области/ресурсы,
timeout/cancel/idempotency, health, требуемые секретные ссылки и ограничения.
Установка и выдача прав принадлежат оператору; агент не устанавливает код.
Registry проверяет совместимость и выдаёт ограниченный binding.

Первый MVP поддерживает поставленные вместе с проектом доверенные адаптеры.
Импорт стороннего Python-пакета не является sandbox. Недоверенный инструмент
потребует отдельного процесса/контейнера с ограничениями ОС, сетью, доступом
к файлам и собственным протоколом. Слова в manifest сами по себе это не обеспечивают.

## 3. Локальный доступ и STOP

Core слушает контейнерную сеть; на Windows публикуется только loopback и
конфигурируемый порт. Redis, служебные endpoints и DB наружу не публикуются.
Панель обслуживается core. Вход — один локальный оператор: пароль с
настроенным hash в `.env`, ограничение попыток, opaque session в памяти.
Cookie: HttpOnly, SameSite=Strict; Secure при HTTPS. Для начального HTTP
loopback Secure не обещается; удалённый доступ этим режимом не поддерживается.

Host/Origin проверяются по настроенному loopback origin, CORS не открыт всем.
Пишущие команды дополнительно имеют CSRF token; WebSocket проверяет Origin,
сессию и область. Сессии теряются при restart и требуют нового входа.
Служебные credentials worker/мостов отделены от операторской сессии, имеют
минимальные полномочия и не попадают в URL/события панели.

Прямой STOP использует supervisor и актуальную сессию без ожидания LLM,
Redis или транзакции записи. Допуск отзывается в памяти, epoch меняется;
сохранение результата остановки может догонять после восстановления БД.
После любого restart запуск остановлен независимо от последнего snapshot.
Worker проверяет владельца до коммита/воздействия; при потере связи действует
fail closed. Отдельный watchdog и краткая аренда нужны позже физическим мостам.
Если ядро целиком зависло, панель не считается исправным аварийным каналом:
локальная остановка процесса/моста и watchdog остаются отдельными средствами.

## 4. Начальные лимиты

Это конфигурируемые defaults для M0/MVP, не измеренные достижения.

| Область | Default | При превышении |
| --- | --- | --- |
| Активность | 1 экземпляр; 1 смысловой ход персонажа одновременно | Новые обращения объединяются/ждут; тест не запускается рядом с рабочим агентом |
| LLM | До 4 одновременных вызовов workspace; из них до 3 обычных, 1 слот зарезервирован обязательной модерации | Ограниченная очередь, без starvation модератора |
| Фон | 1 GM/reflection задача; 1 embedding slot, threads 2, batch 4 | Приоритет foreground recall; indexing уступает между batch |
| Задания | До 256 pending вычислительных заданий workspace | Backpressure для новых jobs; уже принятое сообщение не теряется молча |
| Retry | Не более 2 реальных API-попыток; тип ошибки/идемпотентность определяет право retry | Ошибка/OUTCOME_UNKNOWN; ручная новая операция вместо вечного повтора |
| LLM deadline | Connect 10 с; первое событие 20 с; idle 20 с; total одной попытки 90 с; total задания 180 с | Отмена/неполнота; значения можно менять по проверенным возможностям модели |
| Контекст | Общий предел 16 000 input tokens, память до 2 000; ответ до 2 048 | Уважать меньший лимит модели; сокращать по приоритету, не удалять обязательную политику |
| Ввод/выдача | HTTP JSON body до 1 МиБ; текст сообщения до 16 000 символов; список default 50, max 200 | Ошибка валидации, cursor pagination |
| Streaming | Bounded buffer 256 событий на клиента; переполненный клиент отключается | Новая проекция/доступный итог, без повторного LLM-вызова |
| Lease worker | Heartbeat 5 с, lease 20 с | Запрет нового коммита/воздействия; reclaim только после проверки владельца/эпохи |
| STOP | Цель revocation p95 ≤ 250 мс, p99 ≤ 500 мс; текстовые cancel receipts до 2 с | STOPPING с неподтверждёнными ресурсами; отсутствие квитанции не выдаётся за успех |
| Ресурсы | core 768 МиБ, worker 1,5 ГиБ, Redis 256 МиБ; общая цель с WSL до 4 ГиБ | Отказ фонового job/уменьшение batch, visible degraded mode |

Общий лимит model context учитывает системные инструкции, схемы и данные;
часть бюджета оставляется выходу в пределах полной context window провайдера.
Если роль не помещается с обязательными ограничениями, модель не допускается.
Deadline — elapsed monotonic time, календарные сроки — UTC. После сна Windows
просроченные аренды/одобрения пересматриваются; автоматического resume нет.

SQLite: WAL, `synchronous=FULL`, явный transaction control, короткая запись и
ограниченный busy timeout (начально 5 с). Redis: AOF, `appendfsync everysec`,
`maxmemory=128MiB`, `noeviction`. DB/outbox восстанавливает потерянную broker
доставку. Внешний эффект и ACK не становятся «exactly once»; неизвестный
результат сверяется, необратимое действие не повторяется автоматически.

## 5. Сроки и квоты

| Данные | Начальная политика |
| --- | --- |
| Полные разговоры | 30 дней; затем только принятые значимые выдержки/сводки по правилам источников |
| Биография, отношения, незавершённые обещания | Длительно, пока разрешены; запрос удаления действует независимо от срока |
| Логи | 14 дней и 256 МиБ workspace; allowlist полей, без полного prompt/секретов |
| Job/технические попытки | 30 дней после терминального состояния, кроме необходимых незакрытых квитанций/ссылок |
| LLM metadata | 90 дней; агрегаты 12 месяцев, без raw prompt/ответов и ненужных персональных связей |
| Тестовые источники | 30 дней после последнего использования; настройки/обезличенный отчёт отдельно |
| STT raw audio | Только временная обработка; opt-in запись имеет самостоятельную политику |
| Медиа поздних этапов | Начальная квота 20 ГиБ, срок незащищённого материала 30 дней; protected/избранное/источники монтажа сохраняются до явного решения |
| Копии | 7 ежедневных + перед миграцией; отдельная проверка квоты и соблюдения удалений |

Для больших медиа/копий предупреждение на 80% и 90% квоты; на заполнении
останавливается новое создание, защищённые источники не стираются молча.
Сроки metadata/тестов и квоты — выбор планирования, их можно изменить настройкой.
История audit не хранит бессрочно все старые тексты под видом версий.

Уведомления расхода — 50/80/100% от введённого бюджета; исходный ориентир
текста $20/месяц. Без ставок денежный итог неизвестен, strict monetary cap
выключен. Включение требует полного тарифа/валюты и резервирования до вызова;
неизвестный usage не освобождает резерв как бесплатный. Это не гарантированный
предел внешнего счёта агрегатора. Цены пользователь вводит сам.

## 6. Runbook

**Запуск.** Проверить конфигурацию, volumes и свободный ресурс → migration
только одним процессом → health/reconciliation → вход → явный запуск агента.
Здоровый broker не означает исправную модель, индекс или Windows-мост.

**Ошибка.** Смотреть безопасный error/trace ID и состояние операции. При
неизвестном результате сначала сверить квитанцию, затем решать повтор.
Закрыть публичный выход при отказе модератора, снизить фон при ресурсе;
не сбрасывать память или очередь «для лечения» без плана последствий.

**Backup.** Остановить новые изменения либо получить согласованный snapshot
через DB backup API; не копировать только main DB при активном WAL. В копию
входят DB, допустимые archive/profile snapshots, manifest/checksums и необходимые
медиа по выбранной политике. Индекс можно пересоздать. `.env` не включается
в обычный экспорт/публичную копию; секреты резервируются оператором отдельно.
Локальные файлы защищаются ACL; шифрование диска/копий настраивается отдельно,
не объявляется существующим свойством приложения.

**Restore.** Сначала preview в staging volume → проверка checksums/schema →
применение актуального независимого deletion/expiry ledger → очистка
истёкших/отозванных источников → rebuild индекса → проверка сценариев →
переключение при остановленном агенте. Если более новый deletion ledger
недоступен, такая копия не допускается в работу как будто удалений не было.
Копии ledger хранятся отдельно от старых snapshots с ограниченным доступом;
в них минимум IDs/сроков, без удалённого содержимого.

**Удаление.** Preview области/производных → revoke access и tombstone →
очистка содержимого/индекса/кэша/экспорта → обработка backup-политики → отчёт.
Заблокированное содержимое не участвует в recall до физического завершения.
Переиндексация или restore не снимают tombstone. Внешняя платформа может
требовать отдельного удаления и иметь собственный retention.

**Обновление.** Версии/digests закреплены → копия → миграция в тестовой области →
контрактные/отказные сценарии → controlled switch. Downgrade БД не обещается:
при несовместимости откат software + совместимый snapshot с последующими
удалениями. Нет автоматической установки пакетов самим персонажем.

## 7. CI и лицензии

При реализации: формат/статическая проверка Python и TypeScript, импортные
границы, unit/contract/failure сценарии, сборка образа и панели, миграция
пустой/предыдущей схемы, browser smoke. Конкретные lint/type инструменты
закрепляет M0. В обычном CI только синтетические данные и mock, без API-ключей,
публикаций и загрузки личной памяти. Живой smoke — отдельный локальный запуск.

MIT — планируемая лицензия собственного кода; M0 добавит LICENSE и инвентарь
компонентов/model cards/notices. Лицензии Redis, голосов, FFmpeg build и
Live2D-активов не переопределяются лицензией приложения. Нельзя автоматически
обещать право распространять любой найденный голос/модель/модпак.

Критерий эксплуатационной готовности: проверены restart, sleep, broker/DB failure,
STOP, restore и удаление; оператор понимает последнюю цель/причину/статус и
может вернуть остановленную систему без потери подтверждённых записей.
