# Обновить и перезапустить на Windows

На подготовленном компьютере откройте **Update-and-Start.cmd** в основной
папке проекта двойным щелчком.

1. Включите Docker Desktop и дождитесь готовности.
2. Сохраните текст, который ещё не отправили в OpenCode: страница переподключится.
3. Откройте CMD и дождитесь сообщения «Сервер запущен».
4. Окно оставьте открытым. Нажмите **START** в панели, когда захотите запустить
   персонажа. Обновление само его не запускает.

GitHub может попросить вход через Git Credential Manager. Ключ LLM в скрипт
вводить не нужно. `Start-Panel.cmd` запускает установленную версию без обновления.

## Что происходит

Скрипт получает `origin/main` из настроенного remote. При новых commits создаёт
отдельный checkout, сохраняя локальные commits текущего deployment, готовит
Python и панель из локального кэша и проверяет поставку. Затем посылает штатный
STOP, проверяет завершение заданий и освобождение ресурсов, закрывает конкретный
процесс сервера, создаёт и проверяет штатную резервную копию с существующим
ledger. Последним меняет launcher и запускает сервер в STOPPED.

Старые checkout, окружение и launcher сохраняются в `runtime/` и автоматически
не удаляются. Backup имеет обычный состав `local_backup`, это не отдельный снимок
Docker volumes. При неудачном старте возвращается прежний launcher; данные
автоматически не восстанавливаются. Старый запуск доступен через `Start-Panel.cmd`.

Обновляется опубликованный `main`, а не незавершённые ветки агентов. Изменения
Docker-образов, native UI и миграций требуют отдельной поставки: скрипт остановится
с `UPDATE_MANUAL_RELEASE`, не меняя личный запуск. Платных вызовов, выдачи
разрешений и START в updater нет. Сам updater `.env` не открывает; при обычном
запуске live-сервера передаёт ему существующий путь.

## Если обновление остановилось

Передайте разработчику последнюю строку `UPDATE_…`. Не делайте `git reset`,
`git clean` и не удаляйте память для исправления.

| Код | Что делать |
| --- | --- |
| `DIRTY`, `GIT_BUSY`, `CONFLICT` | Разработчику сохранить и свести изменения; старый checkout сохранён |
| `GIT` | Проверить доступ к GitHub и вход в Git Credential Manager |
| `TOOLS`, `VERSIONS`, `DEPENDENCIES` | Нужна подготовка точных версий или кэша зависимостей |
| `PREFLIGHT` | Проверить Docker Desktop и комплект поставки |
| `STOP`, `JOBS`, `LOCK`, `PORT` | Не запускать второй сервер; передать код разработчику |
| `BACKUP` | Проверить резервирование; launcher ещё не переключён |
| `STARTUP` | Прежний launcher возвращён; сохранить сообщение из окна сервера |

Проверка без обновления: `Update-and-Start.cmd -Check`. Проверяет настройки,
чистоту checkout и версии инструментов, не получает commits и не останавливает
сервер. Готовность Docker и поставки проверяется при настоящем обновлении.

## Установка updater

В checkout с launcher используйте CMD и `scripts/update-local.ps1` с
`scripts/update_local.py`. В старый основной checkout можно положить только CMD,
а оба helper-файла — в `runtime/operations/updater/`. CMD найдёт их автоматически.
Настройки читаются из `config/local.launcher.json`; пути на host и native bundle
сохраняются. Сам файл настроек не содержит значения API-ключа.
