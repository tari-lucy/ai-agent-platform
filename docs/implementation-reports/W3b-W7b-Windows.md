## Найденные проблемы и минимальные действия

1. **WinError 206 при запуске warm/resident.** Доверенный Python entry вырос так,
   что строка CreateProcess стала длиннее Windows-лимита. В отдельной ветке
   `5d8e713` entry передаётся без потерь в сжатой форме: строка около 10,4 тыс.
   вместо 34,5 тыс. символов. Флаги изоляции, права, STOP и исполняемый код прежние.
   9 unit passed, strict mypy 318 файлов и Ruff чистые; узкое независимое ревью
   блокеров не нашло. Реальные пробы выше прошли. **Пересборка образа не нужна:**
   entry формирует host. Подробности: [отчёт](Windows-short-entry.md).
2. **Chromium наследует read-only XDG_CONFIG_HOME OpenCode.** Голый Python-тест
   работает, такой же скрипт из OpenCode падает `chrome_crashpad_handler:
   --database is required`, SIGTRAP. Запуск дочернего Python с
   `XDG_CONFIG_HOME=/work/browser-config` исправляет это без изменения защиты.
   Проверенный рецепт добавлен в [инструкцию](../agent-workspace.md).
   Claude: закрепить рецепт в HANDS_TOOLS (`sandbox/entry.py`), включая явный
   параметр `proxy` Playwright. Пересобирать apt/pip-слои не нужно; обновить
   harness поверх готового hands-образа, затем использовать новый immutable ID.
   В этой поставке платформенный текст HANDS_TOOLS не меняется.
3. Старый scripts остаётся в начальном наборе/каталоге после включения home,
   хотя исполнителя нет. Это уже заявленное ограничение W7b, не обход допуска.
   Автоматически права/историю не удаляли. Для понятного UI стоит пометить запись
   как устаревшую/замороженную; решение владельца платформы.

## Живая модель и длинная проба

Две платные пробы, всего **4 HTTP-вызова**, без реальных аккаунтов/игры/публикаций:

- Первая: 3 вызова, модель читала справку и пробовала Chromium. Ошибки запуска
  браузера попали в журнал хода; итоговый ответ не доставлен, job завершился
  CAPABILITY_UNAVAILABLE. Точную причину отсутствия финального результата этот
  общий код не доказывает. STOP принят; CPU-журнал содержит 30,463 с.
- Вторая: 1 вызов, добавлен проверенный рецепт XDG/Playwright. Провайдер вернул
  REJECTED; повторов нет, STOP принят. Это не доказательство работоспособности
  живого сценария или качества модели.
- Новая опциональная проба `scripts/probes/workspace_v2_live.py`: только новый
  абсолютный каталог, публичный профиль, ограничение HTTP-вызовов, штатная загрузка
  конфигурации провайдера. Выводит лишь счётчики/коды, не ключи, endpoint или тексты.
  Запуск требует явного `--i-understand-this-makes-paid-api-calls`; из pytest не
  вызывается. Описание задачи включает браузер и when_done; прохождение не заявляется.
- Часовой soak: первая короткая фикстура (CPU rlimit 30 с на процесс) выдержала
  5 ходов за 12,5 мин, затем шестой не дал result, тест закончился через 15,5 мин.
  Ресурсы закрылись. Причина не доказана; для часа такая фикстура не подходит.
  Повтор с нормальным ограниченным профилем CPU 120 с, 1536 МиБ и wall 180 с
  запущен, **на момент этого checkpoint ещё идёт, результат не засчитан**.
  Тест `test_resident_soak.py`, opt-in `AW_RESIDENT_SOAK_SECONDS=3600`.
  Это низкоуровневый настоящий OpenCode/runner с синтетическим провайдером,
  не проверка всего production scheduler. Лог в ignored runtime.

не объявлять. Суточный CPU и quiet-hours подтверждены синтетически; ожидание
настоящей полуночи и живой browser/wake journey не пройдены.
