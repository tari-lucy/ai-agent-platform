# W4: оператор видит папку агента и кладёт файлы в её inbox

Claude Code, 2026-10-26. План: [doc31 §3, §6, §9](../31-agent-workspace-v2.md).
Ветка `claude/w4-home-files` от W3. Инструкция: [agent-workspace.md](../agent-workspace.md).

## Что сделано

- **Доступ к тому** (`sandbox/home_files.py`). Хост не монтирует volume (на Windows он
  внутри VM Docker): каждое действие — `docker run --rm` без сети, read-only, cap-drop,
  uid 65532, 128 МиБ, 16 процессов; том монтируется только для чтения, кроме записи в
  `inbox/`. Путь разбирается посегментно `O_NOFOLLOW` от корня тома: ссылка внутри
  тома не ведёт наружу ни как файл, ни как каталог. Список до 1000 записей, чтение до
  1 МиБ, загрузка до 32 МиБ, `O_EXCL` — без перезаписи. Тома ещё нет — пустой список,
  контейнер не создаёт его.
- **API** (мост OpenCode, после обычной проверки сессии/Origin/CSRF и выбранной личности):
  `GET …/agents/<dir>/home[/<путь>]`, `GET …/home-file/<путь>`,
  `POST …/home-inbox/<имя>` (octet-stream). Без включённого дома — 503. Ошибка пути —
  400, отсутствие/ссылка — 404, существующий файл — 409. `HomeView` сопоставляет
  scope с томом; бинарный файл — карточка (размер), текст — до 200 000 символов.
- **Окно (патч 17).** Раздел `workspace` в дереве файлов: каталоги сначала, ссылки и
  особые файлы скрыты, обрезанный текст помечен полным размером. Вложение с областью
  `workspace` уходит в `inbox/` тома, а в сообщение — «Файл оператора в твоей рабочей
  папке: /workspace/inbox/<имя>».
- **Тексты агенту.** `inbox/` — от оператора, `share/` — для оператора, оператор видит
  всю папку; результат — в `share/` с путём в ответе.
