# OC: адресное обновление, пакетная история и пробуждение

Дата: 2026-10-25. База: `1c476e5`. Ветка: `codex/opencode-efficient-refresh`.
Поручение оператора: уменьшить оставшуюся задержку вокруг OpenCode без сокращения
памяти, ослабления прав/STOP и повторных полных прогонов. Предыдущий этап —
[пустая прогретая песочница](OC-prewarmed-sandbox.md).

## Изменения

- SessionBook.entries читает до 200 ссылочных сообщений одним get_many, сохраняет
  исходные номера, порядок и явные gaps. Скрытая/отсутствующая запись не становится
  концом истории. Чужая область остаётся отказом.
- TicketRelease.source_statuses возвращает свежие флаги для каждого основания,
  включая scope, версию, availability, read/transfer/public флаги и ledger. Общий
  bases_open по-прежнему требует все основания и отдельный file guard; содержимое
  источников этот метод не выдаёт и решений между действиями не кеширует.
- История для экрана и модели загружается через владельца памяти пакетами, с
  api_transfer. Перед использованием текста снова сравнивается точная версия.
  Обработанные закрытые реплики можно опустить; необработанную реплику нельзя
  незаметно пропустить. Финальные current/release guards до модели и результата
  сохранены. Канон, recall, длина памяти и TTL не сокращаются.
- Runtime имеет один coalesced Event для планирования. Успешные сообщения,
  операторские ответы на обращения и решения о доступе будят проверку своей
  partition; чужая partition и собственные уведомления агента не будят её.
  Завершение job также даёт hint. Секундная периодическая проверка остаётся
  fallback. Hint не выдаёт START, Permission, бюджет или модельный вызов.
- STOPPED больше не выставляет 30-секундный throttle деятельности. Переход в
  ACTIVE/OPEN сбрасывает ожидание и будит runtime; одинаковый checkpoint этого
  не делает. Прежнее обновление active-clock сохранено с `(run, elapsed)`.
  Observer не вызывает Supervisor.snapshot/poll рекурсивно. Независимый
  supervisor watchdog/epoch/STOP не заменён новым Event.

## Native UI, патч 13

Серия 1–13 к точному OpenCode v1.19.3 воспроизводит проверенное дерево
`9ac917f`; проверка выполнена отдельным Git-индексом без изменения старого checkout.

На directory выполняется не больше одного refresh одновременно. Всплеск событий
объединяется; пришедший во время чтения хвост обрабатывается следующим проходом,
включая случай ошибки предыдущего прохода. Адресное событие другого разговора
обновляет только каталог/метаданные. Source/STOP и другие общие invalidation
перечитывают видимый разговор. Native session-info берётся из каталога, без
загрузки всей истории. Нового командного replay или ACK по факту чтения нет.

Видимая сессия задаётся lifecycle экрана, не последним GET: prefetch не меняет
адресата, возврат A→B→cached A корректен. При входе в cached route сначала
завершается прежний inflight/prefetch, затем делается новый force read владельца.
Пока чтение pending/failed, прежнее private body скрыто целиком. Это сохраняет
проверку отзыва/TTL и не возрождает старую историю из native-кэша. В browser
storage по-прежнему ничего не пишется.

## Проверки

Все разговоры вымышленные, провайдер синтетический. Личные тексты/ключи не
использовались в диагностике. Живых платных API-вызовов нет.

- Серверный affected-набор: SessionBook, batch-query bound, context assembly,
  wake, ticket release, HTTP conversation и context revocation: **21 passed**,
  129,94 с. Проверены поздний STOP, TTL, отзыв во время модельного ответа,
  сохранение gaps/порядка, чужой scope и свежие per-source решения.
- Дополнительный узкий wake/initial-access набор после разделения операторских
  hints: **5 passed**, 43,40 с. Финальная observer-регрессия дополнена проверкой
  двухаргументного clock callback и отсутствия реентрантного snapshot. Итоговый
  wake + сквозной owner/ACK набор после этой поправки: **4 passed**, 32,53 с.
  Ruff изменённых файлов и strict mypy **297 source files** чистые.
- Native Bun: **81 passed**, typecheck чистый. Регрессии: одна очередь refresh,
  невидимые разговоры не читаются, prefetch и cached return не меняют адресата,
  старый inflight до отзыва не заменяет новое чтение владельца.
- Настоящий Edge, production owners, синтетический harness: **3 passed**, 110,76 с.
  Ответ/видимость/ACK/reload/STOP; обращение→ответ→продолжение; source revoke,
  закрытые native endpoints; A→B→cached A после отзыва при невидимой A.
- Vite build и sealed bundle прошли. Ни новый OpenCode image, ни panel rebuild
  не требуются. Использованы прежние закреплённые Bun/lockfile в новом checkout.
- Узкий независимый review release/wake/native lifecycle по doc27 §8.7 выявил
  active-view/prefetch и observer-стыки до включения. Исправления и их регрессии
  проверены. Полный pytest и unrelated upstream suite не повторялись.

При подготовке автоматическая проверка отклонила переключение ветки в старой
папке upstream как потенциально чужой. Вместо этого создан отдельный checkout;
старые файлы не менялись. Это не блокирует воспроизводимость серии патчей.

## Замеры

Одна контрольная пара на Windows/Docker, тот же production host scenario,
реальный OpenCode, моментальная синтетическая модель. Без частого опроса истории:
тест ждёт завершения owner job и затем один раз читает свежий draft.
Интервалы вложены: их суммы между строками не являются общим временем.

| Интервал | До | После |
| --- | ---: | ---: |
| Отправка сообщения → готовый доступный draft | 10,169 с | 6,411 с |
| Warm runner | 3,931 с | 3,161 с |
| Сборка контекста | 0,343 с | 0,114 с |
| 8 Execution.verify, суммарно | 1,793 с | 1,143 с |
| SELECT за окно | 1110 | 1031 |

В этой паре весь путь быстрее примерно на **37%**. Это единичный замер, не SLA;
provider latency, история, инструменты и текущая нагрузка изменят результат.
Новый frontend в эту числовую оценку не входит: его уменьшение HTTP-нагрузки
подтверждено отдельно Bun/Edge проверками. Ранее 14–16 секунд включали частый
тестовый опрос полной расшифровки (27 чтений за ход); такой опрос сам создавал
нагрузку. Он не используется как baseline для заявления об ускорении.

После этой пары добавлено адресное пробуждение при START и устранён 30-секундный
STOPPED-throttle. Полный тайминг из-за этой небольшой поправки не повторялся;
проверяется отдельной регрессией с production ActivitySettings, без fast().
