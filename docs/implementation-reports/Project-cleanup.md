# Аккуратная уборка локальной папки проекта

Дата: 2026-10-29. Ветка `codex/project-cleanup`, база `origin/main` `140551c`.
Основание — поручение оператора убрать остатки экспериментов, сохранив рабочую
среду и данные. Это файловая уборка, не изменение архитектуры приложения.

## Что сделано

- Metadata-обход без чтения файлов: вне защищённых каталогов найдено 8,35 ГиБ.
  Junction и symlink не обходились; содержимое .env, памяти, профиля и диалогов
  не читалось. Полная опись оставлена локально, не добавлена в публичный Git.
- Удалено **1455 каталогов** восстанавливаемых кэшей и зависимостей, логический
  объём **3 300 396 312 байт**: `.venv`, `node_modules`, Python/mypy/ruff/pytest
  caches старых неактивных собственных checkout. Ошибок файлового удаления — 0.
- Удалён отдельный загрузочный `runtime/tools/bun-cache`, ещё **711 726 955 байт**.
  Исполняемый Bun сохранён. Всего около **3,74 ГиБ логического объёма** плюс
  исходные файлы снятых checkout. Из-за hardlink и фоновой активности это не
  обещание такого же прироста свободного места; наблюдаемый прирост C: около
  **1,5 ГиБ**.
- Через `git worktree remove`, **без force**, сняты 12 собственных закрытых
  рабочих копий. Перед снятием повторно проверены HEAD, чистота, отсутствие
  активной ссылки процесса, интеграция в main и ignored-файлы. Ветки, коммиты,
  Git objects и remote history сохранены.
- Созданы локальные указатели `runtime/README.md` и отдельная папка
  `runtime/operations/cleanup-20261029` с 14 audit-файлами. Скрипты не объявляются
  универсальной утилитой: исторический план нельзя запускать повторно.
- Добавлено `/agent-files/` в `.gitignore` этой ветки и в локальный
  `.git/info/exclude`: личные материалы уже исключены из случайного git add
  даже в старой корневой ветке. Личная папка не перемещалась.

Снятые checkout: `oc-00-native-web`, `oc-01-native-bridge`,
`oc-04-native-delivery`, `oc-04-runtime-readiness`,
`oc-07-candidate-preparation`, `oc-first-session-review`,
`opencode-fallback-note`, `opencode-ui-plan`, `panel-purpose-plan`,
`readme-entry`, `report-lineage-brief`, `work-session-gateway-diagnostics`.
Восстановление: `git worktree add <путь> <сохранённая_ветка>`;
соответствие веткам и HEAD находится в локальном manifest.

## Что сохранено намеренно

- Действующий `deployment/workspace-v2`, его Python/Node зависимости и
  собранные UI, все rollback-поставки и их зависимости.
- `agent-files`, личный host, ledger удалений, backups и служебный updater.
- Checkout с незакоммиченными изменениями (`api-budget`, `r1-agent-session`,
  `python-helper-launcher`), невлитые поставки/приёмки/voice и рабочая копия GLM.
  Не удаляются исходники только потому, что задача выглядит старой.
- `work-session-provider-fix`: при дополнительной проверке найдены 3 ignored
  файла вне разрешённого списка кэшей. Вся копия оставлена.
- Копии с локальными runtime-данными, содержимое которых нельзя объявить
  ненужным по имени папки. Старые диагностические скрипты малы и могут ещё
  использоваться удалённым агентом; их автоматического переноса не было.
- Docker images, containers, volumes, сети и Docker build cache не трогались.
  Уборка папки не является разрешением на общий Docker prune.

## Проверки и границы

- PowerShell 7.6.5: на собственном тестовом junction проверено, что recursive
  удаление убирает ссылку, сохраняя внешний target. Тестовый fixture затем убран.
- Перед удалением каждого дерева проверялись абсолютный путь, разрешённый
  корень, имя generated-каталога, protected paths, reparse ancestors и Git status.
- Все шесть пакетов действующего Python загружаются из workspace-v2,
  а не из снятых старых checkout. В конце HTTP панели отвечает 200.
- STOP, START, перезапуск сервера, платные API и тестовые runtime не запускались
  этой уборкой. Общий gate не нужен: код приложения и контракты не менялись.
- Корневой checkout оставлен на `zcode/onboarding`, его ветка не переключалась.
  Для просмотра актуального рабочего кода используется deployment, а не
  предположение, что корневая копия автоматически равна работающему серверу.

Старый bridge, SessionBook, warm runner и связанные контракты **не удалены
из репозитория**. Doc33 заменяет их на активном пути, но совместимость старых
host, тесты, panel fallback и миграция данных требуют отдельной задачи вывода
из эксплуатации с проверкой зависимостей. Удаление по имени «старая архитектура»
не является безопасной уборкой диска.
