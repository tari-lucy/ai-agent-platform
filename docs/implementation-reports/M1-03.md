## Результат и границы

Создан единственный внутренний supervisor с live state projection, typed
journal/readiness ports, local watchdog и owner-scoped SQLite journal.
Start требует явной recovery, текущей версии и проверенного контекста; сначала
durable workspace reservation, затем admission в памяти. Параллельный второй
профиль/work-test run блокируется существующей уникальностью workspace slot.

STOP синхронно отзывает epoch/admissions и выставляет bounded local cancel
signals. Он не вызывает journal, broker, model и не ждёт обычный IO lock.
STOPPING показывает зарегистрированные ресурсы; acknowledge снимает конкретный
ticket. При отсутствии квитанции за 2 с — FAULTED/OUTCOME_UNKNOWN. Истечение
lease не выдаётся за квитанцию. Поздний result не проходит resolve/finish.

Pause/resume отдельны от STOP, mute и GM pause. PAUSING конечен; автономная
рефлексия и новые воздействия закрыты, разрешённое наблюдение независимо.
Resume повторно проверяет контекст, но не восстанавливает отменённые IDs.
Старый cancellation_id недействителен даже при совпадении run/epoch.
Сон/scheduler stall/proof expiry закрывают допуск; явный запуск обязателен.

Core bootstrap создаёт свежий STOPPED owner, без DB migration/autorun и
без HTTP handlers. Неизвестные старые ресурсы сохраняют занятую FAULTED slot;
readiness.reconcile обязан подтвердить остановку. Default readiness/journal
недоступны, поэтому scaffold нельзя активировать без явной последующей композиции.

## Найденная runtime несовместимость и минимальная правка

No-dev core image не содержал greenlet: он был только транзитивной dev
зависимостью Playwright. Импорт SQLAlchemy asyncio и настоящий SQLite adapter
падал. Координатор до изменения назначил M1-03 владельцем manifest/lock
(aa17459). Добавлен SQLAlchemy[asyncio], использующий уже locked greenlet3.5.6.
Версии всех пакетов и их artifact hashes сохранены; новых пакетов в lock нет.

Из-за неполного metadata cache полный offline resolve не прошёл. Extra links
минимально исправлены по установленной pinned SQLAlchemy metadata;
uv lock --check --offline и locked no-dev export прошли. No-dev graph содержит
greenlet независимо от dev group. Offline wheel и installed-image acceptance
подтверждают runtime работоспособность после этой правки.

## Что не проверено и ограничения

Стандартная cold Docker build без сети не прошла из-за неполного registry
metadata cache (setuptools). Прошла отдельная offline packaging probe с
имеющимися immutable bases, новым project wheel и только pinned greenlet из
существующего public check image. Это не замена production Dockerfile и не
доказательство новой чистой установки. Полная core/worker build по новому lock
остаётся необходимой следующей пробой при доступном публичном build cache.

LLM/Redis hangs — synthetic protocol tests, без живых провайдеров и dispatcher.
Не проверены HTTP auth/CSRF/Origin/service credentials, реальные adapters,
голос/игра/каналы/публичный output, и полный зависший процесс ядра.
Не было платных API, загрузок моделей, личных данных или чтения .env.
Containers/volumes чужих проектов не менялись; собственные probes остановлены,
их synthetic volumes сохранены.

finish — конечный bounded synchronous owner handoff, без await/блокирующего IO.
Он не даёт общей транзакции с SQLite/external API. Права/источники/аренду попытки
и модерацию дополнительно проверяют соответствующие владельцы.
Journal может догонять STOP: завершившийся старый snapshot ACTIVE не
восстанавливает admission. Требуются flush/reconcile; fresh boot никогда
не доверяет snapshot как разрешению. CAS DB revision и live control revision
различаются при coalescing; control API должен читать supervisor projection.

Buffers конечны (resources200/admissions256/requests256); saturation request
cache закрывает обычные команды, STOP доступен. Cache — in-memory, не обещает
долгосрочное HTTP idempotency. Readiness/service methods — доверенная
композиция core, а не sandbox произвольного Python.
