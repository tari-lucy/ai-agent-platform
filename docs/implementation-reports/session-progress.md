# Ход рабочего разговора в панели

Исполнитель: Claude Code. Ветка `claude/session-progress`, base main `278891e`. Окно:
панель разговора и её тесты, новая read-only проекция
`m3_composition/work_session_progress.py`, `WorkSessionTranscript` в `panel.py`, регистрация DTO
в `catalogue.py`, generated, подключение в `work_sessions.transcript()`.

## Результат

- `WorkSessionTranscript.progress` (новые DTO `WorkSessionProgress`, `WorkSessionModelCalls`,
  `WorkSessionResultFile`): состояние текущего хода `waiting_start` → `queued` → `running` →
  `reply_ready` → `done`, конечные `failed` / `cancelled` / `unknown`. Только из существующих
  записей: SessionBook, WorkAttempt, Job (и код ошибки последней попытки job, если владелец его
  записал), журнал LLM (вызовы операции `<job>.<digest>`: число завершённых/идущих/с ошибкой,
  время), файлы из `WorkAttempt.result_files` через каталог (удалённые/заблокированные не
  показываются, изменённые позже помечены). Промпты, аргументы, переписка, секреты не читаются.
  Второй очереди/реестра нет; чтение ничего не отправляет и не подтверждает.
- Панель: блок «Ход выполнения» — состояние словами, прошедшее время между записанной отметкой
  и временем проверки сервера (не таймер), подтверждённые вызовы модели, «Сохранено:» со
  ссылками в библиотеку, следующее действие, код ошибки в «Подробностях», «Обновление страницы
  ничего не отправляет повторно». Без точной причины — «Рабочий ход завершился ошибкой».
  «Чей ход» и пометка сообщения («ответа нет») согласованы с конечным состоянием. Успешный
  вызов модели не считается выполненным поручением: «завершён» — только по итогу хода, файлы —
  только реально сохранённые.
- Обновление: расшифровка перечитывается по `job.changed`, `usage.changed`, `work.changed`; пока
  ход в очереди/выполняется — повторное чтение раз в 3 с (сервер не публикует событие старта
  job; планировщик не менялся).
- STOP во время хода → «Рабочий ход отменён», поздний результат не применяется. Неизвестный
  исход (аренда исполнителя потеряна) → «Исход … не подтверждён»; когда исполнитель всё-таки
  отчитался, владелец job сверяет факт и ход показан отменённым, ответ не появляется.
  Повторного исполнения нет (новой кнопки нет).
