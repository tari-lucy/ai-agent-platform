# M4-04: удаление и экспорт выбранного источника

База 458a365; координатор, codex/panel-memory-lifecycle. Узкий стык реального
backend и существующей панели; весь M4/M5 и операции людей этим не закрываются.

## Реализовано

- Canonical memory.delete/export-args, MemoryPlanProof и MemorySourceExport,
  generated JSON Schema/TS/OpenAPI. Preview для одного явно выбранного Source,
  срок пять минут, оператор/область/версия Source. Для удаления дополнительно
  закреплены состав и digest версий/видимости зависимых записей (до 200).
  Их текст не читается для proof, приватные ID не выдаются в плане.
- Одноразовый план: ID/версия/target проверяются на execute. Durable claim
  proof связывает его с OwnerOperation; другой request_id план не применяет.
  Receipt, lost response и сверка используют существующего владельца операций.
  Proof хранит только ID/digests, срок технической записи равен receipt_retention,
  чтобы очистку можно было сверить после истечения пятиминутного плана.
- Удаление только STOPPED и через RetentionService рабочего host. Не создаются
  второй ledger/owner и дополнительные права. Сначала независимый ledger и
  блокировка, затем штатные индекс/purger/физическое удаление редакций и зависимостей.
  Тот же retention подключён из HostMaintenance; sweep/resume и команды панели
  сериализованы одним runtime lock. STOP остаётся независимым.
- Частичный результат не объявляется завершённым: waiting, completed_steps /
  pending_steps у OwnerOperation. Проверка той же команды продолжает только
  подтверждённую очистку выбранного источника, не всего pending-набора области.
  Неподтверждённый исход до ledger остаётся OUTCOME_UNKNOWN, без слепого повтора.
- Экспорт — JSON выбранного Source (текст/метаданные), без производных записей,
  чужих источников, скрытого архива и файлов медиа. Сервер не создаёт постоянную
  выгрузку. Каждый GET проверяет operator/operation/proof, текущие Source ACL,
  API rights, TTL и точную версию. Ответ bounded, no-store, attachment и checksum.
  Панель проверяет checksum/формат/область до создания временного Blob.
- План/статус вынесены из карточки: удаление записи из списка не сбрасывает
  unknown-команду. Подтверждение удаления обязательно; «Проверить исход» повторяет
  точную команду. Показаны выполненные и ожидающие части; скачивание отдельной кнопкой.
  Состояние остаётся в RAM, приватный текст не пишется в localStorage.

## Ограничения

Экспорт не является backup и не охватывает весь архив/медиа. Скачанная внешняя
копия не отзывается. При partial purge источник закрыт, но физическую очистку
нельзя считать успешной до завершения штатного purger. Старые snapshot-файлы
не удаляются этой кнопкой: их чтение/restore закрывает независимый ledger.
После reload UI не восстанавливает незавершённую команду из локального хранилища;
технический ledger и owner receipts сохраняются, maintenance продолжает очистку.

Рабочий host пока не использовался для удаления/экспорта в smoke. Готовность
удаления требует уже подготовленных operator-controls/recovery; serve не мигрирует
и не провиженит эти возможности. Следующие отдельные стыки: настройки расходов
и workspace, просмотр истории исправлений и итоговая операторская приёмка.
