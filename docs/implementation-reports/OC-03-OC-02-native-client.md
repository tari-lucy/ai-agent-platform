## Что даёт оператору

- Родное окно OpenCode `/opencode/`: каталог личностей платформы (только рабочая память;
  имена, без ключей `aw_…` и git-сведений), их сессии, свободный разговор. Одна «личность»
  вместо Build/Plan и одна «Модель платформы» (gateway) — реальное назначение модели в
  платформе. Все запросы клиента идут через адаптер к bridge `aw-opencode/1`; родные API,
  PTY, auth/provider не отдаются; история и черновики не хранятся в браузере.
- Ход разговора честно: «ждёт, пока эта личность будет запущена», родной busy в очереди/
  выполнении, ответ, ошибка/отмена/неизвестный исход, остановленный разговор. ACK только
  для точного видимого ответа на активной вкладке (Codex).
- Обращения: если личность спросила оператора тикетом, окно показывает «ждёт вашего ответа»
  с адресом точной карточки панели (`#/tickets?ticket=<id>`); ответ даётся в панели, разговор
  продолжается сам. Новое поле `WorkSessionTranscript.open_ticket_ids` (пусто по умолчанию;
  только связанные тикеты сессии в её scope, ждущие оператора по владельцу).
- Две личности (OC-02): вторая добавляется офлайн `add-persona` (Codex). В окне видны обе;
  сообщение неактивной ждёт её активации (проекция «в очереди» только для области активного
  запуска), активная отвечает только со своей памятью, reload сохраняет выбранный разговор,
  чужая сессия не читается через другой directory.
