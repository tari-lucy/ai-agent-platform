## Результат и границы

1. На Windows/Docker проверены настоящий OpenCode 1.19.3 и штатный launcher.
   Модель синтетическая, приложение и owners настоящие; платных вызовов нет.
2. Воспроизведена и исправлена ложная классификация `unknown`, когда фоновая
   проверка допуска длится больше секунды. Это **внесённая задержка async-проверки**,
   не измерение пропускной способности слабого хоста под CPU-нагрузкой.
3. Подготовлены read-only preflight, порядок переключения и отдельный кандидат
   deployment. Личный запуск остаётся на прежней версии до review и native dist.
   Это подготовка OC-07, не закрытый OC-06/07 и не готовый пользовательский Web UI.

## Исправление runner и инвариант для cross-review

Ранее монитор оборачивал `_verify` в `wait_for(..., 1)`. Медленная read-only
проверка отменялась, TimeoutError превращался в `unknown`, контейнер удалялся,
даже если его работа была исправна. Проба с задержкой 1,4 s воспроизвела это
на исходной версии: ожидаемый success, фактически unknown.

Теперь одновременно выполняется максимум одна фоновая проверка. Монитор
независимо проверяет текущий epoch/lease/cancel и STOP каждые 100 ms и сохраняет
прежний общий wall deadline. Завершённая проверка не создаёт busy-loop; новая
проверка запускается с прежней частотой опроса. Незавершённая task отменяется и
дожидается при выходе. Отказ владельца остаётся отменой, превышение общего срока —
timeout. Граница create/model/MCP/file и выпуск результата сохраняют полную
проверку прав/источников. Нет продления Permission, повторного вызова модели,
изменения сети/mounts/лимитов или принятия результата по неполной проверке.

До личного включения нужен узкий просмотр другим исполнителем по doc27 §8:
`sandbox/docker.py::_watch` и место вызова в `_run`. Проверить независимость STOP,
одну pending task, полную проверку перед действием/выдачей и очистку контейнера.
Эта запись — запрос на cross-review, **не утверждение, что оно уже выполнено**.

## Deployment

Preflight действующего launcher: `LAUNCHER_OK`, `PYTHON_OK`, `ENV_FILE_OK`,
`PANEL_OK`, `RUNNER_OK`, **`OPENCODE_UI_NOT_CONFIGURED`**, exit 78.
Проверка `.env` — только наличие файла, не его содержимое/авторизация.
Текущий личный checkout остаётся на `f166eab`; runtime не перезапускался.
Наличие исправного Python подтверждено, проблема старого несуществующего
интерпретатора в этом launcher сейчас не воспроизводится.

Кандидат и неактивный launcher лежат только в ignored локальных каталогах;
личные пути в Git не включаются. Для кандидата ещё нужны собственное locked
окружение, принятые сборки PUI/OC-03 и cross-review новых границ. Старый `.venv`
не переиспользуется как editable-окружение нового checkout. Инструкция:
[порядок подготовки и переключения](../opencode-deployment-runbook.md).

  не переназначались; качество настоящей модели здесь не оценивалось.

- Смена личного deployment/backup/restore не выполнялась; подготовка не требует
  останавливать текущую работу оператора или выдавать новые права.
