# Подсказки панели и наблюдаемость автоматической памяти

Дата: 2026-10-15. Координатор. База main 647890a, отдельная ветка
codex/panel-guidance-memory-status. Пользователь назначил обе части вместе:
понятные подсказки по использованию и состояние обработки памяти/рефлексии.

## Результат

- Общая оболочка: компактное «С чего начать» по подтверждённому состоянию
  агента, раскрываемая памятка по семи разделам и действиям при ошибке/обрыве
  связи/ожидании памяти. START/STOP отнесён к активному агенту, даже при просмотре
  другой личности или тестовой области. Нет автостарта, команд из подсказок,
  модальных туров или сохранения диалога/пароля в браузерном хранилище.
- Вход кратко объясняет следующий шаг. Для неизвестного/устаревшего состояния
  подсказка предлагает обновить данные; для тестовой памяти пояснена изоляция.
- В разделе «Память и люди» добавлена карточка обработки: включено/выключено,
  ожидание запуска/автономного режима/лимита, время проверки и обновления суток,
  резерв фоновых вызовов, последний полученный цикл и предыдущие записи.
- Этапы и статусы разделены; failed/unknown показаны явно, с кодом и допустимыми
  действиями. Обновление только читает данные и не повторяет платную операцию.
- Результаты сопоставлены по record_ids точного MemoryCycle с доступными
  утверждениями, сводками и StateChange. Предложение развития не объявляется
  применённым изменением характера; успешная рефлексия может ничего не менять.
- Ошибка обновления не превращает кэш в подтверждённое актуальное состояние.
  Неполная выборка и несопоставленные результаты помечены. Нулевой счётчик
  найденных записей не объявляется отсутствием результатов во всём хранилище.
- Отступ общей оболочки учитывает реальную высоту фиксированной шапки через
  ResizeObserver: длинные названия/сообщения о связи не перекрывают подсказки.

## Проверки

Typecheck/build и ESLint чистые. Node affected-набор: 21 passed (4 новых проверки
условий обработки, лимитов, порядка по времени и сопоставления результатов;
17 существующих проверок памяти). Полный Node/backend suite не повторялся.

Один сценарий Edge на изолированном ядре с synthetic проекциями: START доступен
при STOPPED; раскрытие подсказок и переход в память; завершённый цикл с утверждением
и сводкой; предыдущий failed; сбой чтения и восстановление; смена WORK/TEST;
узкий экран, отсутствие горизонтального переполнения и перекрытия шапкой.
Проверено отсутствие JS exceptions и любых POST из новых подсказок/карточки.
Первое падение было неоднозначным selector в тесте; исправлен на role=combobox.
После визуальной проверки изменены только отступы шапки и повторён этот сценарий.
Снимки исключительно вымышленные, в игнорируемом runtime, в Git не добавляются.

Приложение использует существующие scope-validated API. Backend, contracts,
миграции, provider, лимиты и permissions не менялись. Новых платных API-вызовов
нет. Полный регрессионный/нагрузочный тест и качество живой модели не проверялись.

## Границы

Журнал memory-cycles сейчас доступен через существующую ограниченную выборку.
При complete=false интерфейс прямо сообщает, что самый новый цикл всего
хранилища неизвестен; сортировка полученных циклов по updated_at не выдаётся
за полную хронологию БД. Списки результатов тоже могут быть неполными.
Точный исход extractor (model_returned_nothing/all_rejected и т.п.) пока только
в фиксированной диагностике владельца, не в MemoryCycle. Панель не выдумывает
причину нулевого извлечения. Для полного журнала и точных исторических причин
нужен отдельный shared API/contract change; в эту задачу не добавлен.

Рабочие файлы диалога и shared/api.ts остаются за вторым агентом. Новая карточка
расположена в memory/**; общий onboarding — в оболочке/help/**. Будущий владелец
GM берёт новую базу после интеграции. Схема Jobs/STOP/visibility ACK не изменялась.
