## Результат

- `ai_agent_application/agent_skills` — `SkillLibrary`, владелец `SKILLS`: `save`
  (создание/улучшение; метод — управляемый файл `skills/<slug>/method.md` через
  `ManagedFiles`, затем `SkillVersion` с CAS; изменённый метод снова `experimental`),
  `verify` (только с evidence; storage проверяет, что источник существует и виден
  владельцу навыков), `retire`, `find` (пересечение терминов, без persona-specific веток),
  `read` (через файлового владельца). `uses_capabilities` описателен и прав не создаёт.
  Скрипт-помощник — только файл; исполнения нет до AW-04.
- `ai_agent_application/agent_knowledge` — `KnowledgeBase`: note (`generated`) и
  hypothesis (`assumption`) различаются видом/происхождением; метод — в навыках, опыт —
  у владельцев памяти (здесь не пишется). Поиск — файловый поиск AW-02 (FTS не нужен).
- Композиция хоста (`m3_composition/workplace.py`): `ManagedFiles` + `DirectoryBlobs` +
  `FileReleaseGuard` на deletion ledger хоста (`HostLedger`) + `CatalogueUsage`; попытку
  читает каталог у владельца ACTIVITY. **Hook `authorize`**: область доступна попытке
  только при текущем automatic `Permission` агента (`workplace-agent`) на capability этой
  попытки и только для областей из `conditions.areas`. Права выдаёт оператор
  структурным решением AW-01 по тикету `capability_request`; второго пути выдачи нет.
- Offline `enable-workplace-files --root R [--blob-dir D] [--ceiling-days N]
  [--max-file-bytes …] [--max-scope-bytes …]`: требует `operator_controls` и recovery
  (ledger), создаёт закрытый каталог blobs, manifests и ready bindings
  `workplace.skills` (skills) и `workplace.knowledge` (knowledge, inbox), строки прав
  SKILLS/каталога (`rights.host_grants` сохраняет все offline-флаги и при
  `enable-social`/`enable-tickets`). Потолок решений — только с `--ceiling-days` и
  включёнными тикетами. Permission не создаётся; агент остаётся STOPPED; повтор безопасен.
- Чтение оператора: `GET /api/v1/workplace-library` (`WorkplaceLibrary`) через guard
  файлового владельца: навык с отозванным/истёкшим/скрытым методом не показывается,
  `complete=false` при достижении предела. Generic reader для ManagedFile не открыт.
- Панель: экран «09 Библиотека» — навыки (статус, когда применять, ограничения,
  «описывает использование — это не права»), заметки, гипотезы, прочие файлы,
  неполнота; выключенный хост — понятное сообщение без повторов.

## Дополнение: чтение текста в «Библиотеке» (после R2/R3)

Ветка `codex/library-content-view`. Оператор открывает текст метода навыка или заметки:
`GET /api/v1/workplace-file/{file_id}` (`WorkplaceFileContent`, `panel.py`), кнопка «Открыть»
у элементов экрана «09 Библиотека». Текст выдаётся для `api_transfer` (передача в панель)
через `FileReleaseGuard` до и после чтения байтов, с проверкой точного размера; хранилище
отказывает на повреждённом digest. Закрытое основание файла (отзыв, TTL, блок в ledger) или
не текстовый файл — `withheld` без текста; длинный текст обрезается до 20 000 знаков.

Ограничение: у `ManagedFiles` (AW-02) нет публичного операторского чтения, поэтому
`m3_composition/workplace.file_content` повторяет шаги его внутреннего `_content` через
открытые `guard`/`blobs`/`limits`. Предложено перенести это в `ManagedFiles` отдельным
методом (зона AW-02).

Проверки: хостовый тест (production `build`): текст метода; файл из источника после блока
источника в ledger — `withheld`; неизвестный id — отказ. Браузерный тест: «Открыть» у навыка
показывает метод. Панель: tsc, eslint, 201 node test.

### Права api_transfer для каталога и деятельности (решение оператора 2026-10-21)

Найдено новым хостовым тестом: в production-матрице CATALOGUE и ACTIVITY читали источники
памяти без права подтверждать `api_transfer` (storage требует его в grant, в ACL записи и у
самого источника). Следствия: release guard не выпускал для модели ни одного файла с источником
среди оснований; бриф личности (AW-06) не показывал модели ни одного воспоминания/обязательства.
Исправлено в `local_host/rights.py`: `Grant(CATALOGUE|ACTIVITY, MEMORY, read, api_transfer)`
при соответствующих offline-флагах и `RecordAccess(..., api_transfer=True)` в
`record_readers()` для этих двух. Решает флаг источника; revoke/TTL/ledger и public — без
изменений. `tests/workplace_experience/test_brief_host.py` на прежнем main падает, после
правки проходит. Затронутые наборы (`workplace_*`, rights/recovery/social, access,
contracts) — 264 passed, 4 skipped.
