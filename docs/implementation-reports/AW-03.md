# AW-03 — база знаний и библиотека навыков

Исполнитель: Claude Code. Ветка `codex/aw-03-skills`, checkout `../aw-03`, base `98ea2b8`
(integrated AW-00). Статус: **независимая подготовка**; зависимость AW-02 ещё не
integrated, поэтому реальное подключение к файловому владельцу, HTTP и UI не выполнены.

## Сделано

- `ai_agent_application/agent_skills` — `SkillLibrary`, владелец `SKILLS`:
  `save` (создание/улучшение: файл метода `skills/<slug>/method.md` через порт
  `WorkspaceFiles`, затем `SkillVersion` с CAS; изменённый метод снова `experimental`),
  `verify` (только с evidence, ссылки проверяет storage у владельца источника),
  `retire`, `find` (пересечение терминов title/applicability/limitations, без
  persona-specific веток), `read` (метод через файлового владельца и `WorkAdmission`).
  `uses_capabilities` описателен: сохранение навыка с «network.raw»/«permissions.grant»
  не создаёт Permission. Скрипт-помощник — только файл; исполнения нет до AW-04.
- `ai_agent_application/agent_knowledge` — `KnowledgeBase`: note (`generated`) и
  hypothesis (`assumption`) различаются видом/происхождением; метод — в навыках, опыт —
  у владельцев памяти (здесь не пишется). Объявленные источники только добавляют
  зависимости. `overview` — краткая карта (счётчики, последние заголовки), не вся библиотека.

## Проверки

`tests/workplace_skills` (3): реальный SQLite для `SkillVersion`; порт файлов — test double
по опубликованному контракту (CAS, replay `request_id`, digest), не второй владелец.
Создание/поиск двух разных методов, чтение, отказ verify без/с выдуманным evidence,
улучшение с историей, конфликт версии, retire; текст навыка не даёт прав; отозванный
admission останавливает IO; различие note/hypothesis, отказ записать метод в знания.
`ruff`, `mypy` новых пакетов.
