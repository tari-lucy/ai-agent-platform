## Результат и приёмка

| Критерий M1-05 | Проверка и результат |
| --- | --- |
| Чужое чтение/команды запрещены | HTTP401 без сессии; Host/Origin/CSRF/purpose и чужой workspace/persona/memory-space/work-test scope запрещены; owner не вызывается до проверки области |
| Чужой WebSocket запрещён | Cookie/Host/Origin до accept; scope до данных, filters run/session/resource; logout/TTL закрывают соединение, входящие команды запрещены |

М1-05 соответствует критериям задачи в указанной проверенной композиции.
Доступные owner ports закрыты до их явного подключения; это не запуск полного агента.

## Реализация

- apps/core/access: stdlib scrypt-v1 verifier, opaque process-local sessions,
  cookie HttpOnly/SameSite=Strict/Secure для HTTPS, absoluteTTL1h/idle15min,
  CSRF/loopback Host-Origin, service bearer и trusted WorkerGrant allowlists.
  Нет универсального credential, wildcard grant, открытого CORS или env reflection.
- Пароль проверяется в отдельном thread: N131072/r8/p1, salt16/hash32,
  maxmem192 MiB. Отмена HTTP запроса не запускает вторую параллельную проверку.
  Session fixation исключена новым случайным cookie при каждом login;
  старый cookie после restart не мешает повторному входу.
- Optional ControlAuthority.is_current — RAM callback для отзыва ожидающей команды
  после logout/expiry; проверяется Supervisor после awaits. Logout не останавливает
  уже запущенный агент. Restart/shutdown не возвращают прежнюю сессию/допуск.
- Canonical OperatorLogin/OperatorSession/ServiceClaimReceipt/ServiceLeaseReceipt
  добавлены в общие schema/OpenAPI/TS. Claim содержит точный command+lease;
  duplicate acquiredFalse запрещает повторное выполнение. Lease receipt — technical
  proof владельца, а не network BudgetLease или разрешение на внешний effect.
- POST auth/login, GET auth/session, POST auth/logout; GET read projections;
  POST commands/direct STOP; WS events; service jobs claim/lease/result.
  Read-only SQLiteReader вызывает принятые repository ACL/source rights/TTL
  с purpose=api_transfer. Встроенный текущий RunSession читается из RAM.
- STOP/control публикуют canonical run.changed в bounded Events. Нет prompt/chunk
  payload; reconnect replay пока закрыт и требует reread projections.
- Trusted access_factory строит JobOwner с тем же новым Supervisor/thread.
  Чужой supervisor отвергается. Без factory/ports runtime остаётся STOPPED
  с unavailable readiness/journal, без подключения рабочей БД и worker loop.
- Compose передаёт operator hash только core, отдельный token — core/worker,
  корректный custom host port/origin; сохраняет loopback publishing.
  deploy/core.py ограничивает WS frame4KiB/queue1, backlog128/keepalive5sec.
- Человек может вручную запустить ai_agent_core.access.setup: новый ignored
  .env.access создаётся исключительно, существующий файл не читается/не меняется,
  значения не печатаются; Linux0600, Windows наследует права локального каталога.
  Single quotes сохраняют '$' в scrypt binding.
- Обнаружен обязательный runtime blocker: bare Uvicorn не имел WS backend.
  Добавлен только websockets17.2 (BSD-3-Clause) в pyproject/uv.lock/notices;
  остальные package versions не обновлены, uv lock --check --offline passed.
  Универсальный wheel SHA256 проверен по lock перед отдельной установкой.
  Migrations/head0003, M2 business code и task reports не менялись.

Подробные порты и настройка: [access README](../../apps/core/src/ai_agent_core/access/README.md).
Использованы API [Python hashlib](https://docs.python.org/3.14/library/hashlib.html#hashlib.scrypt)
и правила [Compose interpolation](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/).

## Что не проверено и следующему агенту

4 real Redis cases не запускались без isolated Redis host; Redis source не менялся
и ранее проверялся M1-04. Пятый Windows skip — POSIX FIFO; Linux case прошёл.
Cached image/source mount проверяет Linux source, но не конкретный VPS/его venv,
новый wheel/cold Docker build, реальные TLS/proxy/browser UI или live LLM.

M2-04 может использовать опубликованные M1-03/04/06 и canonical service receipts.
После обновления main обновить своё окружение по uv sync --locked (для общего
recall suite — --extra recall), затем выполнить scripts/check_combined.py своим Python3.14;
при старых editable paths использовать runner и согласованный lock.
Локальные bindings не передаются через Git. WorkerGrant/capabilities, ExecutionPolicy,
BudgetLease и current admission связывает trusted core composition; bearer token
сам по себе ничего не разрешает. Возврат result — technical receipt владельцу.

Dialog/recall/persona business command handlers, полный outbox→WS, streaming owner
и worker provider loop остаются соответствующим задачам M2/M3/M4.
job.progress и WS after_event_id пока fail closed; UI должна перечитать projections.
Никаких обходных Lease schemas/storage/owner или автозапуска при re-login.
