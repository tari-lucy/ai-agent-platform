# OC-02: дополнительная неактивная личность на local host

2026-10-24, Codex. База `origin/main f16bbe4`, отдельный checkout/ветка
`codex/oc-02-add-persona`. Поручение оператора — закрыть backend-стык второй
личности для OC-02 Claude, затем остановиться. Личный host не изменялся.

## Реализовано

`python -m ai_agent_core.local_host add-persona --root <absolute-host>
--persona-id <id> [--profile-file <Markdown>]`.

- Под OS-lock импортирует новый независимый Profile и CharacterState через
  PersonaService; права области — только каноническая `rights.host_grants`.
  При отсутствии файла используется нейтральный reference-профиль. Импорт
  проверяется до записи; UTF-8 ввод ограничен 128 КиБ.
- Конфигурация хранит id, отдельную WORK-область и digest исходного импорта,
  но не текст личности. Активные persona/workspace/модель не меняются.
  Никаких скопированных источников, файлов, тикетов, Connection, LLMAssignment,
  Capability или Permission: новая область содержит только Profile и state.
- Обычный serve добавляет подготовленные области в scopes оператора и каталог
  bridge. Выбор/просмотр B и intake её сообщений не активируют второй runtime.
  Только текущий A может исполняться. Scope budget остаётся **8 суммарно**:
  основная WORK, все TEST/settings и дополнительные WORK. TEST-пул не урезается.
- Повтор с тем же id и исходным текстом не меняет Profile/state/grants.
  Иной импорт под существующим id отклонён. Рабочая область имеет ограниченный
  детерминированный id, не является путём на диске.
- `PERSONA-ADD-PENDING` фиксирует незавершённую offline-операцию. До её завершения
  load/serve отказывают, включая build с ранее прочитанным config. Повтор именно
  исходного запроса воспроизводит owner receipt и завершает публикацию config.
  Другой запрос не поглощает marker. После конфигурационного commit повтор также
  не создаёт новую версию профиля.

## Совместимость

`HostConfig.additional_personas` необязателен и по умолчанию пуст. Пустое значение
не сериализуется: новая версия не добавляет этот ключ при сохранении старого
одно-профильного host. После явного добавления B старая версия host parser не
понимает новую конфигурацию — launcher-only откат на неё недопустим.

Один helper `host_scopes()` используется serve и backup compatibility. Набор
профилей включён в identity backup: копия до добавления B не удаляет B молча,
а полноценная новая копия проходит preview. Миграции, contracts/generated,
Compose и зависимости не менялись. `panel.py`/проекция ожидающих обращений,
принадлежащие Claude, не затронуты.

## Проверки

Windows, Python **3.14.8**, временные вымышленные host, настоящие owners/SQLite
и authenticated HTTP. Платных вызовов, Docker и личных данных нет.

- Новые шесть сценариев: CLI import/replay/conflict/lock, предел областей,
  старый config, interrupted owner commit/retry, production HTTP-каталог и
  изоляция сообщений, backup compatibility до/после B.
- В HTTP: обе личности видны, у B `active_runtime=false`; её источник/сессия
  недоступны через область A; попытка START B даёт 403. START A не исполняет
  очередь B, вызовов модели **0**, processed_sequence B остаётся 0. Restart
  даёт STOPPED, B остаётся в каталоге.
- Первый affected-набор: 6 passed / 3 failed. Все три новых падения были из-за
  лишнего требования отдельного DACL к SQLite-файлу. Существующий init защищает
  SQLite закрытым host-каталогом; сохранены private-root и no-links проверки,
  ACL и политика существующего host не переписывались. Повтор трёх упавших —
  **3 passed**. Добавленный backup-тест первоначально ошибочно читал
  `BackupResult.backup_id`; исправлен на `manifest.backup_id`.
- Последний точечный прогон backup + сериализация — **2 passed, 20,60 с**.
  Все **10 уникальных affected-сценариев** теперь прошли, включая прежние
  bridge/mock-host и GM assignment compatibility; единым полным прогоном после
  исправлений весь набор не повторялся.
- Ruff чистый. Strict mypy пяти изменённых source files чистый; после последней
  правки сериализации повторены только два затронутых модуля — чисто. Первый
  запуск mypy ошибочно разрешал imports из editable environment; явный MYPYPATH
  направлен на проверяемый checkout, без установок/изменения venv.

## Передача Claude / границы

После интеграции backend использовать обычный `add-persona` на новом временном
host **до serve**, затем повторно войти оператором. Не добавлять области через
тестовую подмену rt.scopes/auth.scopes и не копировать записи личности A.
При включённой деятельности B принимает сообщения и ждёт активации; отдельной
команды переключения активной личности в этом пакете нет. Настройки/инструменты
не включаются автоматически по факту добавления профиля.

Дальше Claude проверяет A↔B в native UI на своей серии из семи патчей. Здесь не
закрывается весь OC-02/06: native browser и качество контекста модели остаются
его gate. Независимый cross-review новой offline-записи/границ scope — GLM до
личного включения. Профиль B в личный host, runtime-права и новая сборка туда
не устанавливались. После публикации этого пакета Codex останавливается.
