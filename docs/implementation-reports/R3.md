# R3 / AW-07-R — рабочий разговор с личностью в панели

Исполнитель: Claude Code. Ветка `codex/r3-work-conversation`, checkout `../r2`, base main
`96c1ae2` (R2 integrated, R1 session-контракты `749ac9e`). Окна shared-файлов — по
[отчёту R1](R1-agent-session.md). Статус: **первая поставка — intake и разговор оператора**;
ответы личности в разговоре появятся с session driver R1.

## Результат

- **HTTP/owner модуль** `m3_composition/work_sessions.py` (новый, зона R3):
  `work.session.open` / `work.session.message` / `work.session.close` → `SessionBook` (R1).
  Текст оператора сначала регистрирует владелец памяти (Source `work-session-message`,
  provenance `operator_input`, внешний id от request_id — повтор находит тот же источник),
  затем в сессию добавляется только ссылка; `verify_source` сверяет точную версию, вид и
  текст у владельца. Intake работает в STOPPED и не вызывает модель, runner или START.
  Без включённой деятельности — `CAPABILITY_UNAVAILABLE` (сессии принадлежат ACTIVITY).
  Событие `work-session.changed` после каждой команды.
- **View расшифровки** `GET /api/v1/work-session-transcript/{session_id}`
  (`WorkSessionTranscript`/`WorkSessionEntry`, contracts `panel.py`): последние 200
  сообщений по порядку; текст каждого — через `TicketRelease.bases_open` (R2) и владельца
  памяти для `api_transfer`, иначе `withheld` без текста. Сессия/сообщения хранят только
  ссылки — второго хранилища текста нет. Generic `work-sessions`/`work-session-messages`
  остаются чтениями метаданных.
- **Панель** (экран «10 Работа»): блок «Разговор о работе» — начать разговор, выбрать,
  читать, писать, закрыть; чей ход («Агент ответит после запуска» в STOPPED); скрытые
  сообщения помечены; один request id на черновик (повтор — без дубля), конфликт версии
  сохраняет текст в поле. Панель принимает событие `work-session.changed` (иначе поток
  событий обрывался бы на неизвестном типе) и обновляет чтения разговора. Второго
  клиента, login или STOP нет.
