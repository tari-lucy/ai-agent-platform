# W7b: пробуждение по окончании фоновой работы, суточный CPU, заморозка helper/MCP-навыков

Claude Code, 2026-10-27. План: [doc31 §7, W4/D71](../31-agent-workspace-v2.md). Ветка
`claude/w8-self-work-extras` поверх W3b. Инструкция: [agent-workspace.md](../agent-workspace.md#самостоятельная-работа-w7).

## Что сделано

- **Будильник по окончании фоновой работы.** `wake_me(..., when_done=<имя>)`: агент
  запускает долгую команду так, чтобы в конце она записала
  `/workspace/.platform/done/<имя>` (каталог создаётся каждый ход). Шаг тика раз в минуту
  читает список этого каталога коротким контейнером дома только для чтения (HomeFiles) и
  будит раньше срока, если файл новее будильника; иначе срабатывает по `minutes`. Текст
  будильника говорит, что случилось. Нового протокола между ходами нет: хост не читает
  контейнер между ходами. `WakeTimer.done_marker` в контракте.
- **Суточный бюджет CPU самостоятельной работы.** Доверенный entry в конце хода читает
  `/sys/fs/cgroup/cpu.stat` своего контейнера (долгоживущий — прирост с прошлого хода,
  включая фоновую работу) и кладёт `cpu_usec` в кадр результата; `RunnerOutcome.cpu_seconds`.
  Хост пишет его в `<root>/data/usage/ГГГГ-ММ-ДД.jsonl`. `--cpu-daily-minutes` (240, `0` —
  выкл.): сверх бюджета будильники ждут следующих суток UTC (`CPU_BUDGET`); ходы оператора
  не блокируются.
- **Заморозка при доме (D71/W4).** С `--home` отдельный Python-контейнер (`--helper`) не
  подключается и его возможность `workplace.scripts` не заводится; MCP-операции навыков
  `find_skills/read_skill/save_skill` не предлагаются. Текст среды направляет к bash и
  `/workspace/skills`. Без дома всё как раньше.
- Попутно: `refresh_opencode_harness.py` удаляет служебную метку `harness-base-*` после
  сборки; opt-in Docker-тест loopback-брокера ждал 429 вместо финального 403 (с b3eca99).

## Проверки (Linux)

- Синтетическая модель, production owners: `when_done` — отказ без дома и для неверных имён,
  старый файл не будит, чтение дома не чаще раза в минуту, свежий файл будит раньше срока,
  один раз; сверх CPU-бюджета — `CPU_BUDGET` (`test_wake.py`). Журнал CPU по личности и
  суткам, битые/отрицательные строки (`test_cpu_budget.py`). Профиль W6 с домом — без scripts.
- Настоящий Docker: контейнер возвращает `cpu_seconds` (~1 с на пробу), `test_docker.py`
  15 passed.
- Полный gate (`scripts/check_combined.py`, Linux, W3b+W7b+приёмка Codex): 1594 passed,
  56 skipped, 2 failed — `test_import_has_no_effects` (известное окружение VPS) и
  `test_memory_cycles` (`RESOURCE_BUSY` под нагрузкой; отдельно 3 passed).

Не проверено: Windows (`cpu.stat` в Docker Desktop/WSL2 — ожидается cgroup v2), живая
модель с `when_done`, CPU долгоживущего контейнера на часах работы.

## Ограничения

- Фоновая работа после последнего хода долгоживущего контейнера (до закрытия по простою
  или STOP) в CPU-учёт не попадает.
- Уже заведённая на хосте `workplace.scripts` при включении дома остаётся записью без
  исполнителя (недоступна). Перенос старых MCP-навыков в `skills/` и удаление кода
  helper/MCP-навыков — отдельный шаг по решению оператора.
