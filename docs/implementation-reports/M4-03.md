## Что сделано

**Экран «Персонаж»**
- Принятый профиль (канон, стиль, версия, редакция) как простой текст — HTML не исполняется.
- **Свойства**: определение и автономность, **начальное значение канона и живое значение в отдельных колонках**; «изменилось опытом»
  помечается только когда оба значения есть и различаются; нет живого значения — «нет данных». Предупреждение, если состояние
  привязано к другой версии профиля.
- **Редактор** канона и стиля: ошибки у полей (пусто, больше 16 000 символов, «изменений нет»); **различия по строкам до применения**;
  «Проверить правку» → «Применить версию». Применение открыто только для **точно того** черновика и версии профиля, которые проверены,
  и только если ядро вернуло проверенную редакцию (digest). Конфликт версии показывает «профиль уже изменён» и предлагает загрузить
  актуальную редакцию, ничего не затирая; потеря ответа не повторяется автоматически.
- **Новая личность**: «Копия профиля» (копируется только канон; память, состояние и отношения не копируются) или «С нуля» (канон и стиль);
  свободный идентификатор личности и своя область памяти; новая личность автоматически не запускается.

**Вкладка «Люди»** (в разделе «Память и люди»)
- Список людей; **одинаковый ник у разных людей — предупреждение, а не слияние**: идентифицирует только подтверждённый аккаунт платформы.
- Карточка: подтверждённые аккаунты отдельно от гипотез и отклонённых; история встреч (новые сверху, основания и их доступность);
  основания отношения и аспекты; темы с известным ответом; обещания (неизвестные и открытые выше, просрочка видна; «удаление разговора
  не означает выполнения»).
- **Привязка и отвязка аккаунта**: платформа, аккаунт, обязательное основание и явная отметка «это один и тот же человек»;
  аккаунт, уже подтверждённый у другого человека, **не привязывается** (слияние — отдельная операция). Команды несут версию человека.

## Приёмка

| Критерий M4-03 | Результат |
| --- | --- |
| Form validation / diff / conflict | ошибки у полей, различия до применения, конфликт версии без перезаписи |
| Identities не смешиваются | ник не связывает; привязка чужого аккаунта запрещена; гипотеза не владеет аккаунтом |
| State отдельно от канона | колонки «начальное (канон)» и «живое», отметка дрейфа, предупреждение о версии состояния |

## Решения и допущения

1. Схемы `persona.validate / apply / create / copy`, `person.link / unlink` и цели команд — **предположения** (`PERSONA_SCHEMA`,
   `PEOPLE_SCHEMA`); ждут владельца контрактов. До этого ядро отвечает отказом, панель показывает его честно.
2. Ядро (M2-01) требует `revision_digest` проверенной редакции для применения. Читать отчёт проверки панели нечем, поэтому принято
   предположение: digest приходит в `resource_id` квитанции проверки. Если его нет — применение закрыто.
3. Редактируются канон и стиль. Свойства, начальные значения и пределы развития меняются импортом Markdown-профиля (формат
   `ai-agent-persona-profile/1`), серверных черновиков (`persona.edit`) нет.
4. Список людей, встреч, тем и обещаний — первая страница + «Загрузить ещё» по курсору; поиск по человеку и слияние людей не реализованы.
