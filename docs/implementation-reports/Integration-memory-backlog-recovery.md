# Видимый backlog памяти и безопасное продолжение частичных циклов (этап 5)

Дата: 2026-10-19/20. Исполнитель: Claude Code. Ветка `codex/memory-backlog-recovery` от
`origin/main` `638162c`. В `main` не вливалось, рабочий host не обновлялся, платных вызовов
не было. Панельную зону (автоматика памяти) оператор поручил в рамках этапа.

## Что было (по коду)

- Порции памяти — `MemoryCycle` с журналом этапов (`extract → consolidate → reflect → done`,
  `record_ids`), задача `post_session`, отбор в `DailyMemory.tick` до 10 эпизодов прошлых
  суток UTC.
- **Сбой терял порцию навсегда.** Эпизоды любого цикла не в статусе `queued` считались
  обработанными, а ключ цикла — хеш набора эпизодов — не давал создать новый. Порцию,
  упавшую на сводке после успешного извлечения, нельзя было продолжить.
- Любой сбой записывался одним кодом `CAPABILITY_UNAVAILABLE`. Причины ожидания были
  видны только в журнале процесса.
- Панель показывала состояние готовности и журнал циклов. Для сбоя всегда писала
  «автоматического платного повтора нет».

## Что сделано

**Ядро (`memory_cycles.py`, `service.py`, `schemas.py`, `consolidator.py`):**

- Продолжение допускается **только по сохранённому доказанному исходу** (`obstacle()`):
  - цикл в статусе `failed`, то есть сбой пойман в процессе и записан журналом;
    `unknown` (`OUTCOME_UNKNOWN`) **не продолжается никогда**;
  - за время цикла нет попытки модели в статусе `unknown`/`running` (`ATTEMPT_UNKNOWN`);
  - цикл ещё не продолжался (`ALREADY_RESUMED`), и на этот набор эпизодов меньше
    3 попыток (`RETRY_LIMIT`);
  - источники не изменились (`input_digest`), иначе `STALE_CONTEXT`.
- Продолжение стартует с первого этапа без сохранённого исхода (`resume_stage`) и
  несёт уже сделанные записи (`resume_ids`). **Сохранённые этапы повторно не
  оплачиваются**: в тесте извлечение после сбоя сводки не вызывается.
- Неподтверждённые этапы продолжения получают **новые идентификаторы генерации**
  (`extr-/cons-<trigger>`). Иначе номер попытки совпал бы с прошлой (`{op}.a1`), и
  журнал расходов слил бы новую попытку со старой.
- Требование к резерву считается по оставшимся этапам (3/2/1 плюс 2 проверки сюжета
  при изменяемом профиле).
- `tick` пробует продолжение **до** отбора новой порции. Идентификатор продолжения
  детерминирован (`resume_key`), поэтому после restart или смены суток UTC порция не
  теряется и не удваивается. STOP не меняется: продолжение идёт тем же допуском и
  только в ACTIVE/OPEN/autonomous.
- Нет кнопки «повторить всё», нового планировщика или второго журнала попыток.

**Панель (`ui/memory/automation.ts`, `MemoryAutomation.tsx`):**

- Блок «Необработанный опыт» различает:
  - «Необработанного опыта нет: обрабатывать нечего, это не ошибка»;
  - ждущие эпизоды прошлых суток (за раз до 10) и сегодняшние;
  - порции, ждущие продолжения;
  - циклы с неизвестным исходом.
  Эпизод, который слишком велик для порции или без оснований, ждёт; точная причина
  — в журнале процесса (ограничение ниже).
- Завершённый цикл говорит: изменение применено / предложение отклонено проверками /
  характер оставлен.
- Сбойный цикл говорит:
  - продолжится с этапа X (и при каких условиях);
  - уже продолжен;
  - предел попыток;
  - или «исход неизвестен — не повторяется».
  Вместо «автоматического платного повтора нет» — «Кнопки „повторить“ нет: продолжение
  решает ядро по сохранённому исходу».

## Ограничения и минимальный контракт

- Журнал попыток привязан к операции генерации, а не к циклу. Поэтому «неизвестная
  попытка» ищется консервативно по окну времени цикла: чужая неизвестная попытка в том
  же окне тоже блокирует продолжение. Это перестраховка, а не риск.
- Код сбоя цикла всегда `CAPABILITY_UNAVAILABLE`. Для точной причины в панели
  минимальный shared change — `MemoryCycle.failure: Literal["generation", "admission",
  "budget", "sources", "stopped"] | None`, заполняемый обработчиком `_perform`. Без него
  панель показывает общую подсказку.
- Причины отсрочки эпизода (размер порции, нет оснований) панель не видит: они только в
  журнале процесса. Для показа — `PrivateApiStatus.memory_deferred: dict[str, int]` или
  ресурс-проекция; это изменение контракта, его не делал.
- Подсчёт backlog в панели — по загруженной первой странице эпизодов; неполнота
  явно отмечена «не менее».
