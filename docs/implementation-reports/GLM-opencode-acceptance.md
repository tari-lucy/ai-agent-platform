## GLM-OC-A — разбор границ (кросс-ревью по doc27 §8)

Просмотрен реальный код на SHA `7b31758`; нарушения инвариантов не найдены.
По областям:

- **HTTP/SSE** (`opencode_ui/surface.py`, `opencode_ui/sse.py`, `access/surface.py`,
  `access/events.py`): dispatch вызывается только после общей границы
  Host/Origin/cookie/CSRF (`access/surface.py:335`); directory выводится из
  доверенных scopes сессии, повторная `check_scope` после awaited-чтений;
  команды — allowlist из 5 типов плюс совпадение partition, тело переправляется в
  прежний `/api/v1/commands` без синтеза ID/версий; query — strict-parsing, ≤8 полей,
  для постраничных чтений только limit/cursor. SSE не занимает слот HTTP-команд
  (`AccessMiddleware` до счётчика запросов), лимит подписчиков и очереди общие с WS,
  переполнение буфера закрывает клиента, отправка медленному клиенту обрывается за
  0.25 s, `notifications_only` исключает StreamChunk/StreamTerminal — тексты модели
  в SSE не попадают; logout/expiry проверяются на каждой итерации → событие `closed`.
  Проекция `invalidation` отфильтровывает чужую partition. SSE не делает START/ACK
  и не держит модельный lease.
- **Статика** (`opencode_ui/assets.py`): manifest проверяется на точный набор ключей,
  версию/протокол/base, размер файла и SHA-256 каждого файла; имена — allowlist
  без точек-префиксов и слэшей-обходов; symlink/junction проверяется на каждом
  компоненте пути включая родителей; запрет overlap с host в обе стороны; serve
  отдаёт только запечатанные байты (после load нет IO по URL); query и `%` в пути
  отвергаются; index.html только для пустого пути или виртуального маршрута
  `aw_<64hex>|base64url/session[/id]`, нативные `/opencode/api/*` → 404. БД/секреты
  в поставку попасть не могут (только manifest-перечисленное).
- **Runner/model gateway** (`sandbox/docker.py::_watch`, `_run`, `policy.py` —
  ровно то место, которое OC-04-runtime-readiness передал на узкий просмотр):
  максимум одна фоновая проверка допуска; STOP/epoch/cancel опрашиваются ≤100 ms
  независимо от LLM; общий wall-deadline сохранён; полная `_verify`
  (current+authorize+guard) перед register, после create и перед выдачей результата;
  результат выпускается только после verify + сверки generation; контейнер удаляется
  в finally, при неудачном удалении честный `_residual` блокирует следующий run
  (unknown, не молчание); `create_args`: `--network=none`, `--read-only`, non-root,
  cap-drop ALL, no-new-privileges, tmpfs `/work` noexec с пределом, pids/cpu/memory/
  ulimits, `--pull=never`, образ по sha256; ENV образа — allowlist. Модельные вызовы
  песочницы идут stdio-RPC через общий gateway с `_verify`+`guard(api_transfer)`
  до и после каждого вызова; прямого доступа к провайдеру/host FS/терминалу нет;
  повторного платного вызова при unknown нет (кэш только succeeded, retry принадлежит
  владельцу). Незначительные наблюдения (не нарушения): не-ContractError из фоновой
  проверки уходит в unknown (консервативно); ContractError на граничных verify
  внутри `_run` доходит до владельца ошибкой, а не `RunnerOutcome("cancelled")` —
  владелец отображает это сам.
- **Native adapter** (серия патчей 0001–0004, итоговый `bridge.ts`): сквозного
  прохода нет — неизвестный маршрут получает 501 `AW_NOT_AVAILABLE`, запросы не к
  виртуальному серверу или в `/api/v1/*` — 403; реальные сетевые вызовы только к
  платформенным endpoint'ам. Хранение — в памяти страницы (PageStorage/драйверы
  черновиков); ACK перепроверяет свежий draft владельца (utterance_id, revision,
  version, полный текст), видимость вкладки и ≥60% компонента, одна автопопытка на
  редакцию, детерминированный `request_id` для идемпотентного replay; скрытая
  вкладка/чужой текст не подтверждаются. Новая сессия в TEST-области отвергается.

**Снятая ложная тревога (зафиксирована, чтобы не повторять):** первичная проверка
компиляции дала «33 файла с SyntaxError `except A, B:`» — артефакт интерпретатора:
скрипт был запущен системным Python 3.13.12, а непарентезированный список исключений
без `as` валиден с Python 3.14 (PEP 758). На закреплённом 3.14.8 компилируются все
573 отслеживаемых `.py`. Дефекта кода нет; синтаксис не переписывался.

## GLM-OC-B — изоляция личностей и lifecycle

Новый набор `tests/opencode_acceptance/test_glm_persona_isolation_and_lifecycle.py`
(production build/SQLite/memory/session owners, синтетический HTTP-провайдер,
вымышленные профили, уникальные маркеры). Итог: **2 passed, 60.0 s**; Ruff чистый.
Запуск — PYTHONPATH по SOURCES+HELPERS из `scripts/check_combined.py`, плюс
`--import-mode=importlib`. Существующие наборы не дублировались: owner-уровень
отзыва/TTL уже покрыт `tests/workplace_sessions/test_context_revocation.py`,
bridge-граница — `tests/opencode_ui/`; здесь проверена именно поверхность bridge
с двумя личностями.

1. **Разные истории/память и переключение просмотра.** A (`АЛЬФА-4К91` в каноне,
   `ЗНАК-А-5В` в истории) и B (`glm-beta`, `БЕТА-8М77`/`ЗНАК-Б-3Н`) имеют раздельные
   сессии; транскрипты не перекрываются. Многократное чтение сессии B и повторный
   вход оператора не меняют активного исполнителя (partition A, STOPPED) и не дают
   ни одного модельного вызова. Каталог выдаёт ровно одного active_runtime.
2. **Изоляция модельного запроса — по телу, не по заявлению модели.** Ход A:
   `model.last("activity")` — в user-сообщении (сериализованный контекст) есть
   `АЛЬФА-4К91` и `ЗНАК-А-5В`, нет `БЕТА-8М77` и `ЗНАК-Б-3Н`. Подмены отклонены:
   команда со scope B в directory A → 403; чужой session-id в чужой partition → 403
   (существование не раскрывается); listing A не содержит сессию B. ACK точный,
   replay того же request_id возвращает ту же квитанцию без второй обработки.
3. **Reload/reconnect и отзыв во время ожидания.** Задержанный модельный ход:
   повторные чтения транскрипта и свежий login не дают START, дубля команды/ACK и
   второго вызова. Отзыв api_transfer основания сообщения во время вызова закрывает
   поздний результат: сессия `invalidated`/`message_unavailable`, draft не записан,
   после оседания — ровно 1 вызов, повторов нет.
4. **STOP и restart.** Прямой STOP после завершённого черновика и после отзыва —
   200/STOPPED. Полный перезапуск host: STOPPED сохраняется, транскрипт читается,
   replay того же request_id возвращает прежнюю квитанцию (нового задания нет),
   модель по-прежнему 1 вызов; новая сессия после restart — единственный путь
   продолжения, работает (2-й вызов).

Уточнённые поведения платформы (fixture-знания для следующих проверок):
CharacterState пинует `profile_version` — рассинхрон с Profile даёт
CAPABILITY_UNAVAILABLE (рабочий инвариант, fixture обновляет обе записи);
чужой session-id → 403, а не 404.

Не покрыто здесь (честные пропуски): исход OUTCOME_UNKNOWN рабочего хода синтетическим
harness'ом напрямую не порождается — «unknown не становится retry» подтверждено через
отсутствие второго вызова после закрытия основания; настоящий Docker/OpenCode-ход и
браузерный native-journey не повторялись (покрыты Codex; дубль запрещён заданием).
