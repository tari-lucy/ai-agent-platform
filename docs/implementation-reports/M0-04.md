Дата: 2026-10-13. Исполнитель: Codex. Ветка: task/m0-04-compose-foundation.
База: 4e7a6e71c8d9ac10d919acd07d28f5d42fc13efc; M0-02/M0-03 интегрированы.

## Изменённые файлы и границы

- .dockerignore: назначенный координатором allowlist build context; исключены
  env, credentials/keys, data, profiles, runtime, .git, pycache и node_modules.
- deploy/Dockerfile: pinned Node/Python/uv stages, locked dependencies,
  non-root core/worker; Node только build stage, dev tooling отсутствует в runtime.
- deploy/compose.yaml, redis.conf: три сервиса, private volumes/networks,
  healthchecks, limits, loopback binding, Redis AOF и auth.
- deploy/core.py, worker.py, healthcheck.py: core отдаёт статическую панель;
  worker только idle heartbeat; health — process liveness. Ни jobs, ни models,
  ни state owners/agent runtime не запускаются.
- deploy/compose.ps1, init-local-secrets.ps1, README.md: безопасные команды,
  новый локальный Redis binding без чтения/вывода/перезаписи существующего env.
- deploy/licenses/redis: исходные LICENSE.txt/REDISCONTRIBUTIONS.txt и SOURCE.md.
- tests/probes/m0_04: synthetic SQLite/Redis Streams/cache acceptance runner,
  обезличенный results.json; этот implementation report.

Manifests/locks, contracts, migrations, application packages/логика и UI client
не менялись. M0-06 profile/config validation и M1 API/access/STOP ещё не реализованы.

## Ресурсы и сеть

| Сервис | Memory=memory-swap | CPU limit | Idle Docker stats |
| --- | --- | --- | --- |
| core | 768 MiB | 1.0 | 36.71 MiB |
| worker | 1536 MiB | 2.0 | 9.656 MiB |
| Redis | 256 MiB | 0.5 | 4.398 MiB |

Все read-only root, non-root users (core/worker 10001, Redis 999),
cap_drop ALL/no-new-privileges/pids 256, private tmpfs, bounded json-file logs
10 MiB × 3 per service. Memory/CPU/read-only/restart/no OOM проверены actual inspect.
WSL working set snapshot: 1194.09 MiB при idle scaffold; это не peak полноценной
платформы с embedder/нагрузкой/Windows integrations и не доказательство общего budget.

Private platform network internal=true содержит Redis/worker. Core дополнительно
подключён к core-loopback bridge для Windows port forwarding. На исходной
internal-only конфигурации core HTTP внутри отвечал 200, но NetworkSettings.Ports
оставались пустыми и Windows connection failed. Разделение сетей исправило это,
сохранив отсутствие host ports Redis/worker. Core bridge допускает transport egress;
никаких внешних calls/runtime permissions эта foundation не исполняет.

restart:no требует явного up после остановки; startup/restart/recreate запускает
только stopped scaffold. Политика реального agent startup/supervisor/access
принадлежит M0-06/M1; liveness не выдаётся за application readiness.

## Проблемы, ограничения и следующий шаг

- Исправлен YAML flow-list quoting tmpfs options: без quotes comma разбивал mount.
- Redis protected-mode допускает только свой loopback без auth; для cross-container
  связи реализована auth, защищённый mode сохранён. Новый 256-bit binding хранится
  только в ignored .env своего worktree; helper не читает и не перезаписывает existing env.
  Runtime auth config в private tmpfs с umask 077; health использует REDISCLI_AUTH.
- AOF everysec/graceful restart не обещает нулевой потери при power loss. Outbox,
  duplicate/lease/reclaim, Redis loss, backup/restore, STOP и host sleep — M1/M5.
- Модели/LLM/пользовательские DB/реальные профили не подключены. Idle RAM ниже caps,
  но ресурсная приёмка полного worker/recall path и 10k corpus ещё впереди.
- M0-05 использует pinned MiniLM и отдельные synthetic fixtures; Compose stack
  остановлен, тяжёлый слот свободен. M0-06 должен добавить safe config/profile
  validation/env example; не печатать expanded config и secret values.

Блокирующих incompatibilities финального Compose нет. Перед commit проверены
owned diff, whitespace и отсутствие operator paths/secret values; vendor license
attributions сохранены как upstream legal text, не являются личными данными оператора.

Автоматическая approval review отклонила предложение отключить protected-mode
без auth как persistent security weakening, не покрытый M0-04. Отклонённая
команда не исполнена. Реализован и проверен безопасный вариант с auth;
блокировки/ожидаемого разрешения больше нет.
