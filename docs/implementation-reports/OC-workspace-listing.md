# OC: проверка просмотра рабочих областей

Дата: 2026-10-24. База: `400bedc`. Зона: host-side workspace bridge,
инструкция среды и один production-composition тест. Без изменения контрактов,
прав, образа Docker и native UI.

## Жалоба и установленные факты

Персонаж сообщил об `ACCESS_DENIED` при перечислении knowledge, inbox и projects.
Это сообщение модели, а не сохранённая трасса вызовов MCP: точные аргументы того
вызова и место отказа в имеющихся данных не установлены.

Проверены через локальный API только метаданные: действующее automatic-разрешение
рабочей сессии уже включает все три области и skills; библиотека доступна.
У существующего файла разрешена передача модели, его источник доступен,
разрешает передачу и соответствует закреплённой версии. Личные тексты,
идентификаторы и локальные пути в отчёт не включены. Это не доказывает полный
ACL-допуск всех прежних вызовов и не заменяет трассу конкретного отказа.

На отдельном временном production host, с настоящими владельцами, SQLite,
ledger и синтетическим session harness, правильные вызовы перечисляют пустые
области и находят только что сохранённую заметку. Сам общий путь листинга
воспроизводимо работает. Объяснение «нужно выдать новое право» не подтверждено.

## Изменение

- Отсутствующее или неизвестное имя области, путь и перечень имён дают
  `INVALID_ARGUMENTS`; известная область без права по-прежнему `ACCESS_DENIED`.
- Инструкция среды показывает точный вызов с одной логической областью.
  Общий `ACCESS_DENIED` не предлагается трактовать как доказательство
  отсутствия Permission: закрытым может быть файл или его основание.
- Для отказов листинга добавлена диагностика фиксированных причин
  `invalid_area`, `area_permission`, `file_release`. В журнал не пишутся
  аргументы, идентификаторы файлов, названия, содержимое или секреты.
- Проверки источников, lineage, STOP и предел списка не ослаблены.
  Отказ выдачи файла не превращается в успешное чтение или пустой список.

## Проверки и предел результата

До изменения: новый production-composition сценарий правильного листинга —
1 passed. После изменения `test_file_listing.py` и `test_workspace.py` —
6 passed (32 с), включая отказы malformed/ungranted area и прежние guards.
Ruff и strict mypy двух изменённых модулей чистые. Первый запуск mypy без
путей исходников monorepo дал import-not-found; с `MYPYPATH` из SOURCES
штатного combined runner проверка прошла. Полный suite не повторялся.
Платных вызовов и запросов к настоящей модели в проверках нет.

Корневая причина исторического отказа не доказана. Если повторится на правильном
вызове, следующая проба — сопоставить новую причину отказа с конкретным ходом,
проверяя допуск и release; не выдавать дополнительные права наугад.
