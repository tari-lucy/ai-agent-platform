# Рабочее место v2: Windows-приёмка W1–W7

2026-10-27. Проверяемая база — main `6e80a85`; ветка приёмки
`codex/workspace-v2-windows`. Личный host/deployment не обновлялся.
Использовались отдельные синтетические host, scopes и volumes; платных вызовов нет.

  Метки `workspace.protocol=1` и `helper.protocol=1` проверены; размер ~163 МиБ.
  Сеть для сборки harness/установка системных пакетов не требовались.
- Все 18 патчей применены к точному upstream
  `e3c4eb242585dcd77be1a867391b7c25fd47ce52` в отдельном checkout с symlink.
  Typecheck и Vite build прошли. Новый native bundle: 938 файлов, ~32,76 МиБ,
  проверен упаковщиком. Старый личный bundle не заменялся.
- Панель собрана после минимального исправления подписи `wake`, описанного ниже.
  Зависимости переиспользованы только после сравнения lockfile.

| W7 | Production owners с синтетическим harness: STOPPED удерживает просроченный таймер, START выпускает wake в дневник; ответ после ACK ссылается на wake. Тихие часы, полночь и часовой предел проходят |

Время операций HomeFiles на Docker Desktop: **0,58–0,78 с** для list/read/put
в проверенном сценарии; текущий таймаут 9 с не менялся. В Edge вложение было
небольшим текстовым файлом; максимальная загрузка 32 МиБ отдельно не измерялась.

Порог `home-quota-mb` — **предупреждение, не hard limit**. Отдельная реальная
проба записала 65 МиБ при пороге 64 МиБ и получила «Порог превышен» в `/guide`.
Это соответствует инструкции, но отличается от понимания «квота Docker».

## Проверки и найденные стыки

- Home Docker: 1 passed, отрицательная проверка метки — 1 passed.
- Egress + настоящий OpenCode/home/resident: 6 passed (~117 с).
- Desktop host-denial + HomeFiles + wake: 4 passed (~81 с).
- Реальная проверка порога: 1 passed (~6 с).
- Начальный доступ в панели: 1 passed; полный профиль + настоящий home в Edge:
  1 passed (~64 с) с уникальным workspace ID.
- Native reload/START/ответ/ACK/STOP с настоящим Docker: 1 passed (~142 с).
- Native ticket/ответ оператора/продолжение/отзыв на синтетическом harness:
  1 passed (~166 с). Это не проверка оплаченного провайдера.
- Resident policy на production runtime с настоящим Docker: 1 passed (~60 с),
  включая выдачу/отзыв через обычные решения, ноль вызовов модели.

Итого — **18 уникальных целевых проверок**, разными прогонами. Это не единый
повтор полного suite. Ruff по изменённым тестам и ESLint по исправленному
компоненту панели проходят; исходная сборка панели после исправления проходит.

Исправления кандидата, отдельные от backend:

1. На исходном main панель не собирается: TS7053 в `Conversation.tsx`, потому
   что speaker `wake` отсутствует в словаре подписей. Добавлена подпись
   «⏰ Будильник». Это кандидат на передачу владельцу панели; в W3b может быть
   аналогичное исправление, не переносить дублирующий patch вслепую.
2. В skipif native journey строка image ID интерпретировалась pytest как Python.
   Условие приведено к bool; сам journey предназначен для synthetic harness
   и запускается без `AW_OPENCODE_IMAGE_ID`.
3. Windows bootstrap/login/reload не укладывался в некоторые старые 5-секундные
   ожидания. Ожидания теста расширены; runtime deadlines и проверки не менялись.
4. DOM visibility не доказывает 60% пересечения ответа с экраном. После
   искусственной скрытости и маленького viewport тест возвращает вкладку,
   отправляет событие видимости и прокручивает ответ в экран. Проверки «hidden
   не ACK» и «clipped не ACK» сохранены; код ACK/прав/STOP не ослаблялся.

Ошибки первых запусков тестовой обвязки исправлялись точечно: неправильная
base-image переменная у отрицательной пробы, выбор managed inbox вместо home
inbox и проверка внутреннего `content` вместо HTTP DTO `text`. Прошедшие наборы
повторно целиком не запускались. Один volume, оставшийся от ошибочной настройки
отрицательной пробы, идентифицирован по её временному окну и удалён без затрагивания
чужих ресурсов.

## Пока не принято

- Длительный soak 1–2 часа, expiry resident после длительного простоя, утечки
  при часовой нагрузке. Короткая проверка двух ходов этого не доказывает.
- Настоящий таймер на две минуты через MCP/OpenCode/Edge и видимость ⏰ в native
  окне: проверены backend с переводом срока в прошлое и сборка патча 18.
- Качество самостоятельной работы живой модели, её выбор bash/webfetch/wake_me.
- Личное включение, образ «руки», SOCKS5, дневной трафик и новый журнал панели.

После дополнения оператора W3b проверяется **после его интеграции в main**.
Живую модель и длительный soak следует запускать на финальном кандидате с W3b,
чтобы не повторять платную пробу и длительное ожидание на промежуточном образе.
Этот отчёт не закрывает весь Windows release gate и не объявляет рабочее место
v2 включённым на личном host.
