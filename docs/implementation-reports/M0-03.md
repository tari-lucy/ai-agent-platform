## Обнаруженные особенности и исправления пробы

- Native MiniLM vectors не обязаны иметь unit norm: предварительная assert
  такой нормы была неверным предположением пробы. Проверяем finite/nonzero/
  dimension и используем cosine metric; RU поиска это не нарушило.
- Failed load оставляет disposable schema: повторение требует fresh volume,
  а не удаления чужой или исходной DB; runner создаёт уникальный volume.
- Read-only root препятствует стандартным pytest/Ruff caches: в runner
  отключены их caches. Итоговый полный запуск прошёл без cache warnings.
- ONNX Runtime при import сообщает, что не может сохранить telemetry device ID
  в read-only root и использует in-memory ID. Telemetry events отключены;
  inference phases network=none. Это warning, не провал совместимости;
  общий telemetry/logging policy будет проверяться отдельно.

## Непроверенное и рекомендации

- 60 размеченных запросов, 1k/10k chunks, Recall@8≥0.85 и p95≤500ms на 10k —
  M0-05. Результат 3 запросов/16 rows не доказывает эти цели; качество baseline
  и необходимость E5/MemPalace сравнения пока не определены.
- Worker/core/Redis вместе, Docker/WSL peak≤4GiB, service health/ports/Compose
  restart — M0-04. Эта проба не оставляет активный platform runtime.
- Конкурирующие writers, cancellation/STOP, реальные transactions владельцев,
  migrations, crash during rebuild, backup/restore/deletion ledger — M1/M2/M5;
  process exit не эквивалентен потере питания/аварии хоста.
- Native Windows SQLite extension/model runtime, ARM/macOS/GPU не проверялись:
  целевая runtime среда — Linux amd64; Windows был build host.
- Длительные indexing loads, 10k growth и resource arbitration ещё не измерены.

Блокирующих несовместимостей этой комбинации нет. Сохраняем стек doc20;
никакой обходной архитектуры/замены dependencies не требуется. Для M0-04
использовать закреплённые Linux версии, собственные volumes и resource caps;
для M0-05 — те же model revision/hashes, измерять полный recall path на
требуемом корпусе. Application extension initializer нужен на каждой
нужной DB connection; не переносить пути из пользовательского текста.
