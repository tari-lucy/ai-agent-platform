## Переход к использованию MVP

Дополнительные реальные пробы остановлены по решению оператора: качество
проверяется при повседневном использовании, без отдельной платной кампании.
Две попытки первого probe получили TIMEOUT из-за неявного httpx timeout 5 секунд
в проверочном скрипте; приложение использовало 60 секунд. Третья попытка после
исправления получила HTTP 200 и полное usage (5407 входных, 512 выходных токенов),
но операция ответа завершилась FAILED. Исчерпан весь выделенный probe output cap;
точная причина отказа документа отдельно не доказана. Цикл памяти не запускался.
Всего три HTTP-вызова: два с неизвестным usage, один с полным. Успешная проверка
качества live-памяти этим не заявляется. Рабочая биография не передавалась.

Probe исправлен: timeout из HostConfig, остановка после неуспешной реплики,
ненулевой exit code при отказе, вариант потолка 4 вызова. Для последующих явно
заказанных проб выбран output cap 1024 как в рабочем pilot; новое платное
выполнение не делалось. Synthetic harness после timeout/fail-fast изменений:
4 passed; Ruff и mypy чистые. После согласования output cap с рабочим pilot
повторён только synthetic сценарий probe: 1 passed (28.67 с), Ruff/diff check
чистые. Полный suite и новые платные вызовы не запускались.

Рабочий host обновлён принятой реализацией памяти. Его предел ответа уже 1024,
суточный лимит 300, обработка памяти включена. Разработчик веб-диалога может
начинать от origin/main f375e66 или более нового принятого main, в своей зоне.
