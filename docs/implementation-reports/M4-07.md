## Что сделано

- **Запуск**: пять независимых индикаторов (запуск, деятельность, режим, голос, гейммастер) — одно слово не подменяет несколько
  состояний. Голос честно «не подключён». STOPPING показывает неподтверждённые ресурсы и не выдаётся за STOPPED; FAULTED —
  «состояние неизвестно, запуск закрыт до сверки»; STOPPED — «после перезапуска/восстановления требуется явный запуск».
- **Управление** (запуск с выбором режима, пауза, возобновление, завершение сессии): доступность по состоянию, причина закрытия
  называется; команда несёт `expected_version` увиденной версии; потеря ответа → «Проверить исход» повторяет **ту же** команду.
  STOP остаётся отдельной кнопкой и этих операций не ждёт.
- **Операции**: неопределённые (`OUTCOME_UNKNOWN`) сверху с пометкой «требуется сверка», затем открытые по сроку, завершённые
  последними; отмена только для открытых; квитанция — «запрос принят», фактический статус показывает владелец; просрочка видна.
- **Подключения и возможности**: раздельные статусы, причины деградации списком; видны только имена настроек и состояния
  проверки, не значения (тест: имена переменных в страницу не попадают).
- **Права**: уровни, отозвано/просрочено; расширение требует явной отметки, для внешнего/публичного эффекта на «Автоматически»
  — отдельное предупреждение; конфликт версии не затирает чужое изменение.
- **Резервная копия и восстановление** (по плану последствий M5-02): копия — план → одна команда; восстановление закрыто, пока
  агент не `STOPPED`, требует идентификатор копии, набранный повторно, отметку подтверждения и план, который называет именно эту
  копию и не просрочен; смена идентификатора сбрасывает подготовленный план; после выполнения интерфейс напоминает, что агент
  остаётся остановленным и требует явного запуска.

## Приёмка

| Критерий M4-07 | Результат |
| --- | --- |
| Partial failure / STOPPING / OUTCOME_UNKNOWN | неподтверждённые ресурсы, FAULTED, неопределённые операции сверху, выполнено/ожидает по статусу владельца, неизвестный исход не повторяется вслепую |
| Explicit resume | остановленный агент не запускается ни входом, ни восстановлением; запуск — отдельная команда с видимой версией |
| Recovery preview | план последствий с проверкой копии и срока, типизированное подтверждение, блокировка при работающем агенте |
| Права | расширение — только с подтверждением; конфликт версий без перезаписи |

## Решения и допущения

1. Схемы `operation.cancel`, `permission.edit`, `workspace.backup`, `workspace.restore` и цели команд (агент — для
   start/pause/resume, сессия — для `session.end`, `operation.cancel`, `permission.edit`, планов) — **предположения**, в одной
   константе/функциях `workspace/model.ts`; ждут владельца контрактов. До этого ядро отвечает отказом, панель показывает его честно.
2. Список копий читать неоткуда (в `READ_MODELS` нет резервных копий): идентификатор копии вводится вручную. Структурированный
   предпросмотр M5-02 (проблемы, операции под риском, замороженные события) приходит только текстом `consequences` плана.
3. Раздельные статусы БД/Redis/worker в API нет; показаны статусы возможностей и подключений.
4. «Последняя связь/аренда» и «попытки» задания в проекциях отсутствуют — не показаны, не придуманы.

## Не проверено / ограничения

- Реальная интеграция: нет исполнителей команд управления/копий в core, композиции `BackupService` (M5-02), `Supervisor` команд
  start/pause/resume; полный цикл «план → копия → restore → явный запуск» не выполнялся.
- Реальный Node 24, Firefox/WebKit, Windows, настоящий TLS/прокси.
