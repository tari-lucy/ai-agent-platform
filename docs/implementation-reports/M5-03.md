# M5-03 — сквозной синтетический набор и браузерный сценарий

Дата: 2026-10-14. Исполнитель: Claude Code. Ветка: codex/m5-03-synthetic-suite, отдельный worktree.
База: 253b5b3 (main с блоком M4 целиком и M5-01, M5-02). Зависимости M1–M4 и M5-02 интегрированы (M4 — как review/UI-only).
Статус: **готово в ветке для review; полный цикл через настоящий HTTP backend не проверен — бизнес-маршрутов в core нет.**
Всё — синтетические данные, mock-модель и mock-проекции; реальные и платные вызовы, сеть, публикация и `.env` не использовались.

Зона: `tests/e2e/*`, `tests/panel/test_journey.py`, `tests/panel/README.md` (раздел), этот отчёт.
**Малая правка вне зоны** (раскрыта): `scripts/check_combined.py` — каталог `tests/e2e` добавлен в списки вспомогательных путей и
запускаемых наборов, чтобы цикл входил в общий оффлайн-гейт. Продуктовый код не менялся.

## Что сделано

**1. `tests/e2e/test_cycle.py` — один непрерывный цикл в одном мире** (через `LabRunner` M3-04, реальная SQLite/FTS5/sqlite-vec):
1. Диалог: знакомство, вопрос, ответ запоминается; текст, похожий на ключ, остаётся данными (в отчёт и лог не попадает).
2. Перезапуск: пока оператор не возобновит, ничего не запускается (нет вызовов модели).
3. Повторная встреча: тот же человек, известный ответ доходит до модели, вопрос не повторяется.
4. Развитие: один опыт отклонён, два независимых — применяются с основаниями; следующая реплика строится на изменённом состоянии.
5. Удаление: источник стирается через `RetentionService` (M5-01); текст пропадает из контекста модели **и из байтов** файла БД,
   WAL и индекса (перед удалением он там найден — детектор работает).
6. STOP посреди генерации: вывод закрыт, обещание и действия не записаны, после STOP ничего не запускается.

Раннер добавляет жёсткие инварианты: только тест-область, изоляция от рабочей биографии (отпечаток до/после), никаких
неописанных вызовов модели, STOP соблюдён, нет секретов в отчёте. Проверяются: прохождение, **повтор по seed с тем же отпечатком**,
другой seed → другой отпечаток при том же вердикте, сохранённый отчёт, рабочая память не тронута.

**2. Вход, STOP и выход через настоящее ядро (ASGI)**: вход не запускает агента (запуск `STOPPED`), cookie `HttpOnly`/`SameSite=Strict`,
STOP выполняется и повторный STOP ничего не меняет, бизнес-команда закрыта (503) до композиции владельцев, после выхода сессия
недействительна, пароль и ключеподобный текст не встречаются в телах и заголовках ответов, `effects_enabled` остаётся `False`.

**3. `tests/panel/test_journey.py` — тот же путь в браузере**: настоящий вход → диалог (одна команда) → перезагрузка страницы
(сессия восстановлена, **команда не повторяется**) → повторная встреча (карточка человека, история) → решение по изменению → удаление по плану
с подтверждением → **настоящий STOP** (ядро останавливает настоящий запуск; интерфейсу подменено лишь отображаемое состояние) → выход.
Инварианты всего пути: ни одного запроса за пределы origin, ничего в браузерном хранилище, ни пароля, ни имён секретов в DOM,
HTML из данных не исполняется, команды строго в ожидаемом порядке.

## Приёмка

| Критерий M5-03 | Результат |
| --- | --- |
| Вход → диалог → restart → повторная встреча → развитие → удаление → STOP | один сценарий в одном мире (цикл) и один сценарий в браузере (путь оператора) |
| No secrets | ключеподобный текст и пароль не попадают в отчёт, лог, тела/заголовки ответов и DOM |
| No external publication | нет предложенных действий (`proposals` пуст), нет запросов за origin, публичный выход не вызывается |
| CI | `tests/e2e` входит в `scripts/check_combined.py`; браузерный сценарий — в `tests/panel` (как M4-01…M4-08) |

## Проверки

Среда: Linux, CPython 3.14.7, Node 22.22.3, Playwright 1.63.0 и Chromium 1228 из кэша (разрешено оператором).
- `tests/e2e`: **4 passed** (~30 с). Браузерный сценарий: **1 passed** (~7 с); весь `tests/panel` — см. ниже.
- Проверка самого набора намеренными поломками продукта (8): удаление не стирает файл, пропускает `finalize`, не чистит индекс;
  вопрос задаётся повторно; одного опыта достаточно; повторная встреча не узнаёт человека; перезапуск возобновляет сам →
  **7 из 8 пойманы**. Выживший («генерация переживает STOP» в ветке `CONTROL_CLOSED` после завершённой генерации) — узкое окно
  между концом генерации и применением; цикл останавливает раньше, во время генерации, а окно закрыто модульными тестами M2-06.
- Проверка браузерного сценария поломками интерфейса (5): удаление без отметки, доставка никогда не «завершена», применённые
  изменения не попадают на путь, STOP без цели → **4 из 5 пойманы**; пятая («пароль остаётся в форме») в сквозном пути
  эквивалентна (форма размонтируется после входа), её отдельно ловит тест M4-01 про очистку пароля.
- `scripts/check_combined.py` и backend-регресс: см. ниже.

## Не проверено / ограничения

- **Полный HTTP-цикл «сообщение → ответ → доставка»** не проверяется: бизнес-маршрутов и композиции владельцев в core нет
  (`/api/v1/commands` для бизнес-команд отвечает 503). Диалоговая часть идёт внутри процесса через лабораторию, интерфейс —
  на mock-проекциях. Когда композиция появится, цикл надо перевести на настоящие маршруты (запрос ниже).
- Реальная модель, качество личности, Windows, Linux-контейнер, Node 24, Firefox/WebKit, нагрузка.
- Перезапуск процесса core (kill -9) не воспроизводится: «перезапуск» — это пересоздание контроллера лабораторией и перезагрузка страницы.
