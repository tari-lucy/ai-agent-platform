Дата: 2026-10-13. Исполнитель: Claude Code. Ветка: codex/m2-07-moderation-gate, отдельный worktree.
База: e65c131 (main с M1-05 и M2-01..06). Зависимости M2-04, M1-03 интегрированы.
Статус: **готово в ветке для review; реальная модель-модератор, качество классификации и runtime-интеграция
не проверены.** Зона: `application/moderation`, `tests/moderation`, этот отчёт. Contracts
(`Utterance`, `ModerationCheck`), storage, migrations, зависимости, Compose, API/UI, jobs, supervisor не менялись.

## Что сделано

`ModerationGate` (владелец `Owner.MODERATION`): `check` (локальный фильтр → другая модель → закрытый
`Verdict` → `ModerationCheck`), `verify`/`release` (единственный путь к `Publisher`), `Policy`/`Rule`
(версия, digest), `ModerationContext`.

## Приёмка

| Критерий M2-07 | Результат (реальная SQLite, шлюз M2-04 с мок-модератором) |
| --- | --- |
| Недоступность блокирует simulated public output | отказ провайдера (transient/auth/rate-limit), пустой/обрезанный/без завершения поток, неизвестное правило, approve с нарушением, block без правила, плохие фрагменты, отмена, потеря допуска, STOP во время проверки → `unavailable`; `release` не вызывает `Publisher` |
| Отказ блокирует | `block` с rule_ids и фрагментами, жёсткое правило сильнее мягкого `revise`, `review`, лимит редакций до обращения к модели |
| Исправленная редакция проверяется заново | `revise` → редакция 2: старая проверка не покрывает новый текст (`verify` отказывает), вторая проверка реально идёт в модель, выпускается ровно редакция 2 |
| Независимая модель | модель = модель реплики или её резерв → отказ без вызова; провайдер сообщил модель реплики → `unavailable`; персонаж/секреты не попадают в запрос модератора |
| Привязка | текст, аудитория, каналы, редакция, контекст, версия политики, срок, поколение управления (STOP), потеря допуска, profile/policy freshness, чужой scope, поддельный/чужой/неодобренный check — каждый закрывает выпуск с конкретной причиной |
| Секреты | секрет/e-mail/телефон/ключ блокируются локально, модератору не отправляются |

## Решения и допущения

1. `ModerationCheck.expires_at` — TTL записи: storage сам скрывает истёкшую проверку (`CHECK_MISSING`);
   проверка срока в шлюзе — запасная.
2. Каждая проверка — новая запись (id включает момент): сбойные и отказные проверки сохраняются для разбора.
3. Решение `revise` — исход шлюза; в `ModerationCheck` оно хранится как `blocked` с кодом правила.
4. Утверждение «другая модель» опирается на идентификаторы моделей (контракт); разные ID у одного
   upstream агрегатора не доказывают независимость провайдера — решение оператора.

## Не проверено / ограничения

Качество классификатора (набор испытаний RU/EN, обходы, ложные блокировки, задержка), очередь ручного
разбора и журнал инцидентов, аудио/изображения/видео, правовые пакеты по странам, реальный каналовый шлюз,
запись `Utterance.moderation_status` владельцем gateway (здесь утверждение приходит как входной объект).
