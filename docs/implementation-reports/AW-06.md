## Результат

- `ai_agent_application/agent_experience`:
  - `PersonaContext` — минимальный контекст личности для шага: канон, стиль, текущее
    состояние (persona owner), открытые обязательства (social owner, точный список, не
    top-k), воспоминания по цели задачи (recall, `api_transfer`). Всё, что уходит в модель,
    проверяется на `api_transfer` и доступность источника; что не проходит — не
    показывается и не пересказывается. Текст помечен как данные (`‹ ›` вместо тегов).
  - `ExperienceRecorder` — возврат результатов владельцу памяти. Успешный tool step,
    записавший файлы через их владельца (receipts — версии файлов), становится источником
    `observation` (`workplace-result`) и **одним** подтверждённым эпизодом
    (`operation_id = work-<attempt>`). Собственный вывод при `complete` — источник
    `interpretation` (`workplace-conclusion`), без эпизода. План, попытка, failed step
    и шаг без записанного результата не пишутся. Ключи — по попытке: retry/replay не
    добавляет второго основания. TEST записывается как `simulation` в своём разделе.
- Композиция (`m3_composition/workplace_experience.py`, вызовы из `activity.perform`):
  бриф строится до подготовки попытки, его источники входят в `inputs` попытки (lineage
  всего, что породит шаг); бриф есть и в выборе собственной цели вместе со списком
  доступных возможностей — характер влияет на цель и метод, без списка занятий в ядре.
  Запись опыта делает владелец деятельности после шага, не executor; изменения характера
  остаются за bounded development, который читает эти эпизоды как любые другие.
- Права: при включённой деятельности ACTIVITY читает MEMORY (только чтобы записать входы
  попытки); ACL новых источников включает ACTIVITY (только чтение). Бриф проверяет
  источник глазами ACTIVITY: источник, который попытка не может записать как вход
  (например, старый — с прежним ACL), не показывается модели.

## Ограничения

- Эпизод фиксирует действие агента с его файлами; качество/значимость (что считать
  важным опытом) — за существующим memory cycle и bounded development.
- Старые источники с прежним ACL в бриф не попадают, пока их ACL не обновлён владельцем.
