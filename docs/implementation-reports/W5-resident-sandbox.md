# W5: долгоживущий контейнер личности

Claude Code, 2026-10-26. План: [doc31 §6, §9](../31-agent-workspace-v2.md).
Ветка `claude/w5-resident` от W4. Инструкция: [agent-workspace.md](../agent-workspace.md).

## Что сделано

- **Режим resident** у прогретого контейнера (`warm_entry.py`, `warm.py`). Тот же
  `opencode serve` отвечает ход за ходом. Перед ходом: пустые `inputs/`/`outputs/`,
  свежий `/guide`, открыть фасад; после — удалить сессию OpenCode
  (`DELETE /session/{id}`), дождаться конца вызовов и закрыть фасад, вернуть
  результат. Процессы не убиваются: фоновая работа агента живёт между ходами.
- **Без накопления переписки.** Каждый ход — новая сессия OpenCode с контекстом,
  который собрала платформа; история хода удаляется. Неудачное удаление → ход failed →
  контейнер закрывается.
- **Фасад закрыт между ходами.** Обращение к модели или владельцам вне хода — 403;
  хост между ходами stdout контейнера не читает.
- **Хост.** `WarmSandbox(resident=True)`: `claim` на ход, `release` после чистого
  результата (ресурс попытки подтверждается, контейнер остаётся под владельцем
  WarmSessions), иначе `close`. Простой — `resident_idle_seconds` с последнего хода.
  Runner не ждёт выхода контейнера после результата, проверяет, что он жив и не OOM.
  `WarmSessions` держит его, пока нет простоя/STOP/смены личности.
- **Хост пропал — контейнер завершается.** Конец stdin (процесс платформы умер) —
  немедленный выход PID 1 со всеми фоновыми процессами: после сбоя/перезапуска работа
  не продолжается сама.
- **Исправлено:** проверка метки контейнера читала полный `docker inspect`, который с
  выросшим скриптом входа превысил 64 КиБ, и удаление считалось неизвестным; теперь
  читаются только метки.
- **Настройка:** `--resident`, `--resident-idle-seconds` (60…14400, 1800); включает
  подготовку контейнера, как `--prewarm`.

## W5b: интернет в долгоживущем контейнере

- Если у личности действует разрешение на интернет, `WarmSessions` готовит контейнер
  вместе со шлюзом (`WarmSandbox(egress=...)`): сеть задаётся при создании, прокси и
  сеть закрываются вместе с контейнером. `claim` требует совпадения «с сетью / без»;
  ход без разрешения не возьмёт сетевой контейнер, и наоборот.
- Проверка разрешения каждые 5 с при обновлении допуска: отзыв закрывает свободный
  контейнер сразу; во время хода — периодическая проверка хода (W3).
- Журнал: `attempt: resident`, лимит объёма — на время жизни контейнера.
- Проверено настоящим OpenCode (`test_resident_sandbox_with_its_own_gateway`): два хода
  через один шлюз, example.com в обоих; после закрытия нет ни прокси, ни сети.
