# Голосовое с подписью одним сообщением

2026-10-30. Поручение оператора: разобрать и решить обращение о голосе и тексте
в одном посте. База: main `f3e6487`. Ветка: `codex/telegram-voice-caption`.

## Причина и изменение

Telegram `sendVoice` и наш TelegramBot уже поддерживают `caption`, но ChannelPost
не передавал его. Добавлен необязательный аргумент MCP `channel_post.caption`:

- `voice=true`, без caption: подпись равна text;
- отдельный caption: озвучивается text, под голосовым показывается caption;
- `caption=""`: голосовое без подписи;
- caption при voice=false или сверх лимита отклоняется до модерации и синтеза.

Для эмоциональной озвучки передавать, например:

```json
{"text":"[warm] Добрый вечер.","voice":true,"caption":"Добрый вечер."}
```

Одна проверка модератора получает и озвучку, и отдельную подпись. При отказе
ни синтез, ни отправка не происходят. Проверки эпохи/STOP сохранены. Выполняется
один sendVoice, отдельный sendMessage не создаётся. Подпись сохраняется в прежнем
локальном журнале исходов, рядом с текстом озвучки. Новых прав нет.

Лимит подписи — 1024 UTF-16 единицы (консервативный предел, включая emoji),
текущий лимит текста озвучки — 1000 символов. Не режем текст молча.

Источник: [Telegram Bot API — sendVoice](https://core.telegram.org/bots/api#sendvoice).

## Включение

На момент сдачи личный сервер не перезапускался. Изменение вступает в силу после
штатного STOP и обновления/перезапуска сервера на этой ревизии. Образы Docker,
панель, настройки прав, ключи и данные менять не требуется. Реальные платные
вызовы и публичные тестовые публикации не выполнялись.
