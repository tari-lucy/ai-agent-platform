# W1: журнал рабочего хода

Claude Code, 2026-10-26. План: [doc31 §9](../31-agent-workspace-v2.md#9-порядок-перехода),
решение D73. Ветка `claude/w1-turn-journal` от main `e37b3bf`.

## Зачем

Аудит архивного хода не смог установить, что реально исполнялось: из потока событий
OpenCode платформа сохраняла только финальный текст и имена инструментов с ошибкой.
Следующий ход видел лишь собственные прежние утверждения модели и повторял их как факт.

## Что сделано

- **Сбор в контейнере.** `agent_harness/worker.py`: каждый завершённый вызов инструмента
  (холодный путь `opencode run --format json`) становится шагом: имя, статус, начало
  аргументов (300 симв.), начало ответа (400 симв.) и полный размер ответа. Журнал —
  последние 40 шагов в пределах 16 КиБ, более ранние только считаются.
  Прогретый путь (`sandbox/warm_entry.py`, `opencode serve`) читает **все** сообщения
  ассистента сессии: каждый шаг цикла OpenCode — отдельное сообщение, прежде виден был
  только последний.
- **Исправлены обрывы хода.** Холодный путь читает поток построчно (до 8 МиБ на строку,
  без общего потолка на ход): чтение файла больше 64 КиБ и промежуточный текст модели
  больше 16 000 символов больше не делают весь ход `OPENCODE_RESULT_INVALID`.
- **Совместимость.** `worker.py` вшит в образ. Пока образ не обновлён, оба пути работают
  как раньше, без шагов (warm проверяет наличие новых функций в образе).
- **Хранение.** `ToolStep` и поля `WorkAttempt.tool_steps`/`tool_steps_omitted`;
  `ActivityBook.record_steps` пишет журнал один раз, пока ход `submitted`, в том числе
  для неудачного хода. После STOP (`ex.verify`) журнал не записывается.
- **Показ.** `WorkSessionEntry.steps` у каждого ответа агента и `WorkSessionProgress.steps`
  у текущего хода — только пока открыты источники и файлы этого хода (тот же
  `bases_open`, что и для текста). Ответ связан с ходом по `reply_to_sequence` =
  `session_sequence` успешного хода.
- **Следующий ход.** Системное сообщение «Журнал инструментов твоего прошлого хода…» —
  до 3000 символов, с указанием опираться на него, а не на прежние утверждения.
  Текущий ход получает зависимости наблюдаемого хода, поэтому отзыв материалов
  закрывает и его.
- **Окно OpenCode (патч 16).** Мост `aw/bridge.ts` превращает журнал в родные элементы
  `tool` перед текстом ответа; так же у черновика (`reply_ready`) и у уведомления
  о неудачном/отменённом ходе. Обрезанный ответ помечен «показано начало, всего N симв.».

  родными `tool` перед текстом); `bun run typecheck` чистый.

Не проверено: настоящий OpenCode-образ и Windows/Docker (нужна пересборка harness
`scripts/refresh_opencode_harness.py` — проверка Codex), живая модель.

## Для проверки на Windows

1. Обновить deployment checkout, собрать native UI с патчами 1–16.
2. Пересобрать доверенный harness поверх pinned-образа и указать новый image ID в
   `enable-work-sessions`.
3. В разговоре попросить агента выполнить действие инструментом (например, разбор
   архива Python-песочницей). Ожидание: шаги видны в окне перед ответом; на следующий
   вопрос «что ты запускал?» ответ опирается на журнал.
