## Приёмка

| Критерий M3-04 | Результат (реальная SQLite) |
| --- | --- |
| Изоляция work/test | лаборатория отказывается работать не в test-области; на каждый запуск своя свежая область и индекс; отпечаток рабочих областей до/после (при одном виртуальном моменте) не меняется на всём каталоге; сценарий, записавший в рабочую область, падает по `ISOLATION:work`; тестовый отчёт — запись `LaboratoryReport` только в test |
| Seed replay | одинаковый seed → одинаковый digest в новом мире (ID, время и порядок детерминированы), другой seed → другой digest; выбор семейства/варианта/силы кубиками GM зависит только от seed, оба семейства достижимы на разных seed |
| Сценарии doc22 | 8 сцен + STOP во время генерации, обрыв API, restart → явное возобновление, удаление: все проходят жёсткие инварианты (узнавание без повторной анкеты, обещание не теряется и не «выполнено» ложно, одинаковые ники — разные люди, слух хранится как reported и противоречие сохраняется со связью, малые границы развития, отказ → тишина без вызовов модели, два опыта → изменение состояния и контекст следующей реплики, инъекция остаётся данными) |
| Перенос только выбранных настроек | preview с diff и блокерами совместимости; перенос требует решения оператора и digest предпросмотра; только выбранные ключи; память/люди/эпизоды/состояние не копируются; несовместимая ревизия блокируется до изменений; направление test → work и общий workspace проверяются |
| Виртуальные часы | месяц виртуального времени — доли секунды; retry-паузы шлюза идут виртуально; вызовы по расписанию срабатывают в свой момент |

Автоматические жёсткие инварианты каждого запуска: `TEST_SCOPE_ONLY`, `ISOLATION:*`, `NO_UNSCRIPTED_MODEL_CALLS`,
`STOP_RESPECTED`, `NO_SECRETS_IN_REPORT`; находки сценария делятся на жёсткие и мягкие (известный пробел).

Мутации защит (24): инварианты runner, области lab/runner, статус по жёстким находкам, исключения, сброс часов, назад во
времени, наивный старт, callbacks, все проверки переноса (направление/workspace/пустой и неизвестные ключи/digest/решение/
блокеры/невыбранные), restart/stop — каждая роняет тест; 2 остаются эквивалентными (дублирующий guard области в runner при guard в `Lab.create`; дублирующий флаг допуска при `run_state=STOPPED`).

## Решения и допущения

1. Часы runner общие с хранилищем: каждый запуск начинается в фиксированный момент (воспроизводимость и TTL в
   виртуальном времени); изоляция сравнивается в тот же момент, чтобы истечение TTL не выглядело записью.
2. Сценарии скриптуют mock-модель (она же проверяет, что платформа делает с ответом); незаскриптованный вызов — жёсткая
   находка. Реальные вызовы — отдельная явная операция и в M3-04 не выполнялись.
3. Пробел, найденный лабораторией: у `SocialService.apply_aspects` нет встроенного лимита скорости изменения отношений
   (±0.05 по doc22) — нужен валидатор развития отношений (аналог M3-03). Сценарий фиксирует его мягкой находкой.
4. Вне зоны: `SocialPort.settle_question` теперь с `Literal`-типом результата (ошибка типизации порта M2-06, найдена при
   подключении), в `moderation/local.py` добавлен `secret_like` (узкая проверка секретов без эвристик личных данных).
5. Отчёт хранится как `LaboratoryReport` без полного текста и без артефакта; полный JSON отдаёт `ScenarioReport.to_json()`.

## Не проверено / ограничения

Качество личности и диалога на реальной модели (оценка оператором 1–5, 20 сценариев × 3 повтора), панель лаборатории,
запуск через job/worker, Windows, хранение отчёта как артефакта, `story_rules_version`/`gm_intensity` лежат в простом
хранилище настроек (реальное — решение composition).
