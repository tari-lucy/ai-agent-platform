# W3: выход в интернет через шлюз платформы

Claude Code, 2026-10-26. План: [doc31 §4, §9](../31-agent-workspace-v2.md), решения D72, D75.
Ветка `claude/w3-egress-gateway` от main `c9348ad`. Инструкция оператора:
[agent-workspace.md](../agent-workspace.md#интернет-через-шлюз-w3).

## Что сделано

- **Шлюз на ход** (`sandbox/egress.py`, `sandbox/egress_proxy.py`). Для каждого хода
  с интернетом: внутренняя Docker-сеть `aw-net-…` (`--internal`) и контейнер-прокси
  `aw-egress-…` из того же доверенного образа (скрипт передаётся через `-c`,
  пересборка образа для самого прокси не нужна): read-only, cap-drop ALL,
  no-new-privileges, uid 65532, 128 МиБ, 64 процесса. Прокси подключён к обычной
  bridge-сети и к внутренней; агент — только к внутренней. Проверено: во внутренней
  сети нет внешнего DNS и маршрута наружу, единственный путь — прокси.
- **Политика прокси.** HTTP CONNECT (HTTPS и любой TCP через туннель) и обычный
  `http://`. Имена резолвит сам прокси, соединяется только с `is_global` адресом
  (не private/loopback/link-local/CGNAT/multicast, IPv4-mapped IPv6 разворачивается),
  кроме сетей оператора `--egress-deny`. Почтовые порты 25/465/587 закрыты. Лимиты:
  байты за ход (обрыв и отказ дальнейших запросов), число одновременных соединений,
  таймауты соединения и простоя.
- **Журнал.** Строка JSON на запрос: метод, цель, статус/причина, байты вверх/вниз,
  адрес, длительность; хост дописывает время, личность, попытку и пишет в
  `<root>/data/egress/ГГГГ-ММ-ДД.jsonl` (0600). HTTP — полный URL; HTTPS — только
  `сайт:порт`: без подмены сертификатов (оператор, 2026-10-26).
- **Runner.** `DockerTaskRunner(egress=...)`: регистрирует шлюз как ресурс хода,
  открывает его до создания контейнера агента, передаёт `proxy` в payload; после
  удаления агента удаляет прокси и сеть, в том числе при отмене (STOP). Без квитанции
  удаления — `unknown`, как для контейнера агента. Прогретый контейнер создаётся без
  сети, поэтому ход с интернетом всегда холодный.
- **В контейнере.** `HTTP(S)_PROXY`/`ALL_PROXY` (обоих регистров), `NO_PROXY` для
  loopback-фасада модели. OpenCode получает `webfetch` (поиск по-прежнему выключен).
  При доме кэш (`XDG_CACHE_HOME`) в `/workspace/.cache`: ripgrep, который OpenCode
  скачивает для `grep`/`glob`, загружается один раз, а не каждый ход.
- **Права.** `enable-work-sessions --internet` заводит возможность `workplace.internet`
  (manifest `external_effect`, binding ready); пользоваться ей можно только после
  разрешения оператора (обычное обращение → «Разрешить…»). Решение принимается в
  начале хода; периодическая проверка хода требует и разрешения на интернет —
  отзыв обрывает ход.
- **Тексты.** Описание среды с интернетом: шлюз, журнал, лимиты, запреты, отказ 403 —
  граница, не сбой; не отправлять личное без просьбы; публикации — только через
  подключения. Фраза «сети нет» и «модель — не доступ к сети» убираются в таком ходе.

## Проверки (Linux VPS, Docker 29, живой интернет)

- ruff, mypy (314 файлов) — чисто.
- Без Docker: `test_egress.py` — политика адресов (включая metadata, CGNAT, IPv6,
  mapped, multicast), разбор целей, лимиты, сеть только своя; прокси в процессе:
  отказ loopback и почтового порта, обрыв по лимиту байтов и отказ после него, журнал.
  `test_internet_wiring.py` — границы настроек, тексты, заведение возможности,
  недоступность без разрешения и доступность после решения оператора, CLI.
- **Настоящий Docker** (`AW_EGRESS_LIVE=1`): `test_egress_docker.py` — HTTP и HTTPS к
  example.com через шлюз; metadata, 10.0.0.1, 172.17.0.1 (Docker-хост) и порт 25
  отклонены; DNS и прямой маршрут отсутствуют; журнал (полный URL для HTTP,
  `example.com:443` для HTTPS); прокси и сеть удалены; STOP посреди хода удаляет
  агента, прокси и сеть.
- **Настоящий OpenCode** (`test_real_home.py`, синтетическая модель): bash (Python
  urllib) и `webfetch` OpenCode получают example.com через шлюз; оба шага в журнале хода.
- Полный gate: см. итог ниже.

Не проверено: Windows/Docker Desktop (внутренние сети, `docker network connect`
на созданном контейнере, адрес Docker-хоста там другой), живая модель, решение
о доступе на composition-уровне в настоящем ходе (проверено логикой и тестами
частей). Проверка — Codex.

## Не входит (W3b)

- Образ «руки»: Chromium/Playwright, ffmpeg, JDK, git — нужна сборка с сетью.
- Просмотр журнала трафика в панели и дневной лимит (сейчас лимит на ход).
- Внешний прокси/VPN на выходе шлюза — отложено оператором.

## Риски

- Открытая сеть: модель может отправить наружу то, что есть в её контексте
  (риск принят D72; смягчение — журнал, лимиты, отсутствие секретов в контейнере).
- Публичный адрес самого хоста считается «публичным»: если на нём открыты сервисы,
  закройте их или добавьте адрес в `--egress-deny`.
