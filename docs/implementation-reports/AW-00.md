## Что опубликовано

`packages/contracts/src/ai_agent_contracts/agent_workplace.py` — записи (все
`VersionedRecord`/`Record`, общий `Scope`, `SourceRef`, `ArtifactRef`, CAS по `version`):

| Запись | Owner | Назначение и инварианты |
| --- | --- | --- |
| `CapabilityManifest` | workspace | Описание существующей `workspace.Capability` для выбора агентом: effect, области, `network: none/gateway`, нужен ли runner. `instructions` — данные, не команда |
| `CapabilityBinding` | workspace | Подключение адаптера: `pending/ready/disabled/revoked`; `ready` только с `verified_at`. Одобренный тикет не делает binding готовым |
| `WorkTask` | activity | Смысловая задача: origin `assignment/own_goal/commitment/ticket_followup`, состояние, `waiting_ticket_ids` обязательны для `waiting`, `outcome` для завершения |
| `WorkAttempt` | activity | Одна попытка шага, связанная ровно с одной `Job.operation_id` и `Freshness` запуска. Записывает входы (`inputs`, `input_files`) для вычисления зависимостей; `unknown` требует сверки |
| `ManagedFile` | catalogue | Версия файла: `reference: ArtifactRef` (id/version совпадают), area, логический `path`, kind (material/note/hypothesis/method/script/plan/draft/result), provenance (read/generated/assumption/verified), полный `dependencies`, `derived_from`, access api/public, state active/blocked/deleted, TTL, `produced_by_attempt` |
| `FileWrite` | — (запрос) | Запрос к файловому владельцу: CAS `expected_version` (None — создание), checksum/size содержимого, `attempt_id`, `declared_sources` только добавляют зависимости. `reference`/`guide` — только чтение; агент не может объявить `verified` |
| `SkillVersion` | skills | Метод поверх существующих возможностей: применимость/ограничения, файл метода и helpers по ссылке, `experimental/verified/retired`; `verified` требует evidence |
| `Ticket`, `TicketMessage` | tickets | Переписка: 4 состояния, `next_turn`, `duplicate_key` (уникален), occurrences, unread через `operator_read_version`, связанные задачи/материалы, `CapabilityRequest` только для `capability_request` |

Инварианты, проверенные валидаторами:

- логический путь — нижний регистр ASCII, ≤8 сегментов, без `..`/пустых/абсолютных
  сегментов, `\`, зарезервированных имён Windows. Это имя в каталоге, не host path;
  физическое размещение по opaque ID выбирает AW-02;
- личные области (`ManagedFile`, `SkillVersion`) принадлежат стабильным
  workspace/persona/memory_space/mode: `agent_id/run_id` в scope запрещены;
- `active` файл не может иметь удалённую/истёкшую/недоступную зависимость — он
  становится `blocked`, зависимость не выбрасывается; `verified` без оснований запрещён;
- ссылки на чужой partition отклоняются общим `SCOPE_MISMATCH`.

Хранение: те же JSON-records/UoW/revisions (`SPECS`), без миграции. Storage сам
проверяет существование `SourceRef` у owner источника, owner записи, CAS и replay.
Semantic keys: `work-attempt` (task, attempt_no), `managed-file-path` (area, path —
одно имя на область, ключ следует текущей ревизии), `ticket-duplicate`,
`ticket-message` (ticket, sequence). Новые owners: `ACTIVITY`, `SKILLS`, `TICKETS`.
Новые модели в wire-каталоге (`catalogue.MODELS`, JSON Schema/OpenAPI/TS
обновлены). `READ_MODELS` (HTTP-чтение) намеренно не расширены: маршруты
добавляет владелец каждого пакета вместе с правами чтения (AW-01 — tickets).

### Порты: `ai_agent_application/agent_workplace/ports.py`

- `WorkAdmission` — доверенное доказательство «эта попытка может делать IO сейчас»:
  scope, freshness, operation/attempt/lease, `is_current()` (epoch STOP, lease,
  отмена). Каждый owner вызывает его непосредственно перед своим commit.
- `ReleaseGuard.verify(admission, sources, files, purpose)` — атомарная проверка
  источников/TTL/ledger/прав перед сохранением или выдачей. Одна для файлов,
  skills, тикетов и harness.
- `AttemptContext.attempt()` — записанные входы попытки (основание зависимостей).
- `WorkspaceFiles` (AW-02): `read`, `list`, `search`, `write(admission, FileWrite, bytes)`.
  Контракт: digest/size/path/quota, объединение входов попытки с `declared_sources`,
  ReleaseGuard, CAS, идемпотентность по `request_id`.
- `CapabilityCatalogue.manifests(scope)`, `TicketDesk.open_or_append/pending_for_agent`.
- `ModelGateway.generate(admission, ModelRequest)` — единственный путь модели для
  activity и harness; реализуется composition поверх существующих `LLMGateway`,
  `PrivateAPIBudget` и `AttemptJournal`; исчерпание → `not_admitted` без вызова.
- `TaskRunner.run/staged` (AW-04): `RunnerTask` со staged `ArtifactRef`, `RunnerLimits`
  CPU/RAM/PIDs/wall/output/disk, `network none|gateway`. Outcome — только отчёт;
  сохранять ли выход, решает файловый владелец.
- `AgentHarness.turn/cancel/close` (AW-08): `permission_ask` превращается в тикет,
  `close` очищает сессию/кэши harness.

## Чего нет (намеренно)

- Второго jobs ledger: попытка исполнения — существующие `ExecutionCommand/Job/
  ExecutionResult`; `WorkAttempt` только связывает задачу с `operation_id`.
- Второго реестра прав: права — `api.Permission` workspace owner; выдача/отзыв
  по тикету появится в AW-01 через этого владельца.
- Отдельного бюджета: `ModelGateway` обязан идти через текущий суточный лимит.
- Нового `WorkKind` у supervisor: деятельность использует существующий `activity`
  (supervisor — зона Codex; при необходимости отдельный вид согласуется окном).
- Panel commands/events для тикетов и файлов — добавляются AW-01/AW-07 в своих окнах.

## Decision note: OpenCode (AW-08 кандидат)

Проверка — только чтение официальной документации (opencode.ai/docs: permissions,
server, config, providers, plugins, agents, models, network; GitHub releases).
Ничего не устанавливалось и не запускалось; совместимость не доказана.

- Версия: последняя v1.19.3 (16.10.2026); кандидат для pin с запасом ≥2 недель —
  v1.18.35 (06.10.2026) или v1.19.x после проверки. В 1.19.0 снят авто-install
  обновлений, в 1.19.1 прекращён sharing. Точный pin выбирается в AW-08.
- Транспорт: `opencode serve --hostname 127.0.0.1 --port …` внутри sandbox, basic
  auth `OPENCODE_SERVER_PASSWORD`; `POST /session`, `prompt_async`, `GET /event`
  (SSE), `POST /session/:id/abort`, `DELETE /session/:id`,
  `POST /session/:id/permissions/:permissionID`; OpenAPI на `/doc`.
- Права: `"permission": {"*": "deny"}` + точечные `ask`; без `--auto`. `ask`
  приходит событием `permission.asked` → адаптер отвечает reject и открывает тикет.
  Нужно проверить взаимодействие `*` с дефолтами `read`/`external_directory`.
- Скрытые LLM-вызовы: title/summary/compaction агенты, `small_model` (по
  умолчанию может уйти на внешний «Zen»). Меры: единственный custom provider
  `@ai-sdk/openai-compatible` с `baseURL` на loopback-мост `ModelGateway`,
  `enabled_providers` только он, `small_model` = он же, `compaction.auto=false`,
  `subagent_depth=0`, `task: deny`. Любой вызов через мост учитывается бюджетом,
  поэтому даже недокументированный служебный вызов не обходит лимит.
- Ambient config/установки: применять только `OPENCODE_CONFIG_CONTENT`, пустые
  HOME/XDG в sandbox, без `.opencode/`, `plugin`, `mcp`, `lsp`, `formatter`;
  `autoupdate=false`. Managed `/etc/opencode` в образе пуст. Документированного
  отключения телеметрии и `OPENCODE_DISABLE_PROJECT_CONFIG` нет → сеть sandbox
  закрыта, кроме моста; это обязательная отрицательная проба AW-08.
- Открытые риски для AW-08: `/session/:id/shell` и `/command` — неизвестно,
  проходят ли permission rules (мост не должен проксировать эти маршруты);
  формат `response` разрешения не документирован; удаление данных сессии
  (`~/.local/share/opencode`) проверить на purge.

Если эти пробы не пройдут, остаётся минимальный собственный цикл поверх
`ModelGateway` + `AgentHarness`-порта; порт от выбора не зависит.
