# Связный приватный диалог и рабочая долговременная память

Дата: 2026-10-15. Исполнитель: Claude Code. Ветка `codex/private-dialogue-memory-quality`,
отдельный worktree, база `origin/main` 125974c (`docs: prioritize usable private dialogue and
memory for launch`). Ветки `a253c7e` и `a06b9a0` не использованы и не смешаны. Предыдущее задание
laboratory-report-lineage не выполнялось, каталоги отчётов не затрагивались.

## Что найдено (причина нулевых claims)

Находка «извлечение отработало, claims 0» **не доказана как ошибка**, и повторить её без платного
вызова нельзя. Но в коде был конкретный пробел, мешавший её объяснить: отчёт `Extractor` терялся
(`service.py` берёт только `accepted`), а «модель вернула пустой список», «все предложения
отклонены валидатором» и «нечего было показывать» выглядели одинаково — «0».

Гипотезы по убыванию вероятности для той пробы (проверяются одним запуском probe, см. ниже):

1. Модель вернула пустой список. Ввод был прямо назван вымышленным, а промпт говорит «нет
   оснований — верни пустой список». Это допустимый ответ, не дефект.
2. Валидатор отклонил предложения: цитата не дословна (`QUOTE_NOT_IN_SOURCE`), чужой `source_id`
   (`UNKNOWN_SOURCE`). Правила не ослаблялись.
3. Документ не прошёл закрытую схему (например, `subject_id` не латиницей): тогда пропадает **весь**
   ответ, и это `failed`, а не «0 claims» — но промпт не говорил, каким должен быть `subject_id`.
   Вывод ограничен `max_output_tokens=512` (по умолчанию), а схема разрешает до 20 предложений
   по 500 символов: длинный ответ мог быть обрезан.

## Что изменено

Зона: `extraction/**`, `m3_composition/{long_term,memory_cycles}.py`, `local_host/provider.py`,
`tests/memory_quality/**`, `scripts/probes/**`. `history.py` не менялся: окно из 8 реплик и проверки
доставки были корректны. Публичный API и существующие schedule/admission guards сохранены.

### 1. Диагностика (без текста, ключей и endpoint)

- `ExtractionReport` получил `offered`, `proposed`, `outcome` и `diagnosis()`. Исходы:
  `accepted`, `all_rejected`, `model_returned_nothing`, `no_usable_sources`, `failed`, `cancelled`,
  `not_admitted`. `Extractor.extract` пишет одну строку
  `Extraction outcome=… offered=… proposed=… accepted=… duplicate=… rejected=<КОД:число> skipped=…
  attempts=… [failure=КОД]`. Новых вызовов и retry нет.
- `Consolidator` логирует фиксированный код отказа (`NO_USABLE_SOURCES`, `GENERATION_<код>`,
  `NOT_ADMITTED`, `PERIOD_INVALID`), раньше возвращал `None` молча.
- `DailyMemory.tick` логирует `selected=N deferred=<КОД:число>`; контекст — строку
  `Private memory context: shown=… partial=… considered=… stale_source=… over_budget=… unrelated=…`.

### 2. Потери фактов

- Промпт extractor говорит то, что валидатор всё равно требует: цитата — непрерывный дословный
  фрагмент без многоточий; `subject_id` — латиница/цифры/`-`/`_` (иначе весь ответ отклоняется).
- Закрытый протокол роли (`local_host/provider.py`) больше не дублирует схему, которая уже есть в
  промпте роли (экономит около 1,7 тыс. символов и токенов на вызов extractor/reflection), и для
  extractor явно задаёт лимит вывода: не более 5 утверждений, claim — одно предложение, quote — до
  150 символов. Это следует из `max_output_tokens=512`, а не подбор формулировок.
- Известные claims, показываемые extractor для связывания противоречия, при >20 записях выбираются
  по близости к новым источникам, а не по порядку id.
- Оригинальная цитата остаётся точной. «Слова собеседника» остаются `reported` (потолок 0,6),
  `observed`/`canon` модель получить не может, собственный ответ даёт `interpretation` без
  независимой группы (потолок 0,4). Личность и права модель не создаёт.

### 3. Контекст (`long_term.py`)

- Рассматриваются 5 последних сводок и 40 последних claims, а не одна сводка и 10 claims; показ
  по-прежнему ≤3 фрагментов и ≤650 токенов.
- Русские формы: совпадение по общему началу слова («зонтиками» находит «зонтики»), без
  embeddings и второй памяти. Среди равных по релевантности утверждение собеседника ранжируется
  выше собственной интерпретации персонажа.
- Длинная сводка сокращается вокруг предложения, отвечающего на вопрос, и помечается
  `partial="true"`, а не отбрасывается и не режется по голове.
- Каждый фрагмент датирован (`at="…"`). Противоречащие claims показываются вместе и помечаются
  `disputed="true"`; старое не затирается. Метка снимается, если вторая сторона отозвана,
  так что отозванное не оставляет следа.
- Фрагмент по-прежнему данные: `<`/`>` экранируются, права и версии источников проверяются заново.

### 4. Рефлексия и restart

Код рефлексии не менялся. Подтверждено тестами: вывод вне границ политики получает
`StateChange=REJECTED`, `CharacterState` не меняется, job завершается успешно; «оставить характер»
не меняет состояние; повтор той же порции (даже под другим request id) возвращает прежний job без
новых вызовов; restart ничего не запускает сам, а `tick` после restart не создаёт второй цикл.

### 5. Сквозной сценарий

`tests/memory_quality/test_private_pipeline.py`: собранный production-host (`initialise` с
**публичным профилем** `profiles/examples/opechatka/profile.md`, `enable_memory`, `build`), настоящие
owners/HTTP и настоящий live-адаптер поверх синтетического `MockTransport`. Разговор из пяти
подтверждённых обменов (предпочтение и договорённость — в первом), цикл памяти, restart, новый
вопрос. Из тела запроса к «модели» видно, что она получила: 8 реплик окна (первая в них **не
входит**), сводку (`partial`, с нужным предложением) и два claims `reported`; чего не получила:
выдуманное «ездили на море» (цитата не найдена в источниках → отклонено), собственную «красную
зонтик»-интерпретацию как слова человека.

## Opt-in probe для координатора

`scripts/probes/private_memory_quality.py` (+ `scripts/probes/README.md`): новый временный host с
публичным профилем, штатный загрузчик env, потолок **5 или 6 вызовов** на уровне HTTP, только
синтетический разговор, отчёт из счётчиков, кодов и булевых признаков. Не запускается из pytest.

```text
python scripts/probes/private_memory_quality.py ^
  --i-understand-this-makes-paid-api-calls --model <id> ^
  --env-file C:\abs\.env --workdir C:\abs\NEW-dir [--max-calls 5|6] [--label-fictional]
```

Ожидаемый бюджет — 6 вызовов, порядка 6–8 тыс. входных и 2 тыс. выходных токенов (прошлая проба
из 3 вызовов: 4365/1582). Два запуска — с `--label-fictional` и без — отделяют реакцию модели на
пометку «вымышленный» от ошибки приложения.

## Ограничения и запросы

- Диагностика пишется в журнал процесса, а не в `MemoryCycle`: хранить исход в записи цикла
  можно только изменением контракта (не мой файл). Запрос владельцу contracts — по желанию:
  поля `proposed/accepted/rejected` в `MemoryCycle`.
- Эпизод, который один превышает 20 источников или 8000 символов (`pairs`), цикл не берёт никогда;
  теперь это видно в `deferred=RESOURCE_BUSY:N`, но разбиения эпизода нет (не придумано без
  изменения контракта).
- Подбор по общему началу слова — эвристика для русского; не морфология. Срок жизни (TTL) производных
  фрагментов проверен тем же путём, что отзыв прав (`source is None`), отдельного теста TTL нет.
- Реальные API-вызовы не выполнялись; ключи и endpoint не использовались.
