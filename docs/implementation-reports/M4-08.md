## Что сделано

Пять представлений поверх постоянной панели **«Полнота статистики»** (видна всегда, перечисляет, чего не хватает):

- **Обзор**: запросы/попытки/повторы, токены вход/выход (cached и reasoning — рядом, не прибавляются к родителям), отказы/отмены/
  неизвестные исходы, расходы **по валютам** (валюты не складываются, точная десятичная арифметика без плавающей точки),
  неизвестная цена не входит в сумму и не равна нулю; «расчётная оценка, а не счёт агрегатора».
- **Модели и роли** (только чтение): назначение, подключение, проверка возможностей, резерв, число попыток; резервное
  назначение не выдаётся за роль.
- **Цены**: версии тарифов по подключению и модели, действующая версия (последняя уже вступившая в силу), «не задана» вместо
  нуля; форма новой версии (единица, валюта, ставки, дата) с проверками и предупреждением о задней дате; **пересчёт** — отдельный
  явный план последствий, привязанный к версии выбранного тарифа (переиспользован `PlanFlow`).
- **История**: время, роль, запрошенная и ответившая модель (расхождение маршрутизации показано), статус, источник и полнота
  usage, токены, задержка, закреплённый тариф, цена или «неизвестно». Полные prompt/тексты/секретные URL не показываются.
- **Аналитика**: SVG-графики известных токенов и расхода по дням (отдельный график на валюту) с таблицей тех же данных;
  попытки с неизвестным usage отмечены, а не нулевые; распределение по ролям/моделям/подключениям.
- Фильтры: период, роль, модель (по ответившей), подключение (по закреплённому назначению). Тестовая память помечена.

## Приёмка

| Критерий M4-08 | Результат |
| --- | --- |
| Roles / rates | назначения и резервы, тарифы с версиями и «не задана», действующая версия |
| Tokens / currencies / attempts | итоги по валютам без смешения, повторы отдельно от запросов, cached/reasoning не складываются с родителями |
| Missing data | постоянная панель полноты: загружена не вся история, usage неизвестен/неполный, цена неизвестна, частичные расчёты |
| Historical repricing preview | пересчёт только через план (область, происхождение), план должен называть выбранный тариф и не быть просроченным; выполнение — одна команда, проверка исхода той же командой |

## Решения и допущения

1. Схемы `tariff.create` и `llm.recalculate` и цель команд — **предположения** (`LLM_SCHEMA` в `ui/llm/model.ts`); ждут владельца
   контрактов. До этого ядро отвечает отказом, панель показывает его честно.
2. Итоги считаются по **загруженным** страницам (по 50 + «Загрузить ещё» по серверному курсору); пока загружено не всё, панель
   полноты помечает статистику неполной. Серверных агрегатов в API нет.
3. Подключение попытки определяется по закреплённому назначению (`assignment_id`); если назначение не найдено — «unknown».
4. Назначения моделей, лимиты и уведомления бюджета 50/80/100 % не редактируются: нет схем и чтения лимитов; бюджетный ориентир
   $20/мес не показан (источника значения нет), чтобы не выдумывать.
5. Фильтра по сессии нет: у попытки нет `session_id`.
6. После очистки метаданных старше 90 дней (M5-01) прошлые месяцы живут только в агрегатах `retention_usage_aggregates`; у них нет
   чтения для панели, поэтому долгая история видна лишь за хранимый период.

## Не проверено / ограничения

- Реальная интеграция: нет исполнителей `tariff.create` / `llm.recalculate`, связи с `UsageLedger` (M2-05) и реальным агрегатором;
  сверка с биллингом агрегатора — не проверялась.
