# OC-03: восстановление нативной страницы сессии

## Поставка и границы

Продолжение WIP Claude `9fbaa0e` в отдельной ветке `codex/oc-03-render-diagnosis`,
с актуальным на начало проверки `origin/main` (`f16bbe4`). Upstream OpenCode
v1.19.3, commit `e3c4eb242585dcd77be1a867391b7c25fd47ce52`.
Третий воспроизводимый патч дополняет первые два; runtime, Bun, зависимости,
сборка и временные host не входят в Git. Личный deployment не изменялся.

## Подтверждённые причины

1. В `aw/bridge.ts` GET отдельного сообщения попадал в ветку списка: маршрут
   `/api/session/{id}/message/{messageID}` получал массив вместо объекта.
   HTTP оставался 200; hydrate отвергал результат, а обработчик поглощал ошибку.
   Ветке списка добавлено условие отсутствия messageID. Новый тест падал до правки.
2. В `context/server-session.ts` ответ assistant мог загрузиться раньше сообщения user.
   Проекция пока пропускала его без родителя, а появление user не пересобирало assistant.
   При изменении родителя теперь перепроецируется связанный ответ. Новый тест
   воспроизводит обратный порядок завершения двух запросов и падал до правки.

Полностью пустая страница из Linux-сообщения не воспроизвелась на Windows в исходном
WIP: заголовок и входящая реплика были видны. Найден скрывающий страницу readiness-gate
`autoselecting.loading` в layout, но его причастность не доказана; он не изменён.
После двух подтверждённых исправлений reload активной сессии проходит в Edge.
Это не доказательство устранения любого возможного Linux readiness-зависания.

## Доставка и ассеты

- Убрано подтверждение по совпадению первых 120 символов с текстом страницы.
  ACK требует зарегистрированный компонент точного ответа, совпадение directory,
  сессии, messageID, полного текста и work-scope. Видимость вкладки и минимум
  60% компонента проверяются IntersectionObserver. Перед отправкой перечитывается
  точная редакция владельца и повторно проверяется видимость.
- Одна автоматическая попытка на редакцию, идемпотентный request_id. Неудачный ACK
  не делает ответ доставленным локально. Для ручного восстановления остаётся
  существующий путь платформы; отдельная ручная кнопка в native UI здесь не добавлена.
- Убраны глобальные debug-хуки адаптера и ErrorPage. CSP не ослаблена: маленькие
  ресурсы вынесены в файлы, theme preload остаётся внешним скриптом под `/opencode/`.
  Markdown-worker по текущей CSP недоступен, остаётся штатный текстовый fallback.
- Сборка проходит валидатор: **938 файлов / 34 350 631 байт** без manifest,
  предел **1024 / 48 МиБ**. Копия адаптера в `dev/` синхронизирована с патчем.

## Проверки

- Windows, локальный Bun **1.3.14**, официальный архив проверен по SHA-256;
  frozen-install с ignore-scripts. Системная установка не выполнялась,
  upstream lockfile не менялся.
- Затронутые Bun-наборы: **77 passed**, 151 assertions, около 0,5 с.
  Маршрут отдельного сообщения, обратная загрузка user/assistant, условия ACK
  и существующие тесты server-session.
- `tests/panel/test_native_opencode_sessions.py`: **1 passed**, около 30 с.
  Настоящая собранная native-страница в Edge, настоящий production host/owners,
  синтетическая модель: вход → сообщение → reload STOPPED без вызова → START →
  reload ACTIVE → ответ → скрытая вкладка не ACK → обрезанный ответ не ACK →
  видимый точный ответ ACK → character в истории → reload без дубля → STOP.
  Один вызов модели; localStorage и sessionStorage пусты.
- Ruff изменённого Python-теста чистый. Полный suite не запускался.
- Три патча применены к точному upstream-тегу в независимом Git index;
  итоговое дерево совпадает с деревом проверенных исходников. На Windows старые
  патчи потребовали нормализации CRLF; для дальнейших checkout добавлен локальный
  `.gitattributes` с LF для серии.

## Что не проверено и следующий шаг

Общий upstream typecheck остановился до анализа адаптера: Windows checkout
представляет upstream symlink `src/custom-elements.d.ts` как текст пути, TS1128.
Это не объявляется успешной проверкой типов. Vite production-build и Bun-тесты
успешны. Linux typecheck/повтор исходного Linux blank-сценария остаются полезной
проверкой для Claude после передачи ветки.

Нет платных вызовов, проверки качества настоящей модели, настоящего Docker runner
в этом браузерном сценарии, нового OAuth-входа, автономного многопрофильного gate,
финальной проверки всех native-кнопок и активации на личном host. Не закрываются
OC-02/OC-06 и весь OC-03 исключительно этим отчётом. Сначала сверить оставшийся объём
с Claude, принять клиентскую поставку, затем подключить собранный кандидат через
`serve --opencode-ui-dir` и проверить реальную сессию с существующим runner.

Сборка и команды: [deploy/opencode-ui/README.md](../../deploy/opencode-ui/README.md).
