# GM: автоматическое снятие паузы после явного START

Дата: 2026-10-30. Задача оператора: не снимать паузу GM вручную каждый запуск.
Ветка `codex/gm-auto-start`, база `b7a5594` (подключённый Telegram-пакет).

Добавлен необязательный локальный `live.gm.auto_start=false`. Команда настройки:

```text
python -m ai_agent_core.local_host configure-gm --root <host> --auto-start
```

`--no-auto-start` возвращает прежнее поведение. Условие передаётся через явные
фабрики в Supervisor; API-контракты, миграции и права не меняются. Автостарт
разрешён только если GM включён оператором и новый запуск — autonomous/WORK.
Создание приложения и recover остаются STOPPED с паузой GM; observation и TEST
ничего не включают. Во время текущего запуска ручная пауза сохраняется, тики её
не снимают. Следующий явный START снова применяет заданную политику. STOP
отзывает допуски как раньше; поздний результат ничего не применяет.

Проверки: четыре новых сценария supervisor и production host с временным root,
синтетическим провайдером, двумя перезапусками и выключением опции. Вместе с
прежними GM offline/path и control: **53 passed за 87,75 с**. Модель в новом
host-сценарии не вызывается: нет опыта — NO_EXPERIENCE, а не фиктивные основания.
Первый запуск собственных новых unit-тестов обнаружил неверное имя метода в
тесте; исправлено на актуальный control. Для интеграционного набора потребовались
штатные test-support каталоги в PYTHONPATH. Полного gate и платных проб не было.

На личном host GM уже был включён, направление линии задано, лимиты — 2 предложения
в сутки и интервал 60 минут активного времени. Эти значения, линия, бюджет и права
сохраняются; меняется только auto_start. Автостарт не означает немедленный вызов:
действуют опыт, интервал, интенсивность, занятость и общий бюджет.

Граница этой задачи: включает существующий планировщик GM. Перенос получения и
принятия его Opportunity из прежнего dialogue-controller в родной OpenCode этим
изменением не реализуется: в текущем persona_brief MCP этого маршрута нет. Это
отдельный стык doc33, а не основание объявлять весь эффект GM в OpenCode принятым.
