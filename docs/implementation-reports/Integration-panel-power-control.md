# Integration-panel-power-control — единая верхняя кнопка START / STOP

Дата: 2026-10-15. База main `816160f`, ветка `codex/panel-start-stop`.
Назначение: исправить доступность запуска из диалога по запросу оператора.

## Изменение

Верхняя кнопка раньше всегда показывала STOP, а запуск был спрятан в разделе
«Рабочее пространство». Теперь тот же основной control показывает зелёный START
при подтверждённом STOPPED и красный STOP во время работы/запуска/неизвестного
исхода. Размер кнопки одинаковый, положение не меняется. Продвинутые controls
рабочего пространства сохранены.

START использует действующую agent.start-команду, текущие scope/agent/version
подтверждённого владельца запуска и режим autonomous для общения. Просмотр
другого TEST-профиля не перенаправляет запуск. Неизвестные/ошибочные/загружаемые
данные не разрешают START; FAULTED/STOPPING не становятся готовностью к запуску.
Нет оптимистичного ACTIVE: после принятой команды ожидается проекция ядра.

STOP использует прежний отдельный direct HTTP port. Запуск, чтения, WS и обычные
команды его не блокируют. STOP доступен и при задержке start-response; поздний
ответ на start не отменяет результат STOP. При неизвестном исходе start отдельная
проверка повторяет **ту же** команду с тем же request_id, автоматического нового
старта нет. Права, backend, настройки API, профиль и рабочая память не менялись.

## Проверки

- Node 24.19.0 / npm 11.17.0: lint и production build/typecheck прошли.
- Существующие client/owner-model проверки: **159 passed**, 0.55 s.
- Затронутый браузерный набор на установленном Edge: **12 passed**, 37.65 s.
  Включает реальный production init/serve на изолированной SQLite: вход прямо
  в диалог → START → mock reply → ack → STOP → снова START → удержанный ответ
  start → независимый STOP → поздний start-response → restart снова STOPPED.
  Остальные случаи покрывают scope isolation, ошибки STOP, CSRF и чтение,
  которое зависло. M1-only auth fixture теперь ожидает START при STOPPED;
  её direct STOP тест сохраняет реальный handler и отдельную ACTIVE UI projection.
- Один добавленный focused browser case: **1 passed**, 3.08 s. Отказ сети при
  START, ручная проверка тем же command ID, просмотр чужого TEST и direct STOP.
- Python test sources: ruff чистый. Diff/privacy/link checks перед commit.

Новые paid API-вызовы не выполнялись, существующий live runtime не перезапускался,
его STOPPED/ACTIVE состояние не менялось этой задачей. Пересобран именно dist,
который обслуживает уже запущенный local host; для новой кнопки достаточно
обновить страницу браузера. Это не приёмка всех остальных экранов или Linux UI.
Известные предупреждения Vite о большом bundle и старого websockets backend
остались прежними; зависимости и конфиги сборки не менялись.
