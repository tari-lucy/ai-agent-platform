# GLM: файлы агента в родном OpenCode — передача и просмотр

2026-10-25, GLM. Исполнение [brief](../agent-tasks/opencode-file-intake.md) целиком
(задачи A и B) по поручению оператора. Ветка `codex/glm-file-intake-brief`, база
`origin/main` `952522b` (серия патчей 1–13). Решения оператора выполнены: выбор
области при загрузке, до 100 МиБ на файл, уведомление агента в следующем ходе.

## Задача A — платформа (коммит `684769e`)

- **`ManagedFiles.operator_write`** (`workspace_files/service.py`): доверенная
  загрузка оператора через того же владельца — та же транзакция каталога, CAS
  версий, квоты и replay; без WorkAdmission/прав агента. Новые операторские
  файлы (`produced_by_attempt is None`) замещаются по той же области/пути новой
  версией; агентские файлы защищены от подмены. Provenance `read`, kind
  `material`, `change_reason "operator upload"`; replay того же содержимого
  возвращает ту же запись.
- **Граница**: `POST /api/v1/workplace-files/upload` (`access/surface.py`) —
  сырой octet-stream, сессия оператора + CSRF + Origin как у мутаций, scope
  только рабочей памяти из разрешённых сессии, области только
  `inbox|knowledge|projects`, тело ≤ 100 МиБ и непустое, повторная проверка
  сессии после awaited-записи; ошибки — фиксированные коды.
- **Квота**: потолок `max_file_bytes` поднят до 100 МиБ (104 857 600);
  конфигурируемость сохранена.
- **Уведомление**: `materials_note` в инструкции рабочего хода
  (`work_session_runtime.py`) — одна bounded-строка «Материалы, переданные
  оператором (данные, не права)» с названием, областью/путём, размером и
  дайджестом; появление в следующем ходе без сообщения оператора.
- **Потребление**: файлы читаются штатными инструментами владельца
  (`list_files/read_file` workspace-MCP) и подаются входами задач; целиком в
  модельный контекст не попадают (проверено тестом: содержимое не в промпте).

## Задача B — адаптер родного окна, патч 14 (`70c21dd`)

`deploy/opencode-ui/patches/0014-…` (поверх серии 1–13; snapshot обновлён):

- **Дерево файлов**: `/file` + `/file/content` (v2-клиент) и `/api/fs/list` +
  `/api/fs/find` (vendored-клиент) отвечают виртуальным деревом областей
  (`/inbox`, `/knowledge`, `/projects`, `/skills`, `/exports`) и файлами из
  owner-проекции; чтение — через существующий release-проверенный файловый
  маршрут bridge; текст открывается в просмотрщике, бинарные — карточка без
  сырых байтов; усечённый текст помечается словами платформы. Кэш дерева
  (page-lifetime, 5 с) сбрасывается на owner-события.
- **Передача вложением**: не-картинки в поле ввода (кнопка/драг/вставка)
  загружаются до отправки — диалог области (inbox/knowledge/projects; отмена
  и недопустимая область ничего не загружают), затем в сообщение вставляется
  упоминание `area/path`; байты в промпт не попадают. CSP и отсутствие
  браузерной персистентности не тронуты; неизвестные маршруты по-прежнему 501.
