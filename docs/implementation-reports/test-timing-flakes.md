# Нестабильные по времени тесты (разрешено оператором 2026-10-21)

Ветка `codex/fix-timing-flakes`. Только тесты; production-код не менялся.

## `integration_dialogue/test_http.py::finish_job`

Общий helper ждал завершения задания фиксированные 10 с (200 × 0,05). Под нагрузкой задание
стартует на тике runtime позже, и тесты на нём (`local_host/test_memory.py` и др.) падали с
`LOCAL_JOB_DID_NOT_FINISH`. Теперь ждёт по сроку до 60 с; проходящие тесты не замедляются.

## `integration_dialogue/test_history.py[unacknowledged]` — диагностика

Под нагрузкой задание первого сообщения заканчивается `OUTCOME_UNKNOWN` (не таймаут
ожидания). По коду `JobOwner.reconcile` (`jobs/owner.py`) это даёт один из двух путей:
1. истекла аренда (20 с, продление каждые 5 с) — цикл событий надолго задушен; для
   диалогового задания (не retry-safe) это верный `OUTCOME_UNKNOWN`;
2. `_admission(command)` в reconcile бросил временный `ContractError` (например, истекло
   двухсекундное доказательство политики при медленной записи — продление обходит это
   повтором, reconcile — нет) — тогда здоровое задание ошибочно получает
   `OUTCOME_UNKNOWN`. Это была бы production-проблема ядра jobs, не теста.
Какой путь срабатывает — проверяется воспроизведением под синтетической нагрузкой с
логированием; решение по пути 2 — владельцу jobs (Codex) / оператору.
