## Что сделано

`UsageLedger` (владелец `Owner.LLM`): запись попыток из `AttemptReport` шлюза M2-04, версии тарифов
по (подключение, модель), расчёт стоимости (`CostCalculation`), `compute_cost`/`money` (чистые
функции на `Decimal`), проекции `summarise` и `history`.

## Приёмка

| Критерий M2-05 | Результат (реальная SQLite) |
| --- | --- |
| Duplicate receipt ≠ новая попытка | id записи выводится из `attempt_id`: повтор квитанции, другая команда, 6 параллельных записей и «перезапуск» дают одну запись (version 1); реальный повтор вызова (другой `attempt_id`) — отдельная запись; тот же id с другой ролью/моделью/назначением/операцией/стартом — `IDEMPOTENCY_CONFLICT` |
| Missing usage/rate ≠ 0 | нет тарифа / нет usage / нет всех ставок → `unknown`, `amount=None`, `currency=None`; нет одной ставки или токенов части → `partial` (нижняя граница); реальные 0 токенов не требуют ставки; сводка считает неизвестное отдельно и ставит `complete=False` |
| Версии модели и тарифа | попытка хранит `assignment_version` и закреплённую версию тарифа; изменение цены прошлое не меняет (расчёт v1 неизменен, пересчёт без изменений не создаёт версию); поздний или ретроактивный тариф — только явным `calculate`/`repin`, предыдущая версия расчёта читается |
| cached/reasoning не удвоены | `total − подкатегория` по ставке родителя + подкатегория по своей (или родительской) ставке: 1000/400 cached, 500/100 reasoning → 4.8, наивная сумма даёт другое; в сводке подкатегории отдельно от родителей |

Дополнительно: late usage после STOP принимается (замена, не сумма; слабее известного не становится),
статус `cancelled` при этом не переписывается; цена по сообщённой модели, нет её тарифа — неизвестно, а не
цена запрошенной; валюты не складываются; work/test разделены и входят в общий итог; чужой principal не читает
журнал; путь «шлюз M2-04 → AttemptSink → журнал» с отменой и двойной доставкой квитанции.

Мутации защит (21): замена/сумма usage, конфликт двух полных отчётов, проверка идентичности, перезапись
статуса и модели, двойной счёт cached/reasoning, нулевая цена вместо неизвестной (тариф, ставка), дата
вступления тарифа, возврат даты назад, версия на идентичный тариф, повторный пересчёт, repin, смешение
валют, неучтённая неизвестная стоимость, подкатегории в родителях, экспонента в деньгах, права владельца,
сообщённая модель — каждая роняет тест (два выживших исправлены тестом/упрощением кода).

## Решения и допущения

1. Шлюз сообщает только завершённые попытки; запись `running` до вызова невозможна без хука шлюза,
   поэтому падение процесса посреди вызова оставляет попытку без записи (её неопределённость видна на
   уровне JobOwner `OUTCOME_UNKNOWN`). Запрос: хук «перед вызовом» в M2-04 + `begin_attempt` здесь.
2. Ставка cached/reasoning без отдельной цены берётся по родителю (подкатегория не дороже и не удваивается).
3. Округление денег: 10 знаков, ROUND_HALF_UP; сумма хранится строкой без экспоненты.
4. Выбор тарифа по сообщённой модели; тарифы привязаны к подключению через версию `LLMAssignment`.

## Не проверено / ограничения

- Сверка с биллингом агрегатора, курсы валют, строгий лимит бюджета и резервирование суммы (оператор/M1-06),
  оповещения 50/80/100 %, HTTP/панель.
- Сканирование записей через `repository.list` (нет запроса по периоду/роли/модели); нагрузка выше десятков
  тысяч попыток не измерялась. Нужен запрос по индексируемым полям (владелец storage).
- Несколько процессов ядра, Windows, runtime-wiring.
