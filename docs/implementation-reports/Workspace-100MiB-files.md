# Файлы до 100 МиБ и несовпадение лимитов рабочего хода

Codex, 2026-10-27. Ветка `codex/workspace-100mib-files`, база main `d7b3d16`.
**Исправление платформы в отдельной ветке, не в main; интеграция за Claude.**
Оператор явно запросил файлы хотя бы до 100 МБ и локальное тестирование.

## Причина найденного отказа

Последний рабочий ход завершился CAPABILITY_UNAVAILABLE до вызова своей модели;
отдельный предшествующий вызов activity-goal не является вызовом этого разговора.
В основании хода находился ранее загруженный JAR размером 6388537 байт, при этом
личная конфигурация сохраняла старый `max_input_bytes=262144` (256 КиБ).
ReleasedSessionContext переносит файловые основания брифа во входы runner;
runner отклоняет превышение лимита. Верхний слой теряет эту конкретику и показывает
общую ошибку. Содержимое архива и переписка для диагностики не выводились.

Подготовка настоящего OpenCode отдельно прошла с прежними 32 МиБ tmpfs, затем
с 256 МиБ, а также с MCP и прежними лимитами. Это не подтверждает, что общий код
CAPABILITY_UNAVAILABLE всегда означает размер файла: вывод относится к этому
набору оснований и воспроизводимому отказу малого лимита.

## Изменения

- HTTP-загрузка в home и HomeFiles принимают до **104857600 байт (100 МиБ)**.
  HTTP использует тот же предел, что прежняя загрузка в управляемые области;
  native клиент уже ограничивал файл 100 МиБ, его менять/пересобирать не нужно.
- Только для записи большого файла увеличено ограниченное ожидание Docker CLI:
  до 59 секунд для 100 МиБ. List/read сохраняют прежние 9 секунд. Байты идут
  stdin в network=none, не в модель, Windows-пути в контейнер не монтируются.
- Предел настраиваемого `max_input_bytes` расширен до 128 МиБ, прежнее значение
  по умолчанию сохранено. Появился `--max-input-bytes` у `enable-work-sessions`.
  Проверки прав, источников, версий, суммы входов и половины tmpfs остаются.
- На личном host штатным владельцем настроек выставлены входы 100 МиБ,
  временный диск 512 МиБ и RAM 2048 МиБ. Для 100 МиБ недостаточно менять только
  HTTP: иначе входы снова упрутся в runtime-лимит. Другие настройки и права сохранены.

Лучше загружать большие новые файлы в `workspace`: они доступны в
`/workspace/inbox/`, агент читает их по необходимости своими инструментами.
Файловые основания управляемой памяти по-прежнему проходят release и могут
стадироваться во входы: этот маршрут также проверен на 100 МиБ. Никакие старые
файлы автоматически не перемещались и не удалялись.

## Проверки

- `test_100mib_files.py` и соседний `test_home_routes.py`: **4 passed, 122,40 с**.
- Реальный HTTP владельца: ровно 100 МиБ принимается; объявленный размер на байт
  больше — 413 до записи; без CSRF — 403; host остаётся STOPPED.
- Настоящий Docker: 100 МиБ записаны в отдельный тестовый home; размер и SHA-256
  совпали при потоковом чтении. Повтор имени не перезаписывает файл.
- Настоящий runner: прежние 256 КиБ отказывают до запуска; настройка 100 МиБ
  передаёт тот же файл в inputs, процесс в network=none видит полный размер.
  Фикстура владельца/допуска синтетическая; сами Docker и передача stdin настоящие.
- Ruff чистый, strict mypy по четырём изменённым исходным модулям — без ошибок.
  Полный suite и платные вызовы не запускались.

Не проверялись: 100-МиБ файл реальными кликами браузера, обработка такого файла
живой моделью, все возможные форматы/распаковки, пропадание Docker посреди загрузки.
Изменение не даёт права исполнять содержимое загруженного файла.

## Локальный кандидат и откат

Подготовлена собственная locked `.venv` кандидата, повторно использована проверенная
панель и native UI 1–18. Образы не пересобирались: изменения формирует host.
Сервер перед переключением остановлен через штатный STOP, подтверждено отсутствие
неподтверждённых ресурсов. Прежний launcher сохранён в ignored rollback-каталоге.
Новые Permission и автоматический START не выдавались.

После обновления страницы оператору нужно нажать START и заново отправить
неуспешное поручение. Само оно не повторялось и не оплачивалось повторно.

Перед откатом к версии, которая допускает входы только до 16 МиБ, сначала новым
интерпретатором выполнить offline `enable-work-sessions --max-input-bytes 16777216`
с прежними обязательными image/area/output-area. Затем вернуть сохранённый launcher.
Простая подмена launcher при host.json с 100 МиБ несовместима со старой валидацией.
