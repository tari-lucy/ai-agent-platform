## Что можно включить в согласованный список удаления

1. **106 остановленных тестовых контейнеров платформы.** Имена вида
   `ai-platform-m0-*`, `ai-platform-m1-*`, `ai-platform-integration-*`,
   `ai-platform-access-*`; это прежние инфраструктурные пробы. Сначала сверить
   по manifest точные ID, убедиться в неизменившемся состоянии. Удаление только
   контейнера не должно сопровождаться автоматическим удалением его volumes.
2. **13 пустых сетей тестов M0-04/M1-04.** Группы
   `ai-platform-m0-04-*_platform`, `ai-platform-m0-04-*_core-loopback`,
   `ai-platform-m1-04-*-network`. По inspect в них 0 подключённых контейнеров.
   Перед удалением повторить inspect: имя само по себе не доказывает пустоту.
3. **41 volume тестов M0-03/04/05 и M1-02/03/04.** Кандидаты определены по имени
   и по отсутствию связей с контейнерами вне пункта 1. В них могут оставаться
   тестовые SQLite/Redis/индексы; байты не открывались. Их удаление отдельное,
   после решения, нужны ли сохранённые результаты этих проб.
4. **Исторические образы платформы**, после исключения рабочих и откатных
   зависимостей. Условные теги: `workspace-v2-windows`, `opencode-helpers-launcher`,
   `opencode-skills-r1`, `opencode-helpers-r1`, `opencode-workspace-r1`,
   `opencode-1.19.3-r1`, `aw08-opencode-1.19.3-synthetic`, `panel:m4-01-check`,
   `core:m1-03-offline-proof`, M0-04/06 core/worker/deps и `m0-02-check`.
   Теги `harness-base-*` могут указывать на те же ID: считать их отдельно
   освобождаемыми образами нельзя. Некоторые ещё используются контейнерами
   пункта 1 — порядок удаления важен. Без сверки launcher/откатов не удалять.
5. **Неиспользуемый build cache** — наиболее заметный резерв, но решение должно
   отдельно касаться кэша сборки. Его восстановление потребует повторных сборок
   и, возможно, загрузок. Ничего из build cache сейчас не менялось.

## Что сохранить

- Все 7 запущенных контейнеров других проектов: они не относятся к этой уборке.
  Их имена и volumes в публичный отчёт не переносятся.
- Все `aw-home-*`: в них бывают дом, кэши, сессии и инструменты персонажа.
  «Не привязан к контейнеру» не означает «пустой» или «ненужный».
- Volumes других проектов и анонимные volumes без установленного назначения.
  Число 19 unreferenced не является списком разрешённых к удалению.
- Закреплённые известные рабочие образы `253e46306ddb…` (руки) и
  `1ecf31a0d693…` (harness); активные/откатные зависимости следует уточнить при
  фактической уборке. Папки личного host, backup, ledger и agent-files не трогать.
- `start-diag.ps1`, `stop-diag.ps1`, `deploy3.ps1`, `deploy4.ps1` и рабочий updater
  до подтверждённого перехода на единый сценарий обновления. SSH-туннель тоже
  не часть уборки.

`jobs.py`, `permits.py`, `perms.py`, `perms2.py`, `timing.py`, `timing2.py`,
`turn.py`, `readlog.ps1`, `firstfault.ps1`, `stoplog.ps1`,

`cfg.ps1`, `cfg2.ps1`, `limits.ps1`, `limits2.ps1`, `deploy2.ps1`,
`deploy_l4.ps1`, `update.ps1`, `run.py`.

Это классификация по имени/дате и прежнему назначению, **не доказательство,
что ни один сценарий их больше не использует**. Содержимое не открывалось.
Даже удаление всех этих скриптов освободит лишь десятки килобайт.
Логи также малы; лучше сохранить текущий и диагностически важные до завершения
приёмки. Не путать их с размером Docker и checkout/node_modules.

## Оценки места Docker

`docker system df` на весь движок:

- images: 64,8 GB, reclaimable 30,37 GB;
- writable layers контейнеров: 1,862 GB, reclaimable 1,057 GB;
- volumes: 1,434 GB, reclaimable 581,7 MB;
- build cache: 35,86 GB, reclaimable 19,22 GB.

Это оценки Docker для **всех проектов**, не сумма только предложенных кандидатов
и не гарантия освобождения такого объёма на диске Windows. Общие слои образов
и кэш пересекаются; складывать размеры тегов и обещать точный итог нельзя.
Наибольший практический смысл — согласованная уборка старых образов/кэша,
а не удаление небольших скриптов или личной памяти.
