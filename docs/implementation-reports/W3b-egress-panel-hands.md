# W3b: журнал трафика в панели, суточный лимит, SOCKS5, образ «руки»

Claude Code, 2026-10-26. План: [doc31 §4, §7](../31-agent-workspace-v2.md), продолжение
[W3](W3-egress-gateway.md). Ветка `claude/w3b-egress-panel` от main `6e80a85`.
Инструкция оператора: [agent-workspace.md](../agent-workspace.md#образ-руки-w3b).

## Что сделано

- **Суточный лимит трафика на личность.** `--egress-daily-mb` (по умолчанию 2048,
  `0` — выключен). При открытии шлюза хост считает объём личности за текущие сутки UTC
  по локальному журналу и передаёт прокси остаток, если он меньше лимита хода; исчерпан —
  прокси отвечает 403 `EGRESS_DAILY_LIMIT`. Текст среды объясняет агенту: до следующих
  суток или обращение. Для долгоживущего контейнера (W5) остаток считается при открытии
  его шлюза — суточная граница внутри его жизни не пересчитывается.
- **Журнал в панели.** Контракт `EgressLog`/`EgressRequest`, `GET /api/v1/egress-log/{day}`
  (оператор, своя личность). Панель → **Работа** → **Интернет**: итог за сутки (запросы,
  отказы, объём, лимиты) и последние 200 запросов, листание дней до 30 назад. Читается
  только по нажатию; данные не покидают хост. Повреждённые/чужие строки не показываются.
- **SOCKS5** на том же порту шлюза (первый байт 0x05): без аутентификации, только CONNECT
  (BIND/UDP — отказ 7), та же политика адресов, портов, лимитов и журнал (`method: SOCKS`).
  В контейнере `AI_WORKPLACE_SOCKS=socks5h://…`.
- **Образ «руки»** (`deploy/opencode/Dockerfile.hands`, `scripts/build_hands_image.py`)
  поверх проверенного harness-образа: git, curl/wget, jq, zip, ssh-клиент, dig/nc, ffmpeg,
  ImageMagick, Java 17 JRE, Node.js/npm, Chromium, Python Playwright 1.63.0 (без скачивания
  браузера). Скрипт проверяет сохранность базовых слоёв, меток и пользователя. Списки
  пакетов в образе: `/opt/agent-harness/hands-packages.txt`, `hands-python.txt`. Размер
  ~2,9 ГБ (Linux).
- **`/guide/tools.md`** каждый ход: что есть в образе (или «только Python и OpenCode»);
  добавлен в инструкции OpenCode (`worker.py`, нужен refresh образа).
- `Dockerfile.harness-refresh` идемпотентен (`install -d`): refresh можно применять поверх
  образа, где `/workspace` уже есть, в том числе поверх «рук».
- Попутно: панель принимала в разговоре только `operator`/`character` — сообщения-будильники
  W7 (`wake`) ломали просмотр дневника; теперь показываются как «⏰ Будильник агента».

## Проверки (Linux VPS, Docker 29, живой интернет)

- ruff, mypy, import boundaries — чисто; панель: tsc, eslint, node-тесты (17 в затронутых файлах).
- Без Docker: прокси называет суточный лимит; SOCKS5 — отказ loopback по имени, почтового
  порта, BIND, только-пароль, успешный CONNECT и журнал; подсчёт за сутки по личности,
  остаток, представление журнала (200 новых, чужие и битые строки отброшены, неверный день);
  маршрут через операторскую поверхность (`test_egress_budget.py`).
- **Настоящий Docker:** `test_egress_docker.py` — SOCKS5 до example.com через шлюз;
  `test_hands_docker.py` — в обычной изоляции (read-only, uid 65532, cap-drop ALL, внутренняя
  сеть, nofile 128) работают git/java/node/ffmpeg, Chromium через Playwright открывает
  https://example.com через шлюз; `test_home_docker.py` — `tools.md`.
- **Настоящий OpenCode** (`test_real_home.py`, синтетическая модель) на образе «руки» после
  refresh — проходит.
- Полный gate (`scripts/check_combined.py`, Linux): 1592 passed, 56 skipped, 1 failed —
  `test_import_has_no_effects`, известный сбой окружения VPS.

Не проверено: Windows/Docker Desktop (сборка образа с сетью, размер на WSL2), Edge,
живая модель (пользуется ли она браузером по `tools.md`).

## Не входит

- Root внутри контейнера (`apt install` агентом) — изоляция прежняя: non-root, корень
  только для чтения; пакеты — в `/workspace`.
- Суточный бюджет CPU-часов; суточный бюджет модели — существующий бюджет активности.
- Экспорт/очистка журнала из панели.
