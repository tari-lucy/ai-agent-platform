## Приёмка

| Критерий M2-03 | Результат (реальная SQLite) |
| --- | --- |
| Раздельные platform IDs | ник, тот же account_id на другой площадке/сервере, другой аккаунт с тем же ником — разные люди; аноним без identity; гипотеза не идентифицирует; подтверждение чужого аккаунта отклонено, отклонённая связь освобождает аккаунт; персона и work/test изолированы |
| Резервы вопросов | при гонке 6 задач резерв получает ровно одна; переформулировка = та же тема; известный ответ/ожидание/cooldown/закрытие/«не обращайся» блокируют без записи; блокированный черновик не считается заданным; unknown удерживает тему; голос+чат одной реплики — один эффект; истёкший резерв освобождается |
| Повторная встреча | после «перезапуска» (новый сервис над той же БД) тот же аккаунт даёт того же человека, `first_meeting=False`, счётчик встреч, отношение, открытые темы, ответы, обязательства; повтор того же события не умножает встречу |
| Точные обязательства без top-k | обещание только по DELIVERED той же реплики; 230 обещаний (> страницы 200) возвращаются полностью и в порядке срока; без recall/embeddings; срок 30 дней исходного текста не закрывает и не стирает обещание |
| Сбой сохранения | исключение при записи — обещания нет, успех не сообщается |

Мутации защит (DELIVERED/utterance, резерв, cooldown, «не обращайся», пагинация, идемпотентность
change_id, слияние при подтверждении, confirmed-only идентичность) каждая ломает тест; две защиты
подтверждённой идентичности дублируют друг друга, поэтому ловятся только вместе.

## Решения и допущения

1. Person ID якорный: детерминирован от первой пары (платформа, аккаунт) в области; вторичные
   подтверждённые аккаунты добавляются в `Person.accounts`. Слияние двух людей не реализовано
   (отказ с `INVALID_ARGUMENTS`) — это отдельная операция с пересмотром зависимых записей.
2. «Не обращайся»/«без инициативы» хранится как пожелание человека в аспектах отношения, не как чувство.
3. Cooldown после доставленного вопроса хранится в теме; ожидающая тема повторно открывается только
   явным `reopen_topic` (новый контекст/политика напоминаний), cooldown при этом сохраняется.
4. Бюджет инициативы (30 с / 2 за 5 мин / 10 мин тишины, doc22) — контроллер поведения M2-06, не здесь.

## Не проверено / ограничения

- Runtime-интеграция, HTTP/панель, Docker/Windows, несколько процессов (кэш аккаунтов/встреч валиден для
  одного процесса ядра), нагрузка выше сотен людей.
- Смысловая проверка «тот же вопрос иначе» (эмбеддинги) — только структурированный ключ.
- Экстракция тем/обещаний из текста (M3-01), лимиты скорости изменения отношений (M3-03).

## Запросы координатору (shared changes, не обходились)

1. **Storage**: repository не умеет искать по семантическому ключу или полю (аккаунт→человек, человек→встречи,
   тема→вопрос). Сейчас — сканирование с кэшем. Нужен запрос по зарегистрированным ключам или индексируемым
   полям (владелец M1-02 / следующая ревизия 0003).
2. **Слияние людей** (подтверждённое объединение/разделение аккаунтов): отдельное назначение — переоценка
   встреч, отношений, тем и обещаний, история исправления.
3. **Composition**: `register_social_extensions`, grants social-владельцу (SOCIAL, MEMORY read, CHANNEL read) и
   `RecordAccess` для social на Source (MemoryService.reader_access) и Delivery (запись канала).
