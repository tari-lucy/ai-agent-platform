## Результат

- **Выдача истории тикетов** (`tickets/release.py`, `TicketRelease`). Текст тикета (title,
  summary, attempted, decision_needed, resolution, constraints запроса) и сообщения агента/
  служб выдаются только пока **каждое** основание выпускаемо для цели: источник у владельца
  памяти доступен, той же версии, разрешён для `private`/`api_transfer`/`public_disclosure`,
  не заблокирован в deletion ledger; материалы проходят guard файлового владельца
  (`FileReleaseGuard.check`, логика не копируется). Текст не делится по основаниям, поэтому
  одно закрытое основание скрывает весь производный текст (безопасный первый вариант).
  Слова оператора, id, kind, state, turn и сами refs остаются: тикет виден и его можно
  закрыть. Хранимая запись не меняется; physical purge — владелец retention.
- **Провенанс не теряется.** `_merge` больше не оставляет последние 50 ссылок
  `sources`/`materials`: при переполнении обновление отклоняется `RESOURCE_BUSY`, все
  прежние основания сохраняются. (Схема контракта не менялась — exports у writer R1.)
- **Порт контекста сессии** (`agent_experience/session.py`): `SessionContextPort` /
  `WorkContext`. `build(scope, query, ticket_ids)` — бриф личности (AW-06) + выпущенная
  история тикетов, с точными `refs` (SourceRef/ArtifactRef) того, что показано;
  `still_valid(scope, refs)` перепроверяет их для checkpoint/resume — при закрытом
  основании контекст пересобирается, задача остаётся. Ничего не хранит (нет скрытой
  памяти harness). Фабрики `ticket_release(rt)`, `session_context(rt)` в
  `m3_composition/workplace_experience.py`: ledger — из `HostMaintenance`, файлы — guard
  `rt.workplace`; без files тикет с материалами не выпускается.
- **Обёртка чтений панели** (`m3_composition/ticket_reads.py`, `ReleasedReader`): `tickets`/
  `ticket-messages` (страница и одна запись) — через `TicketRelease` для `api_transfer`, одно
  решение на тикет страницы; остальные ресурсы без изменений. Storage уже сам не отдаёт запись,
  чьё основание утратило `api_transfer` или истекло; обёртка закрывает то, чего storage не
  видит: блок в deletion ledger (restore старой копии), смену версии основания и материалы.
- **Исправлено в host rights:** `record_readers()` включает `TICKETS` (только чтение);
  раньше тикет на настоящем хосте не мог сослаться ни на один источник памяти.
