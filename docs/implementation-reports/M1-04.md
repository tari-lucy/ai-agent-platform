## Изменение

Добавлены core JobOwner/OutboxDispatcher и порты jobs, SQLite scheduling/
attempt/reconciliation adapter, bounded Redis Streams adapter, acceptance
fixtures/runner. Job, revision, attempt metadata, receipt и outbox сохраняются
в принятом SQLite UoW одной транзакцией. Worker не пишет DB.

Supervisor.refresh принят отдельно (8e16ff8) до jobs consumer: проверяет
текущее readiness, продлевает только живой admission, сохраняет cancellation
ID/Event; STOP/пауза/expiry не оживают. Старый Admission snapshot заменяется;
потребитель resolve использует исходный cancellation_id.

Единственная новая миграция 0003 после 0002: job_schedules, job_attempts,
job_reconciliations. Контракты Job/Lease/Result остаются прежними; дополнительные
scheduling/технические сведения отделены от авторитетных contract revisions.
Назначение shared migration/HEAD и single-head assertion отражено координатором
в doc24 (dc6b045/c5c755f). Существующие contract schemas/Compose/locks/M2 files не менялись.

## Поведение

Задание допускается только по сохранённой Behavior ExecutionCommand и обязательной
доверенной Policy. Проверяются scope/full run, epoch, исходный cancellation ID,
worker scope/capability/session expiry, deadline и fencing текущей попытки.
Claim.acquired=False сообщает о уже выданной аренде и не разрешает повторное
вычисление; потерянный ответ не создаёт новую попытку. Изменённый body с прежним
request ID отклоняется. Перед executor I/O необходим verify.

Default: 256 pending workspace, batch 50 (cursor), 2 попытки, lease 20 с,
heartbeat 5 с, total 180 с; задержки с bounded jitter. Переполнение потока
отказывает в отправке, без trimming pending; Redis noeviction и AOF используются
в пробе. Диспетчер переиздаёт текущий queued/waiting Job из DB после потери
брокера/подтверждения. В очереди только references, без prompt/аргументов.

XACK возможен после durable result/terminal state, не после получения сообщения.
Поздний результат после STOP сохраняется только как технический факт; Job закрыт,
admission недействителен. Финальное применение/публичный output принадлежит
следующему владельцу с повторной проверкой admission/rights/sources/lease.
accept не выполняет callback/инструмент. DB commit и внешний эффект не объявлены
одной транзакцией или exactly-once доставкой.

Reclaim не доказывает смерть worker. Старые attempts fenced, ресурсы остаются
неподтверждёнными до реального cancel receipt. Неизвестный внешний исход не
повторяется автоматически и занимает квоту. settle_unknown добавляет отдельную
metadata-only квитанцию, сохраняет первоначальную unknown history, закрывает
неопределённость без resume. Старый ресурс можно подтвердить отдельно после
новой попытки; новая попытка при этом не отменяется. Restore/restart автоматически
не исполняет старые queued/running jobs.

## Критерии приёмки

| Критерий M1-04 | Проверка / результат |
| --- | --- |
| Crash до/после commit | Реальная SQLite transaction rollback/commit с инъекцией сбоя; нет второй записи Job/Result |
| Commit результата до ACK | Durable result replay; настоящий PEL reclaim не запускает вторую попытку, последующий XACK очищает pending |
| Broker loss | Реальный Redis delivery loss + переиздание из SQLite; publish с потерянным ответом сохраняет один operation/event ID |
| Restart/AOF | Настоящий Redis process restart и reconnect, streams/groups сохраняются |
| Reclaim/lease | Истёкшая короткая lease, безопасная повторная попытка №2; поздний worker fenced, expiry не ACK ресурса |
| Duplicate | Command/result/renew replay, конфликт изменённого body; отдельный acquired flag |
| Bounded retries | Две попытки максимум, WAITING с сроком/причиной; unsafe/unknown без автоматического retry |
| STOP/отказы | Настоящий SQLite BEGIN IMMEDIATE write lock, полный/CLIENT PAUSE Redis; direct revocation <250 мс в этих probes |
| Длительное задание | 24 heartbeat ×4 с =96 с; один attempt/cancellation ID, readiness обновляется |
| Recovery/unknown | Restart без autorun, отдельная сверка/исходная unknown history, unknown удерживает квоту |
| Области и пределы | Worker grant/scope/capability expiry, quota/backpressure, cursor до хвоста очереди; worker DB access отклонён |

## Что не проверено / ограничения

- Readiness/Policy и executor — синтетические. Реальные Permission/conditions/
  exact moderation/binding checks должны быть подключены владельцами через
  обязательный Policy port; UnavailablePolicy закрывает исполнение. Нет live
  LLM/API, публикаций, игры, загрузки моделей или чтения локальной .env.
- HTTP/service authentication — M1-05; циклы scheduler/priority/resource budgets/
  telemetry — M1-06. Bootstrap остаётся STOPPED, handlers ещё не подключены.
  Исполнитель обязан учитывать acquired flag, дедуп attempt ID, verify/lease
  перед I/O и фактический cancel receipt. Новая запись результата не является
  разрешением автоматически проиграть payload.
- Crash worker/core проверен инъекцией на transaction boundary и новым owner,
  не OS kill. Redis restart настоящий. Это не проверка Windows sleep/всего Docker
  runtime hang, дискового ENOSPC или производительности публичного провайдера.
- Стандартная cold Docker build не повторялась: уже зафиксирован отсутствующий
  offline metadata cache. Locks/dependencies/Compose не изменялись; Linux source
  проверен в принятом immutable image. Installed wheel/full authenticated runtime
  wiring остаются интеграционной пробой после M1-05/06.
- Lifetime cleanup технических journals/terminal outbox — M5-01; scheduler quotas/
  ресурсные полосы — M1-06. Pending memory/stream bounded уже сейчас. Самовольное
  удаление unknown receipts/живых volumes не используется.
