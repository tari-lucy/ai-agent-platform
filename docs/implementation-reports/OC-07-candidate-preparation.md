## Проверки и найденная проблема среды

Первый offline sync по запросу Python 3.14 обнаружил устаревший managed alias:
ссылка указывала на отсутствующий executable. Повтор с точным
`sys._base_executable` уже работающего Python 3.14.8 успешен. Глобальный alias и
старое окружение не менялись, Python не скачивался.

`uv pip check --python <candidate-python>`: все 44 пакета совместимы.
CLI `serve --help` работает через Python кандидата с `-I`, сервер не запускался.

Preflight кандидата: **LAUNCHER_OK, PYTHON_OK, ENV_FILE_OK, PANEL_OK, RUNNER_OK**;
только **OPENCODE_UI_NOT_CONFIGURED**, ожидаемый exit 78. Проверка `.env` —
существование файла; содержимое не читалось. Никакой подмены PYTHONPATH при
проверке launcher, импорт указывает на собственный checkout кандидата.

Работающий личный deployment остаётся на `f166eab`, оба checkout чистые.
Личная БД не открывалась, память/Permission/конфигурация host не менялись.
Контейнеры, сервер и платные вызовы не запускались. Полные тесты панели не
повторялись после приёмки PUI: выполнена необходимая локальная сборка/typecheck.
