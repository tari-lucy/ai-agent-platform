# Windows: короткая передача доверенного entry в Docker

2026-10-27. База `6173f4e`. Платформенная правка изолирована в
`codex/windows-short-entry-fix`, не предназначена для самостоятельного merge
Codex в main: интегрирует Claude после своего gate.

## Причина

W3b/W7b увеличили WARM_ENTRY до 33277 символов. В Windows аргумент после
`subprocess.list2cmdline` занимает уже 34531 символ, ещё без большинства
Docker-флагов. CreateProcessW отказывает WinError 206 до создания docker.exe.
Cold Python/Chromium работает, а настоящий прогретый/resident OpenCode не
запускается. Это воспроизведено на обычном real-home тесте и попытке soak.

## Минимальная правка

`create_args` упаковывает только доверенный entry длиннее 4096 символов:
UTF-8 → zlib → base64 → короткий Python loader. Loader компилирует и выполняет
исходный код в том же процессе. Новый аргумент — около 10421 символа.
Команды/байты модели не меняются; mounts, env, user, лимиты, gateway и STOP прежние.
Host-файлы, shell или новый сетевой путь не добавляются, образ пересобирать не нужно.

## Проверки

- Unit policy: 9 passed, включая точное восстановление Unicode и неизменные
  аргументы изоляции при размере Windows-команды меньше 16000 символов.
- Ruff чистый; mypy — 318 файлов без ошибок.
- Независимый узкий read-only review policy/test: блокеров не найдено.
- Реальный Windows/Docker-прогон выполняется на приёмочной ветке; результат
  фиксируется в её отчёте W3b/W7b, а не выводится из unit-проверки.

## Дополнительное наблюдение

При исходном WinError 206 conservative-флаг `_create_unknown` переводит
очистку warm в OUTCOME_UNKNOWN. Прокси уже мог быть создан до ошибки,
поэтому после неудачного теста остаётся его внутренняя сеть. Приёмка удалила
только свою точно идентифицированную пару proxy/network. Эта правка устраняет
причину текущего отказа, но не меняет общий протокол сверки unknown-ресурсов.
