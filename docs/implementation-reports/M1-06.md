## Реализация и границы

- application/telemetry: finite metadata-only health/trace/latest projections,
  scope/run/work-test isolation, opaque hashed correlation, bounded subscriptions,
  coalescing и отключение медленного клиента.
- application/scheduling: один синхронный core budget owner; configurable pools,
  trusted Capability/version registry, bounded pending/active/history,
  priority moderation → foreground → background и reserved moderation capacity.
- Bootstrap: закрытая композиция telemetry/scheduler и poll timer50ms.
  RAM/pending берутся из существующей проверенной конфигурации; capabilities
  не регистрируются автоматически, runtime остаётся STOPPED.
- Общий runner включает tests/operations. Contracts/export, migrations/head0003,
  manifests/locks, Compose и M2 source не изменялись.

Defaults: LLM4 с резервом1, CPU2000 milliCPU с резервом200, RAM1536 MiB с резервом128;
отдельные background/embedding/foreground pools по1. Заявленные costs проверяются
по лимитам, обычная lane не занимает резерв. Это планирование бюджета по спецификации,
не измеритель RSS или доказательство общего расхода WSL.

Scheduler проверяет исходный cancellation_id/run/epoch/profile/policy version и
текущую capability version перед grant/verify. Budget — не tool permission:
обязательны JobOwner/Policy checks и повторная проверка после await перед эффектом.
Для job используется настоящий attempt_id; duplicate Allocation.acquired=False —
status query, не разрешение вычислять снова. Retry нового attempt возможен после
подтверждённого завершения старого; UNKNOWN/живая попытка блокируют новый budget.

STOP/expiry/health loss закрывают permit, но не освобождают ресурс без actual receipt.
Через bounded cancel grace — UNKNOWN; восстановление health не оживляет permit.
Поздняя factual reconciliation освобождает exact ticket и уточняет техническую
историю, не resume и не применение результата. Restart требует нового STOPPED
supervisor/recover/reconcile; новую копию budget owner при ACTIVE создать нельзя.

## Потребители и непроверенное

Порты и порядок вызовов — README модулей scheduling/telemetry.
M2-04 может использовать принятые scheduler/trace ports; M1-06 dependency закрыта
после интеграции. Не добавлять вложенные provider retries поверх JobOwner attempts.
M1-05 остаётся следующей задачей: sessions/CSRF/Origin/service identity и безопасный
сетевой доступ к внутренним ports. Subscription/BudgetLease сами не credentials.

Не проверены live provider/модератор, real worker/OS crash, реальный VPS venv,
authenticated полный runtime, actual RSS/mixed load и новая installed wheel/cold build.
Source-mounted Linux container не означает испытание конкретного VPS.
Обычная проверка там: python scripts/check_combined.py в venv по принятому lock.

Health внешнего сервиса должен сообщать его доверенный владелец; local control/
resource_scheduler READY не выдаётся за readiness Redis/LLM/памяти.
Durable truth/restore — M1-04/M5, финальный public output — свой moderation gate.
