# Исправление подстановки старого ответа в новом разговоре

2026-10-24, Codex. Оператор в новом разговоре увидела служебный JSON и текст
прежней сессии. Диагностика существующего host выводила только даты, счётчики
и признаки JSON, без текста разговоров/ключей/endpoint.

У нового разговора было одно сообщение оператора и готовый acknowledgeable
ответ обычным текстом; показанный оператором служебный JSON не совпадал с этим
ответом. В прежних сессиях были сохранены старые ответы в JSON-формате.
Промпты, память и данные не менялись: причина обнаружена в native-проекции.

## Причина и правка

Native `server-session` хранит части в общем для directory `part[messageID]`.
Адаптер выдавал `msg-1`, `reply-1` и т.п. для каждого разговора. Даже с разными
session_id номера повторялись и могли подставить старые части. Это объясняет
наблюдение, не доказывая отдельную ошибку/скорость настоящей модели.

Патч 11 добавляет session_id к стабильным message ID (operator, character,
platform notice). Оптимистические клиентские UUID сохранены, повтор от draft
к доставленной записи сохраняет один scoped ID. Receipt сопоставляет этот же
ID, session, directory, полный текст и ревизию, затем перепроверяет владельца.
Правила ACK и авторизация не ослаблены. Записи/ссылки/история БД не переписывались,
JSON не превращался в действие и не скрывался обрезкой поля summary.

## Проверки

Новая Bun-регрессия: два разговора одной личности с одинаковыми sequence имеют
непересекающиеся message ID. До правки — **1 failed** (пересечение найдено),
после — **3 passed** вместе с точным ACK и single-message GET. Строки фикстур
синтетические, платных вызовов нет.

Полная серия 1–11 совпала по дереву с исходником поверх pinned v1.19.3;
Vite build и prepare/load успешны: **938 файлов / 34 352 265 байт** без manifest.
Затронутый native Edge journey ответа/точного ACK/reload/STOP — **1 passed,
46.43 с**, production owners временного host, synthetic harness/HTTP-модель.
Платных вызовов нет. Полный suite/Docker journey и Linux typecheck
заново не запускаются; runtime-порты и типы fetch не менялись.

Для обновления агент штатно остановлен. Личный host не очищается; используется
сохранённая backup/rollback-подготовка. После замены bundle и restart проверяется
STOPPED и чистый вход. Дальнейший START остаётся действием оператора.
