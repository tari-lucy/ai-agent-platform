| Критерий M3-02 | Результат (реальная SQLite) |
| --- | --- |
| Нет своего голоса | нет канала/Utterance/Delivery API; персонаж получает `CharacterOffer` без направления и замысла линии; предложение — только ситуация (схема модели не содержит исхода) |
| Нет forced outcomes | `choice/actual_outcome` пусты до `resolve`; `resolve` только из ACCEPTED/REALIZING и только с независимым первичным источником (реплики, сводки, рефлексия, модель — отказ); эпизод создаётся один раз и только тогда; повтор `resolve` отклонён |
| Cooldown / границы / отказы | cooldown 15 мин (÷ интенсивность), ≤3 за 2 ч, ≤2 линий, ≤1 неразрешённое; 2 отказа семейства → отдых до следующей сессии; повтор без нового основания и паузы 1 ч запрещён; hard/soft/неуверенность/сбой классификатора закрывают предложение (запись `BLOCKED`, cooldown не тратится), линия с неуверенным замыслом — `paused` |

| Пауза / STOP | пауза отменяет ожидающие, сохраняет линии и принятое; STOP и простой ничего не создают; accept при остановке/паузе отказан |

## Решения и допущения

1. Сессия = `scope.session_id`; отдых семейства считается по отклонённым предложениям этой сессии. Окно и cooldown
   считаются по часам (persisted `created_at`/`cooldown_until`), поэтому переживают перезапуск; «активные минуты»
   приближены часами владельца при допуске.
2. Семейство и тема закодированы в читаемом id `opp.<family>.<hash>.<n>` (в контракте нет таких полей).
3. Причина блокировки хранится в `boundaries` как `[BLOCKED <код>]` (нет отдельного поля).
4. Просроченные записи storage скрывает даже от владельца, поэтому переход в EXPIRED возможен лишь пока запись видна
   (при отстающих часах или при попытке принять); после TTL предложение просто исчезает.
5. Запись scope у обновляемой линии/предложения следует за сессией действия (иначе storage отклоняет запись).
