# Doc33, этапы 1–3: Windows-приёмка

Дата: 2026-10-29. Проверяемая ветка `claude/personal-diagnostics`, checkout
deployment уже на `2f2ea20` (проекция/панель предупреждений памяти включена в код).
Отчёт подготовлен в `codex/harness-windows-acceptance` от той же базы.

**Статус: preflight; живая приёмка не выполнена.** Поручение явно оставило
условие «после STOP оператора и “обновляй”». В текущем поручении команда
«обновляй» не поступила. Общая автономность работы не заменяет это отдельное
условие. Нового вопроса оператору не отправлялось; независимые Soniox и опись
выполнены. Этот отчёт не выдаёт ожидание или прежние тесты за живую приёмку.

## Реально проверено без вмешательства

- Текущий deployment checkout на указанной ветке/коммите. Это сверка файлов на
  диске, не доказательство версии всех модулей уже запущенного процесса.
- Последняя RunSession в SQLite: `STOPPED`, `unconfirmed_resource_ids=[]`.
  Чтение URI `mode=ro`, только state/epoch/времена/количество ресурсов;
  сообщения, цели, профили и полный payload не читались.
- Панель слушает `127.0.0.1:8765`; listener 4096 сейчас отсутствует.
- Docker Desktop доступен. Контейнеров native-харнеса и шлюза агента сейчас нет.
  Семь работающих контейнеров относятся к другим проектам; они не менялись.
- Код `harness-status` в этой базе получает пометки от LearningPart и отдаёт
  проекцию. Это чтение кода, **не проверка жёлтой карточки в браузере**.
- Составлена отдельная read-only
  [опись ресурсов](Windows-cleanup-inventory.md). Она не удаляет и не разрешает
  удаление старых Docker-ресурсов.

Личный сервер, host-конфиг, launcher, контейнеры, файлы агента и память не
менялись. START/STOP не нажимались. `.env` не открывался, платных запросов нет.
Разрешённый предел 3000 ₽ не расходовался этой приёмкой.

## Критерии и что выполнить после разрешённого включения

| Критерий | Статус сейчас | Короткая проверка |
| --- | --- | --- |
| Работа 30+ минут с модом | Не проверено | Сохранить время START и начала нативного хода, наблюдать 30+ минут; сверить завершение/ошибки и стоимость, не подменять ожидание успешной работой |
| STOP первым нажатием | Не проверено | Измерить monotonic время от команды до исчезновения harness/gateway/egress; отдельно проверить Run STOPPED, неизвестные ресурсы и отсутствие позднего результата |
| Файл из inbox на C: виден | Не проверено | Положить отдельный безвредный marker в inbox, попросить прочитать точный marker, сверить; чужие файлы не удалять |
| Сборка bind против Docker volume | Не проверено | Один и тот же синтетический проект и образ, одинаковые лимиты, несколько запусков; отделить cold/warm и создание контейнера от сборки; не использовать личный проект как эталон без копии |
| Разговор → память, без дублей | Не проверено вживую | Новый вымышленный факт в отдельном разговоре, видимость Source в панели; повторный сбор даёт те же ID/число записей |
| wake_me, STOP, START без повторения | Не проверено вживую | Один новый таймер, получить сообщение; STOP/START; сверить native message ID и единственную резервацию/отправку |
| Удаление источника → жёлтая пометка | Не проверено вживую | Создать специально тестовый Source, удалить только его через владельца/панель, увидеть предупреждение для точной сессии; начать новую без закрытого основания |

Известные целевые синтетические проверки этапа 3 — в
[отчёте реализации](Harness-stage3.md). Они не закрывают таблицу выше.
Проверка Soniox на поддельном сервере тоже не является живой проверкой doc33.

## Найденное и границы

Кода платформы в этом пакете не исправлялось. Новых дефектов doc33 живым
сценарием не установлено: он ещё не запускался. Данные о прежних сбоях аренды
старого пути не переносятся на новую схему как её доказанные неисправности.

До полноценной сдачи нужен согласованный момент начала живого сценария и его
наблюдение. При дефекте — конкретный код, технические времена, точная версия и
обезличенный отчёт для Claude, без самостоятельной починки платформы. Нельзя
ставить accepted по отсутствию контейнеров, удачному START или одному ответу.
