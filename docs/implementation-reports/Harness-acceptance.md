## Найденное исправление

Первая попытка открыть сессию сразу после ready=true дала RemoteProtocolError
до вызова модели: адрес контейнера уже был, HTTP OpenCode ещё не слушал.
Явное ожидание health в приёмочном клиенте позволило начать длинный ход.

Исправление — `90bbb87`, ветка `codex/harness-ready-health`: ready только
после аутентифицированного /global/health, ограничение wall-time,
STOP/epoch guard до и после запроса. Пять быстрых тестов, Ruff и strict mypy
изменённого модуля чистые, независимый review без оставшихся блокеров.
[Подробности](Harness-http-readiness.md). Исправление выложено после длинного хода: restart остался STOPPED,
после START ready наступил через 8,645 с, первый native-запрос немедленно
получил HTTP 200 / healthy=true. Затем проверен STOP во время инструмента.
Длинный ход выполнялся на 3df61e4; повторять его на правке только startup
не стали. Образ и native UI не пересобирались, изменился только host.

## Сборка и границы результатов

Один pinned-образ, CPU=1, RAM=512 МиБ, без сети, read-only root, cap-drop ALL.
UID 0 — только инициализация/сборка синтетического benchmark, права агента
не менялись. Подготовка файлов исключена из времени compileall; запуск
контейнера измерялся отдельно. Forced-повторы не равны чистой cold-сборке.

В дополнительной серии на bind-каталоге runtime медиана была 41,456 с,
с bytecode-cache в /work tmpfs — 12,321 с. Это отдельная серия, а не замер
ускорения непосредственно в projects. Рекомендация: временный кэш/сборку
вести в доступном /work, результаты сохранять в projects. Хранение личных
проектов не переносилось. Числа относятся к множеству мелких Python-файлов.

Паузы длинного хода проверяют устойчивость инструмента; это не 32 минуты
полезного анализа. JAR не запускался, подключения к игре нет. Не проверяются
все выводы модели, Minecraft-протокол, сон/перезагрузка во время работы,
публичная речь и весь MVP. Полный gate не повторялся.

.env вручную не открывался; его читает штатный live serve. В Git нет ключей,
endpoint, паролей, профиля, переписки, БД и raw-логов. Вызовов харнеса за приёмку: 24;
расчётный расход 2.18 ₽, дневной итог
104.79 ₽ при пределе 3000 ₽. Это расчёт по тарифам платформы,
без сверки с кабинетом провайдера; отдельная стоимость оборванного STOP
запроса у провайдера не подтверждена. Soniox-платных вызовов не было.
