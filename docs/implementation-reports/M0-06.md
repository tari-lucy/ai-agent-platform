## Изменения

Один config adapter в packages/adapters/src/ai_agent_adapters/configuration.py,
общий для core/worker bootstrap. Schema 1.0: workspace/persona/scope, finite
ports/resources/embedding/queue/recall bounds; autostart только false.
Defaults → явно выбранный nonsecret workspace draft → local JSON overrides →
explicit local binding/process env. JSON не принимает секретные поля.
Paths selector только process environment, не новые implicit reads из .env.
.env.example имеет пустые Redis/LLM bindings; config/defaults содержит
редактируемый вымышленный workspace example, не accepted persona canon.
Настоящий local .env агент не читал/не переносил/не выводил.

Bootstrap сначала валидирует настройки и binding compatibility, затем
создаёт shell/idle receipt. Каждый запуск — свежий epoch и STOPPED/effects false;
переданный persisted ACTIVE/STARTING/STOPPING/FAULTED не восстанавливает допуск.
Credentials/endpoint SecretStr; safe manifest имеет явный allowlist без
workspace/persona IDs, paths и значений bindings. Ошибки: статический field/code,
без raw inputs/exception contexts/JSON/file paths; CLI/entrypoints exit 78.

Назначенное минимальное wiring deploy/core.py/worker.py: validation до
listener/heartbeat; existing CORE_CONTAINER_PORT alias также валидируется.
Ни одного LLM/DB/broker job/native integration вызова на bootstrap.
Это не реализация supervisor STOP/revocation/lease/permissions, которые в M1.

При actual image check обнаружено: cached local wheel uv оставался старым
после изменения Python files без pyproject changes; configuration module
отсутствовал в установленном package. Coordinator назначил минимальный fix:
две uv sync строки Dockerfile получили --reinstall-package ai-agent-platform.
[Правила uv cache](https://docs.astral.sh/uv/concepts/cache/) подтверждают
такую эвристику и forced rebuild; фактическая пересборка/installed source
hash checks прошли. Manifests/locks/base images/Compose/resources не изменялись.
Никакого удаления чужих images/cache/volumes или workaround architecture.

## Приёмка / непроверенное / далее

M0-06 критерии пройдены: editable example; invalid profile explained safely;
secret dump отсутствует; fresh/restored bootstrap всегда STOPPED.
Секреты endpoint/key нужны только при later live LLM binding; реальных
providers/paid API/user profiles/game/channels/public releases не было.

Source validation не выдаётся за runtime API/access/state machine.
Selected external profile/override paths не монтируются Compose автоматически:
deployment owner привяжет их явно. Resource fields — validated intentions;
реальные container limits остаются M0-04. Root JSON profile — bootstrap draft,
а канон/accepted snapshot/version commands появляются M2-01.
Для runtime с новой ревизией нужен rebuild (compose build), ранее собранные
M0-04 tags не менялись; pinned M0-06 images отдельно проверены.
Реальные auth/CSRF/service scopes, STOP при broker/DB отказе, sleep watchdog,
owner persistence и restart после ACTIVE service будут проверены M1.
Следующая зависимая задача M1-01: contract schemas/converters/OpenAPI.
