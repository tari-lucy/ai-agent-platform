## Первая поставка

- Read-only impact из существующей SQLite: все редакции ManagedFile/SkillVersion/
  Ticket/TicketMessage/WorkTask/WorkAttempt, включая скрытые/старые. Связи SourceRef,
  ArtifactRef, produced_by_attempt, task и ticket; текст не ищется по совпадениям.
- PurgeImpact содержит только IDs/отпечатки редакций/keep digests. Пределы rows/
  bytes/blob count конфигурируемые; неизвестный workplace kind и превышение
  ограничений дают отказ, не частичный успешный план. Второго реестра нет.
- WorkplacePurger — существующий DerivedPurger: требует независимый ledger,
  source уже должен быть blocked. Сначала скрывает затронутые identities, затем
  quiesce runner/harness, проверка полного ранее принятого impact, физическое
  удаление blob/history и SQL invalidation. При сбое остаётся blocked_pending_purge.
- DirectoryBlobs.prune держит те же проверенные Windows handles/POSIX dir_fd,
  отказывает на links/reparse/чужие имена. Сохраняет bytes, используемые другой
  независимой записью; удаляет старые digest и неопубликованные orphan/pending
  копии в данной области. Чужие partitions не обходятся и не удаляются.
- SQLitePhysicalStore.erase_records_locked — та же существующая erasure
  реализация под уже захваченной writer reservation, без второй write transaction.
  Это исключает запись нового файла между вычислением keep set и очисткой.
  Identity остаётся blocked, все payload revisions удалены; finalize/VACUUM,
  tombstones и purged_at по-прежнему принадлежат RetentionService.
- confirm и quiesce callbacks **обязательны**, permissive runtime defaults нет.
  Это проверка уже существующего решения по удалению и остановки ресурсов;
  второй отдельный пользовательский диалог подтверждения не предполагается.

## Открытый стык: preview существующего удаления

Сейчас MemoryPlanProof / m3_composition.memory_lifecycle показывает erased/detached
память; material-linked workplace bodies в нём не представлены. Простое включение
purger скрыто расширило бы последствия source delete. Минимальное изменение в
ближайшем shared-окне: добавить invalidated identities + fingerprints всего history
в existing proof/DeletionPreview, dependency digest и текст последствий. Показать,
что неразделимый файл/skill/тикет теряет весь body/history, а не одно слово.
Before-block сверка должна включать полный impact. Confirm callback проверяет
этот proof (при resume допустим уже удалённый subset, но не новые/изменённые bodies).

Сейчас constructor требует confirm именно потому, что production proof wiring
ещё не готов. Не подключать lambda pass к рабочему retention. Тестовые callbacks
разрешают только явно синтетическую область/проверяемый план.

## Открытый стык: чтения тикетов/материалов (Claude AW-01/05/07)

TicketService.get/messages сейчас проверяет SourceRef через SQL, но materials —
ArtifactRef, не SQL source-link. Кроме того, _merge обрезает refs до последних 50,
тогда как старое TicketMessage тело остаётся. Поэтому после удаления/отзыва старого
основания нельзя полагаться только на текущий Ticket.sources.

Нужно подключить owner release check перед выдачей ticket/message/context: текущий
ledger/TTL + исторические SourceRef/material links и актуальный ManagedFile guard.
Не терять provenance при переполнении: отказ/новый явно связанный контекст, а не
молчаливое отбрасывание. Более простой безопасный первый вариант — скрывать весь
тикет, если любое его историческое основание закрыто. Новые message/source связи
можно добавить совместимо в окне владельца. SourceRefs должны браться из записанных
inputs, не только из добровольного списка модели. Это точный privacy gate перед
личными данными, а не просьба пересматривать весь пакет тикетов.

Ранняя block в purger уже закрывает найденные identities даже при physical failure,
но не заменяет release gate при чистом API-transfer revoke, restore или scan error.
AW-03 уже integrated в свежем origin/main; его additions будут сверены при merge.
