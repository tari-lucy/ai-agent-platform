# Warm OpenCode: медленная подготовка входов и окно активации

Codex, 2026-10-27. Продолжение ветки `codex/workspace-100mib-files` после `06345bf`.
В main не вливать самостоятельно: платформенное исправление передаётся Claude.

## Наблюдение и воспроизведение

После увеличения лимита входа два новых личных рабочих хода всё ещё завершились
CAPABILITY_UNAVAILABLE без вызова модели роли activity и без журнала инструментов.
Отдельный activity-goal успешно вызывал модель: это другой ход. Предел размера
был реальным препятствием, но его изменение не устранило весь отказ.

Найдена ещё одна воспроизводимая ошибка: WarmSessions.take резервирует прогретый
контейнер, затем driver/runner проверяет основания, читает файлы и сериализует
вход. WarmSandbox.activate разрешал активацию только в течение 5 секунд после
claim. При длительной подготовке этот срок истекал, даже если все свежие права
и источники подтверждены. Исключение превращалось в общий неуспешный исход.

Реальный тест с прогретым OpenCode, вымышленным home, синтетическим провайдером
и шестисекундной задержкой проверки входа до исправления падает за 16,77 с:
итогового result нет. Текст реального диалога, архив и API для воспроизведения
не использовались. Это доказывает механизм, но не является записью точного
внутреннего исключения двух уже завершённых личных ходов: старый журнал его терял.

## Исправление

- После подготовки/сериализации входа и **повторной полной `_verify`** доверенный
  runner вызывает `refresh_claim(template, task)` непосредственно перед attach.
- Метод сначала проверяет supervisor через `valid()`, затем тот же живой
  зарезервированный процесс, template, limits и network. Обновляет только время
  короткого claim: Permission, admission, epoch, supervisor lease и home не меняются.
- `activate()` по-прежнему отклоняет активацию за пределами пяти секунд после
  подтверждённого claim. Закрытый/освобождённый/чужой slot оживить нельзя.
- Проверки на границах модели, инструментов и результата, STOP и cleanup сохранены.
- При техническом отказе runner пишет только фиксированную фазу, тип исключения
  и контрактный код. Тексты, пути, идентификаторы источников и секреты не пишутся.
  Это позволит отличить следующую причину вместо повторного гадания по общей ошибке.
