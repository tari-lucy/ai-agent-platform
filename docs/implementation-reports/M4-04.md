## Что сделано

- **Список и поиск** по загруженным страницам (первая страница каждого ресурса + «Загрузить ещё» по серверному курсору):
  фильтры по типу записи, виду знания, доступности, человеку/автору, периоду и тексту. Интерфейс прямо говорит, что это
  поиск по загруженному, а не серверный recall (маршрута recall для панели нет).
- **Карточка**: вид знания (наблюдение / чужое сообщение / гипотеза / интерпретация / канон), источники основания и их
  состояния, уверенность, противоречие (обе позиции сохранены, ссылки между утверждениями), срок хранения (защищено, без
  срока, осталось N дн., истёк), права источника (чтение / API / публичное раскрытие), адаптер и внешний ID.
  Недоступное не заменяется выдуманным текстом: «Содержимое недоступно… не восстанавливается».
  Текст скрыт, если источник недоступен, чтение запрещено, а у производной записи нет ни одного доступного основания;
  текст удалённого/просроченного источника, пришедший от сервера, отвергается валидатором и не показывается.
- **Исправление** утверждения/сводки: основание обязательно, уверенность можно только снизить, команда несёт `expected_version`
  увиденной версии; `VERSION_CONFLICT` предлагает пересмотреть правку, чужая правка не затирается и повтор не делается.
- **Удаление и экспорт источника**: предпросмотр → план последствий (текст владельца, число связанных записей, срок плана,
  напоминание про внешнюю публикацию и копии) → явное подтверждение (для удаления) → исполнение, привязанное к `plan_id` и
  версии плана. План обязан содержать выбранную запись и быть не просроченным (проверка и при показе, и в момент клика).
  Потеря ответа: «Проверить исход» повторяет **ту же** команду (тот же `request_id`), второго исполнения нет.
  Ход выполнения берётся из операции владельца: «Выполнено» только при `SUCCEEDED`; `OUTCOME_UNKNOWN` не выдаётся за успех,
  ожидающая часть показана отдельно.
- Постоянный STOP, пометка тестовой памяти, plain text (HTML не исполняется), отсутствие записи в браузерное хранилище,
  узкое окно без горизонтальной прокрутки — как в M4-01/M4-02.

## Решения и допущения

1. Схемы полезной нагрузки `memory.correct`, `memory.delete.*`, `memory.export.*` в backend **не определены**; имена в одной
   константе `MEMORY_SCHEMA` (`ui/memory/model.ts`) — предположение, ждёт владельца контрактов. Пока ядро отвечает отказом,
   панель показывает его честно и ничего не считает выполненным.
2. Удаление и экспорт — по одному источнику за план: `expected_version` предпросмотра привязан к версии выбранной записи.
   Пакетные планы (M5-01 их умеет) потребуют решения владельца о смысле `expected_version` для набора.
3. Исправления доступны для утверждений и сводок; эпизод неизменяем, источник — первичное свидетельство.
4. Время «осталось N дн.» — снимок на момент открытия карточки (рендер остаётся чистым, фонового таймера нет).

## Не проверено / ограничения

- Реальная интеграция: нет маршрутов/обработчиков `memory.*`, composition владельцев, связи с `RetentionService` M5-01; полный
  цикл «план → удаление → физическая очистка → отчёт» не выполнялся. Артефакт экспорта и его скачивание — не реализованы
  (только статус операции).
- Серверный поиск/recall, фильтры на стороне сервера, `projection_lag`, поиск по человеку через `Person` (M4-03).
- Node 24, Firefox/WebKit, Windows, реальный TLS/прокси.
