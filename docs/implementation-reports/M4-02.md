## Что сделано

- **Лента** из `sources` (operator_input/third_party_message), `utterances` (только новейшая ревизия) и `deliveries`.
  Статусы: сохранено, генерируется, предварительно, завершено, отменено/не отправлено, исход неизвестен, ошибка доставки,
  текст недоступен. Доставка считается по каналам: один неизвестный/неудачный канал не прячется за успешным; более новая
  попытка того же канала заменяет старую; доставки другой ревизии и другого сообщения не учитываются.
- **Отправка**: одна команда `dialogue.message` (target — session_id, scope с run/session). Поле очищается только после
  квитанции. При потере ответа команда **сохраняется без изменений**; «Проверить исход» повторяет ту же команду с тем же
  `request_id`, ядро возвращает сохранённую квитанцию. Автоповторов нет. Ясный отказ не создаёт ложной неизвестности.
- **Текущая цель/ожидающие дела**: из `RunSession` и открытых `operations`; цель и основание ядро не передаёт, это сказано
  прямо (ничего не придумывается). «Генерируется» только по открытой операции владельца.
- **Вводные**: список (тип, автор, срок, статус), создание (тип, текст ≤4000, срок в будущем ≤366 дней), отмена с
  `expected_version`. Текст вводной не меняет канон/права.
- STOP остаётся постоянным и действует по фактическому владельцу независимо от просмотра (проверено в браузере во время
  «генерации»). Тестовая область помечена и не получает цели команд. Вся текстовая выдача — plain text (HTML не исполняется).
  В браузерное хранилище ничего не пишется.

## Приёмка

| Критерий M4-02 | Результат |
| --- | --- |
| Send/save/stream/final/error | отправка и квитанция, потеря ответа → проверка тем же id (одна команда), отказ без потери текста, статусы ленты; **stream-превью не реализовано** (приватного потока в core нет) — об этом сказано в интерфейсе |
| Версионные вводные | создание и отмена с `expected_version`; конфликт версии показывает безопасное сообщение, повторной записи нет |
| STOP во время генерации | кнопка доступна и цель — владелец запуска (браузерный тест) |
| Не тот агент/область | тестовая память не получает команду; закрытая отправка при остановленном агенте |
| Безопасность | чужая область/неверные перечисления отвергаются до кэша; сырые ошибки не показываются; HTML как текст |

## Решения и допущения

1. Схемы полезной нагрузки `briefing.create`/`briefing.cancel` в backend **не определены**: имена вынесены в одну
   константу `BRIEFING_SCHEMA` (`ui/dialogue/model.ts`) как предположение. Пока владелец не определит и не зарегистрирует
   схему, ядро отвечает отказом, и панель показывает его честно («функция пока недоступна»).
2. Входящие сообщения берутся из `sources` по происхождению; в core нет отдельного чтения «сообщений сессии» и привязки
   к `session_id`, поэтому лента относится ко всей области, а не к одной сессии.
3. Первая страница (limit 50) каждого чтения; неполнота помечается.

## Не проверено / ограничения

- Реальная интеграция: маршруты сообщений/вводных и композиция владельцев в core отсутствуют; диалоговый контроллер M2-06
  не подключён. Полный цикл «сообщение → ответ → доставка» не выполнялся.
- Предварительный текст по мере генерации (нужен `PrivateStream`), возобновление после обрыва WS с `after_event_id`.
- Реальный Node 24, Firefox/WebKit, Windows, настоящий TLS/прокси, реальная модель.
- Часовой пояс: время показано в локальной зоне браузера; UTC доступен в `title`.
