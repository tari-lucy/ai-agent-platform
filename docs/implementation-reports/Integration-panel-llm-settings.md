# Настройки лимита API и тарифов в панели

Координатор, 2026-10-19. База `d170cd4`, ветка `codex/panel-llm-settings`.
Стык M4-08 с владельцами конфигурации host и учёта LLM. Полная приёмка M4/M5
этим отчётом не объявляется. Платных вызовов нет.

## Результат

- «LLM и расходы → Обзор»: чтение и изменение предела попыток в WORK, только
  при STOPPED. Перезапуск сервера не нужен. Число хранится в `host.json`,
  счётчик usage не сбрасывается. Период онлайн не меняется; резервы памяти/GM
  остаются внутри общего предела. Технический диапазон 1..1 000 000,
  минимальное допустимое значение рассчитывается по включённым резервам.
- «Цены»: запись новой версии Tariff через владельца LLM. Предыдущая версия
  задаётся явно, без автоматического CAS-retry поверх чужой правки. Новые
  попытки закрепляют тариф по времени начала; старые CostCalculation не меняются.
  Неизвестная ставка/usage не превращается в ноль. Дата новой версии не раньше
  предыдущей, будущее ограничено годом. Исторический пересчёт не подключён:
  его прежние UI-only кнопки заменены честным пояснением.
- При неизвестном результате POST формы сохраняют точную команду в RAM и
  предлагают проверить её с тем же request_id. До разрешения исхода поля
  закрыты. Секретов, endpoint и browser-storage для команд нет. После reload
  незавершённая команда не восстанавливается: сначала проверяется фактическое
  значение. Список тарифов дочитывается курсором; запись новой версии закрыта,
  пока не загружены все головы тарифов. Старый закреплённый тариф виден в истории
  попыток; список цен не выдаётся за полную историю редакций.

## Владение и восстановление

`LiveBudget` — адаптер существующего владельца host-config. У него нет своего
счётчика или второго хранилища лимита. Запись файла атомарная; RMW использует
тот же asyncio-lock, что HostLedger. Резервирование ledger_floor и изменение
лимита не теряют правки друг друга. Runtime admission получает новый предел
без await между окончательной проверкой допуска, записью и заменой бюджета.

В файле сохраняется одна последняя техническая квитанция ApiLimitChange с
монотонной budget_version; долговременный статус команды — существующий
OwnerOperation у WORKSPACE. Потеря подтверждения между file commit и записью
результата в SQLite восстанавливается по совпадению request_id, оператора и
fingerprint, без повторного изменения. Восстанавливается и runtime cap после
прерванного подтверждения file commit. Если доказательства исхода нет,
ответ остаётся OUTCOME_UNKNOWN. Завершённые старые квитанции воспроизводятся
после последующих правок. Офлайн configure-api-budget повышает версию и очищает
последнюю файловую квитанцию. Чтение host-config при backup учитывает UTC-поля
новой квитанции через тот же JSON validator.

Tariff создаётся вместе с квитанцией в одной существующей транзакции LLM;
request_id внутренней операции разделён по оператору. Текущие API ACL Connection
и Tariff проверяются перед записью и в транзакционной fence. Публичные контракты
и generated JSON Schema/OpenAPI/TypeScript обновлены из одного каталога.

## Найденный блокер старого host

У init подключения и назначения имели ACL только для LLM; оператор видел пустой
список даже с owner-grant. Без обхода этих ACL запись тарифа отказывала.

Новый init с явным operator-controls выдаёт оператору чтение метаданных
Connection/LLMAssignment. Для ранее подготовленного host добавлена офлайн-команда
`prepare-llm-panel --root <host>`. Она работает под host-lock, сохраняет другие
ACL и создаёт версии записей через их владельцев. Повтор не меняет уже готовые
записи. Значения моделей/привязок и Permission, общие grants, память и TEST не
меняются. Частичная подготовка безопасна для исполнения и может быть повторена.
`serve` ничего не выдаёт и не мигрирует. Connection содержит только имена
настроек, реальные значения ключей/endpoint из `.env` не читаются этой командой.

## Проверки

Временные host, реальные владельцы/SQLite/HTTP, синтетический транспорт и данные.
Рабочая память в тестах не используется.

- Четыре новых host-сценария приняты отдельными точечными прогонами: cap/CAS,
  replay, сохранение расхода/restart STOPPED, отказ ACTIVE/TEST/без CSRF,
  нижняя граница резерва, совместный RMW с независимым ledger; потеря
  подтверждения file commit; тариф/CAS/replay/старые и следующие стоимости,
  unknown usage и отзыв API-доступа; явная повторяемая офлайн-подготовка старого
  ACL без изменения Permission и host-config.
- Последний совместный прогон offline preparation + `tests/usage` +
  `tests/contracts`: 127 passed (19.32 с). Это не повтор всех новых host-тестов.
- Windows Edge, настоящие subprocess init/serve: cap 300→350 и первый тариф,
  потерянные после commit ответы, одинаковые повторные тела/request_id,
  reload и restart, настройки сохранены, START остаётся явным. Вместе с
  затронутой прежней панелью расходов: 13 passed (32.26 с), JS ошибок нет.
- Node LLM/client tests: 23 passed. Отдельная регрессия JSON host-config для
  backup с ApiLimitChange: 1 passed. Ruff, strict mypy (220 source files),
  typecheck/build и ESLint чистые. Generated export check и static import boundaries
  проходят; diff проверен, в изменённых файлах секретов/личных путей не найдено.

Первый прогон выявил реальный блокер ACL; после исправления сценарий тарифа
принят. Последующие отказы тестовой подготовки (импорт Permission, имя/параметр
CLI, слишком широкая замена fixture grants) исправлены; перепроверялись только
затронутые сценарии. Полный suite и платные API-пробы не запускались.

## Ограничения

Нет денежного hard limit/сверки счёта провайдера, онлайн-смены периода, модели
или подключения, исторического repricing и полного просмотра редакций тарифа.
Лимит рабочего host остаётся 300; тестовые цены не переносятся в рабочую БД.
Пользовательские ставки вводятся оператором в панели. Автоматического START
или вызова модели при сохранении настроек нет.
