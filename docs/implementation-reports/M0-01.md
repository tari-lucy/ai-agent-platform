| Состояние измерения | Свободная RAM Windows | Дополнительное наблюдение |
| --- | --- | --- |
| До запуска Docker оператором | 5,41 ГиБ; позднее 5,72 ГиБ | Engine недоступен, distro Stopped |
| После запуска Docker, 7 сторонних контейнеров | 0,97 ГиБ; позднее 1,27 ГиБ | vmmemWSL working set 5,66 ГиБ; анонимная сумма docker stats примерно 4,22 ГиБ |
| После разрешённой остановки всех семи | 3,70 ГиБ | Running = 0; vmmemWSL working set 2,85 ГиБ; Engine доступен |

Сумма Docker stats округлена и не равна памяти VM: она не включает все расходы
WSL, Desktop и ОС. Working set — отдельная метрика, не private committed bytes
и не установленный лимит. После остановки часть памяти WSL ещё занята;
причина/срок её освобождения не измерены. Автоматический reclaim не проверен.

Defaults проекта: core 768 МиБ + worker 1536 МиБ + Redis 256 МиБ = 2560 МиБ
(2,5 ГиБ), общая цель вместе с Docker/WSL ≤ 4 ГиБ. Разница 1,5 ГиБ — целевой
запас на инфраструктуру, а не измеренный overhead. Один embedder, threads 2,
batch 4; Redis maxmemory 128 МиБ/noeviction; не более одной тяжёлой пробы.

В текущем снимке после остановки свободно меньше 4 ГиБ. При этом целевые
4 ГиБ включают уже работающий Docker/WSL, поэтому нельзя механически
вычитать их как полностью дополнительный расход. Без измерения целевого
runtime нельзя подтвердить достаточность запаса. Перед install/build/model
probe повторить снимок, учесть peak/кэш/возврат памяти, выделить один runtime
slot. Не запускать второй полный стенд. CPU/API baseline остаётся выбранным;
совместная работа с игрой/аватаром/эфиром не исследовалась.

## 4. Безопасные локальные настройки: проверено и отложено

- `.env` отсутствует именно в новом worktree; поиск секретов по машине не делался.
  Значения env, auth headers, provider endpoints, Docker container env и диалоги
  не читались. Для metadata использовались только allowlist полей.
- `git check-ignore --no-index` подтверждает исключение `.env`, `.env.*`,
  `.secrets/`, `credentials/`, `profiles/private/`, `data/`, `runtime/`, `logs/`.
  Тестовые имена переданы как аргументы; реальные секретные файлы не открывались.
- Из Docker settings-store прочитаны только разрешённые поля: сохранён
  `AutoStart=false`; ресурсные/backend/TCP поля в этой записи не обнаружены.
  Отсутствующий override не выдаётся за конкретный default.
- Пользовательский `.wslconfig` не найден. Явный пользовательский лимит WSL RAM,
  swap, processors и autoMemoryReclaim этим файлом не задан. Machine-wide policy
  и effective runtime limits отдельно не исследованы; Engine MemTotal указан выше.
- На стандартных TCP-портах Docker API 2375/2376 слушателей не найдено ни после
  запуска, ни после остановки контейнеров. Это проверка двух портов, не общий
  аудит сети/firewall и не доказательство настройки будущего core/Redis.
- Git обнаружил разницу владельцев repo/admin files и текущего процесса.
  Использован только точный `git -c safe.directory=<свой checkout>` на каждый
  вызов. Глобальный Git config, ACL и права не менялись; wildcard trust не добавлялся.
- Sandbox отказал CIM/WSL, а status управляемого worktree дал ложное для обычного
  checkout сообщение `must be run in a work tree`. Те же чтения вне sandbox
  подтвердили нормальный non-bare worktree и работающий WSL/Engine. Нулевые поля
  из неуспешного docker info/CIM не трактовались как 0 RAM/CPU/контейнеров.
- Перед коммитом проверены отсутствие custom hooksPath и активных hooks.
  Проверка ACL/шифрования локальной памяти и backup не проводилась: данных
  нового runtime нет, doc23 не объявляет шифрование уже существующим свойством.

Для владельца M0-04/M0-06 остаются: публикация только loopback core,
непубликуемый Redis/DB, отдельные Compose project/volumes и изолированные
work/test данные; service credentials по ролям, safe config validation,
остановленный агент после startup/restart. Конфигурация этих свойств сейчас
не создавалась. Не предлагается лимитировать всю VM до 4 ГиБ автоматически:
общая VM и сумма container budgets — разные области настройки.

для автоматического повторения при аудите другой машины. Имена не публикуются.
Установка/сборка/сетевые download probes не входят в этот набор.

## 7. Ограничения и передача M0-02

1. Python 3.14 локально не обнаружен; целевой Linux image ещё отсутствует
   в принятой конфигурации. В M0-02 подготовить независимый uv-проект,
   выбрать/закрепить 3.14 patch и проверить чистую установку/минимальную сборку.
   Дополнительные install/download действия сейчас не выполнялись. Python 3.13
   из doc20 — fallback только при доказанной несовместимости 3.14, а не из-за
   наличия host 3.13.12. Крупную смену решения передать координатору.
2. Docker Engine уже доступен, но новая сборка/проба требует повторной оценки
   памяти и единственного runtime slot. Чужие проекты остановлены только по
   явной команде оператора; их прежние policies сохранены. Одновременный запуск
   других workload снова изменит запас. Не запускать/удалять их из M0-02.
3. FastEmbed/ONNX/sqlite-vec/FTS5/SQLAlchemy на Python 3.14/Linux не проверены.
   Нет основания считать Windows-installed packages совместимым lockfile.
   Wheel resolution/minimal build — M0-02; load/restart/delete/rebuild,
   RU embedding, peak RAM/latency и image/model digests — M0-03.
4. Compose v5.1.2 не объявлен несовместимым, но features/health/named volumes/
   container limits/loopback/AOF и restart проверяет M0-04. API/STOP, работа
   без Redis/DB и work/test isolation требуют M1/M2/M5, не host inventory.
5. Не проверены registry/package network access, downloads/checksums образов,
   компилятор/C toolchain при отсутствии wheels, установка npm graph и
   Playwright browsers. После отдельного назначения M0-02 использовать обычные
   предусмотренные задачей пробы; не устанавливать глобально всё заранее.
6. Нужен конкретный владелец LICENSE/third-party notices и выбранного варианта
   Redis license. Doc23 относит это к M0, но текущая зона — только отчёт.
   Минимальное решение: координатор явно включает эти файлы в назначение
   владельцу manifests/поставки. Здесь shared change и обходная копия не созданы.

Других противоречий, требующих перепроектирования, не обнаружено.
Исходный аудит достаточен для review M0-01 и постановки M0-02 после принятия
координатором. G0 не закрыт: успешных target probes/locks/digests ещё нет.
