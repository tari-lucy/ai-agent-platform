# OC: стабильный список и название разговора

Дата: 2026-10-24. База: `f2eca21`. Исполнитель: Codex.

## Причины и результат

Карточки bridge не содержали сохранённых дат. Адаптер подставлял Date.now()
при каждом чтении; detail дополнительно терял даты даже при их наличии.
SSE/refetch поэтому менял ключ сортировки без настоящего изменения разговора.
Теперь список и расшифровка передают created_at/updated_at владельца, detail
сохраняет их; при отсутствии даты fallback — стабильный 0, а не время GET.

Родной редактор названия отправлял не подключённый `/api/session/{id}/rename`.
Патч 12 переводит этот запрос в `work.session.rename`: авторизованный оператор,
stable Scope, expected_version, существующий SessionBook, транзакция/CAS/replay.
Переименование не записывает сообщение, не будит персонажа и не вызывает модель.
Подготовленный/выполняемый ход даёт RESOURCE_BUSY: его session version не меняется,
поэтому правка заголовка не отменяет оплачиваемый ответ. Переименовывать после хода.
Неизвестные native-маршруты, архивирование и прочие операции не открыты.

Изменённые зоны: contracts/generated, SessionBook, dispatch work sessions,
bridge-проекции, native patch/snapshot, тесты и документация. Миграций, зависимостей,
новых разрешений и изменений runner нет.

## Проверки

- Production bridge HTTP: 3 passed, включая стабильные даты списка/detail,
  переименование, точный replay и конфликт старой версии. Расширенная проверка
  busy отдельно — 1 passed. Сначала тест ошибочно ожидал 409, исправлено на
  штатный HTTP 429 для RESOURCE_BUSY; production-код по этому падению не менялся.
- Bun: 4 passed, включая list/detail refetch и запрос rename, прежний ACK.
- Edge с собранным native UI, настоящими owners и синтетическим harness:
  1 passed; ввод → переименование заголовком → reload → START → ответ/ACK → STOP.
- Ruff чистый, strict mypy трёх изменённых Python-модулей чистый.
- Vite build прошёл; bundle проверен loader: 938 файлов, 34 352 745 байт.
  Все 12 патчей на pinned v1.19.3 дают точное дерево сборки (отдельный Git index).

Полный suite, новый Linux typecheck и реальный Docker-runner не повторялись:
runner не менялся. Платных вызовов и новых сообщений в личную память нет.

## Сопутствующая диагностика скорости

Из сохранённых метаданных двух последних завершённых рабочих ходов:
время между созданием и завершением WorkAttempt — примерно 59 и 106 секунд.
В соответствующих временных интервалах запросы модели занимали суммарно около
17 и 54 секунд (2 и 5 вызовов). Отдельный вызов — примерно 5–16 секунд.
Это интервальное сопоставление, не новая сквозная трасса по дочернему operation_id.

Остальное время включает запуск OpenCode, инструменты, проверки, журнал и паузы
между запросами; точного распределения нынешние данные не дают. Поэтому нельзя
объявлять провайдера единственной причиной или гарантировать ускорение сменой
модели. Следующая самостоятельная оптимизация — измерить эти участки и убрать
лишние ожидания/последовательные чтения, сохранив STOP, release и бюджет.
Этот пакет исправляет UI, не объявляет задержки исправленными.
