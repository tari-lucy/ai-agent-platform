# Рабочий ход: продолжающийся отказ до модели

Codex, 2026-10-27. Handoff Claude, ветка `codex/workspace-100mib-files` после `ebaef57`.

После увеличения входов и исправления warm-claim личный рабочий ход всё ещё не
прошёл. Новые WorkAttempt завершаются CAPABILITY_UNAVAILABLE без tool_steps и
**без LLMAttempt роли activity**. Activity-goal в соседнем задании успешно
вызывает провайдера; это не доказательство вызова модели рабочего разговора.
Образ доступен, отдельные пробы подготовки OpenCode с home/MCP проходят.
Заново отправлять личные сообщения в диагностике Codex не стал.

## Следующая проверяемая причина

Фактические не секретные настройки личного host:

- `live.max_prompt_chars = 24000`;
- `work_sessions.max_prompt_chars = 100000`;
- верхний предел поля LiveConfig.max_prompt_chars в коде — 40000;
- configure-api-budget пока не предоставляет параметр prompt-size.

Измерение на настоящем Docker/OpenCode с вымышленным home и синтетическим
провайдером: **16110 символов, 7 базовых инструментов**, без личного канона,
памяти, production MCP и дополнительных EnvironmentModels guide. Живых вызовов 0.
Следовательно, общий cap 24000 оставляет менее 8000 символов для остального;
его несогласованность с рабочим cap — конкретная гипотеза, а точный размер
неуспешного личного запроса старые журналы не сохраняют. Не утверждать, что
любой следующий CAPABILITY_UNAVAILABLE вызван только этим ограничением.

Execution.generate в m3_composition/service.py проверяет prompt_size(messages,
tools) против private_api_budget.max_prompt_chars **до** LLMGateway/журнала
попыток. ExecutionModelGateway в activity.py превращает CAPABILITY_UNAVAILABLE
и RESOURCE_BUSY в not_admitted. Дальше рабочий driver показывает общую ошибку.

## Пакет Claude (Linux подходит)

1. Воспроизвести отказ на production local host с синтетическим провайдером,
   home/internet/MCP и ограничением 24000; подтвердить отсутствие сетевого вызова
   и LLM-попытки. Измерить только суммарный размер/число инструментов, не тексты.
2. Дать оператору точную фиксированную причину до-модельного отказа; источник
   конфликта лимитов должен быть виден вместо общей ошибки OpenCode.
3. Согласовать явно настраиваемый рабочий предел с host/provider budget. Не
   поднимать предел автоматически при отказе, не обходить ни один из guard.
   Если нужен больший потолок LiveConfig — сделать это явно, сохранив текущий
   default и существующие настройки. При необходимости добавить offline CLI.
4. Проверить отказ без транспорта при малом лимите и успешный тот же путь при
   достаточном настроенном лимите; без платных проб и полного gate.

Окно Claude: m3_composition/service.py, activity.py. При необходимости также
local_host/layout.py и cli.py: пакет 100 МиБ там уже закоммичен, новых WIP Codex
в этих файлах нет. Диагностику и применение на личном Windows host оставляет Codex.
Общие контракты/экспорт отдельно не выдаются этим handoff: если понадобятся,
сообщить минимальные совместимые поля. Код платформы — отдельной веткой.

Ни приватная переписка, ни ключи, endpoint, реальные файлы или .env для
воспроизведения на VPS не требуются. Платные повторы и новый длительный soak
не запускались. Реальное рабочее поручение после `ebaef57` успешным не объявлять.
