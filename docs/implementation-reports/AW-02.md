# AW-02 — управляемое файловое пространство

Дата: 2026-10-21. Исполнитель: Codex. Статус: integrated; runtime включение новых файловых прав не выполнялось.
Ветка `codex/aw-02-workspace-files`. Начальная подготовка от `113e975`,
реализация принятого AW-00 после merge `98ea2b8`; подготовительный commit
`a8ea0a6`. Финальный commit определяется Git log этого отчёта.

## Результат и критерии

- Реализован принятый порт `WorkspaceFiles`: `ManagedFiles`, Owner.CATALOGUE,
  существующие SQLite/UoW/receipts, CAS и idempotency. Второго каталога нет.
- WORK/TEST/persona изолированы в metadata и физическом partition. Имена файлов
  логические; physical store принимает только scope и checksum от владельца.
  Произвольные host paths, DB/secrets/backup через порт не доступны.
- Read/list/search/write, неизменяемое содержимое и история версий. Одна запись
  каталога/квитанции публикуется транзакционно после полного blob write/fsync.
  Сбой до commit может оставить закрытый orphan, но не доступный файл.
- Квоты конфигурируются через FileLimits: файл/все bytes области/число файлов/
  все версии/scan cap. Старые, скрытые и orphan bytes учитываются. Повтор
  content hash не расходует bytes повторно. CAS и uniqueness не дают перетереть
  чужую логическую запись. Reference/guide не становятся writable при переносе.
- SourceRef и file DAG берутся из зарегистрированного WorkAttempt; заявленные
  скриптом источники могут только дополнить их. Предыдущие зависимости сохраняются.
  FileReleaseGuard проверяет partition, текущие/выбранные версии, TTL, права и
  существующий независимый deletion ledger до/после IO и при выдаче.
- API/public rights не возникают из private read: пересечение разрешений всех
  входов и явно настроенного default_access; по умолчанию оба false.
- Trusted authorize callback обязателен. STOP/lease/epoch проверяются через
  WorkAdmission и storage fence; поздний blob не становится записью каталога.
- Физический read отказывает на traversal/ADS/device/UNC, symlink/hardlink,
  reparse, FIFO, подмену root и повреждение digest. Windows удерживает реальные
  directory handles без delete sharing; POSIX использует pinned dir_fd/no-follow.
  Private store не является sandbox и не монтируется в runner.

## Подключение для Claude AW-03/AW-05/AW-07

Импорты: `ai_agent_application.workspace_files` (ManagedFiles, FileLimits,
FileReleaseGuard), `ai_agent_adapters.workspace_files.directory.DirectoryBlobs`,
`...usage.CatalogueUsage`. Реальный образец композиции — tests/workplace_files/wf_support.py,
не конфигурация production прав.

Constructor требует storage + core_owner CATALOGUE principal, закрытый blob store,
release guard, существующий AttemptContext, CatalogueUsage.counts, limits и
`authorize(admission, read|write, area)`. Hook обязан проверить актуальное
Permission конкретного агента/area; SQL service grants это не заменяют.
`admission.is_current` должен проверять supervisor, job lease, отмену и актуальность
допуска. Попытка хранится владельцем activity до IO, включая все реально прочитанные
inputs/input_files; нельзя доверять только declared_sources из результата модели.
Отдельный реестр попыток не создавать.

Readonly list/search предназначены для trusted composition/operator routes с
их session/scope authorization; объект сервиса не выдаётся агенту или runner.
Все consumers используют owner guard, включая API transfer: generic SQL reader
не заменяет проверки state/access ManagedFile. Новый host не получает grants
через создание сервиса или serve. `DirectoryBlobs.prepare` — только явный trusted
setup нового каталога с owner-only ACL/permissions. Не передавать root модели.

## Границы поставки

AW-02 acceptance закрыта как владелец принятого порта. UI/HTTP/task wiring —
AW-03/05/07; защищённый runner — AW-04. Физическое удаление orphan/history,
backup manifest и restore fence — AW-09. До его gate не включать личные данные
в новый контур. Windows directory power-cut durability не заявляется:
fsync содержимого есть, POSIX directory fsync есть; Windows metadata flush
не доказан. Search линейный и ограниченный max_scan; большого corpus gate нет.

Production host, реальные диалоги, платные API и браузер не использовались;
полный suite приложения не запускался. Существующие контейнеры/volumes не менялись.
Следующая независимая задача Codex — AW-04; AW-03 может брать принятый порт
после фактической интеграции этой ветки в main.
