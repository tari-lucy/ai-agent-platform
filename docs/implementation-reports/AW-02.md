# AW-02 — управляемое файловое пространство

Дата назначения: 2026-10-21. Исполнитель: Codex.
Статус: in_progress / независимая подготовка файлового примитива. Полная
реализация и приёмка AW-02 не выполнены; зависимость AW-00 должна быть
integrated до использования новых общих схем/API/owner wiring.
Исходная база подготовки: `113e975`; отдельная ветка
`codex/aw-02-workspace-files`, свой checkout. После AW-00 база обновляется.

## Зона

Свой application workspace_files, filesystem/storage adapters, tests/workplace_files.
Contracts/exports/catalogue AW-00 не редактирую параллельно с Claude.
Другие shared registration/wiring — в отдельном коротком окне после AW-00.
Рабочие данные, пользовательский host и чужие checkout не используются.

## Уже проверено чтением кода

- Existing `workspace.Artifact` имеет version/reference и один provenance_source;
  ID и version сверяются валидатором. Для результата из нескольких входов
  нужен принятый способ хранить полный набор зависимостей без потери оснований.
- Artifact уже зарегистрирован за Owner.CATALOGUE в storage catalogue;
  второй параллельный каталог-владелец не нужен.
- Retention уже имеет DerivedPurger, PhysicalStore и отдельный DeletionLedger;
  файловые derivatives подключаются к этому пути, а не к новому ledger.
- Полные knowledge/project файлы пока не являются готовой реализованной
  областью; существующие Artifact/SourceRef — исходные стыки, не доказательство
  безопасного filesystem.

## Входные требования к AW-00

Уточнить в общем контракте стабильные scope/persona/WORK-or-TEST IDs, ID/версию
управляемого файла, ссылку на содержимое без произвольного host path, полный
набор SourceRef-зависимостей, права/TTL и версионное изменение/квитанцию.
Порт должен позволять атомарно проверить актуальные источники и допуск до
выдачи/сохранения результата; источник этих решений доверенный, не сам скрипт.
Конкретные имена новых DTO/методов выбирает и публикует Claude в AW-00.
Если существующие типы покрывают часть задачи, переиспользовать их.

## Следующее

После integrated AW-00 сверить общий main и реализовать первую управляемую
read/write/version операцию с синтетическими файлами, затем изоляцию/квоты и
негативные path/link/race cases. До появления контракта обходной DTO, API или
дублирующая owner-реализация не создаются.

## Независимая поставка до AW-00

Добавлен private adapter `workspace_files/safe_read.py` и Windows handle helper,
без contracts, migrations, application owner, API и runtime registration.
Чтение SHA-256-named blobs: строгие имена, bounded IO и проверка digest,
отказ на hardlink/reparse/symlink/non-file, закреплённый root. Служебный root
передаёт доверенный владелец, не модель. Это физический примитив, не новая
схема вместо AW-00. Ни сохранение/каталог, ни разрешения им не подменяются.

Реальный Windows тест нашёл ошибку первого варианта: attribute-only directory
handle не запрещал rename. Исправлено на FILE_LIST_DIRECTORY с отсутствующим
FILE_SHARE_DELETE; реальное переименование теперь отклоняется. Конкурентная
запись в открытый файл также закрыта. Не следует ослаблять это до path.resolve().

## Выполненные проверки этой поставки

- Собственный venv из frozen lock/local cache, Python 3.14.8; import path
  проверен на этот checkout. Без скачиваний и изменения dependency files.
  Ссылка uv на общий 3.14 оказалась устаревшей: выбран фактический установленный
  interpreter из metadata уже существующего host venv, не его site-packages.
- Windows `pytest tests/workplace_files`: **20 passed, 3 POSIX-only skipped**,
  0.14 s. Настоящие symlink/hardlink/junction, root rename race, writer denial,
  размер/hash, отсутствие файла, invalid inputs и безопасные ошибки.
- После исправления режима каталога сначала повторены только три затронутые
  Windows handle/junction cases: 3 passed; затем один итоговый небольшой набор.
- Linux Python 3.14.8: **7 native probes passed** в существующем локальном
  образе, без сети/установок; 1 CPU/128 MiB/non-root/read-only и два ограниченных
  назначения (исходники read-only, временный tmpfs). Проверены regular read,
  hardlink, symlink, ancestor link, подмена root перед file open, рост после
  проверки размера и FIFO без writer. Внешний marker остался неизменным.
- Ruff и strict mypy по трём новым source modules: чисто для Windows и Linux
  platform settings. `git diff --check` и просмотр staged diff/новых файлов.

В Linux image не оказалось pytest: первый pytest-запуск завершился до тестов;
вместо установки выполнены короткие stdlib probes. Полный Linux pytest-набор
этим не объявляется пройденным. Первые Windows запуски также упёрлись в
sandbox TEMP/link restrictions; итоговый прогон использует новый каталог в
своём ignored runtime и доступ для создания только синтетических ссылок.
