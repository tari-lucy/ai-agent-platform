# Спецификация панели текстового MVP

**Уточнение оператора 2026-10-23: целевой интерфейс.** Всё обычное общение и
поручения — в родном OpenCode; панель — настройки персонажа, память, права,
расходы, библиотека, диагностика и START/STOP. «Обращения» остаются полноценным
разделом панели с ответами и явной выдачей прав. Панельные чаты/форма поручения
убираются из обычной навигации только после приёмки нового входа; данные и owners
сохраняются. Это план, не сообщение об уже изменённом интерфейсе.
[Граница и переход](30-opencode-user-interface-plan.md), [пакет Claude](agent-tasks/panel-control-claude-pool.md).

Дата: 2026-10-13. Статус: выбранная компоновка для реализации; макеты, браузер
и API ещё не созданы. Семантика операций следует [API](19-api-contracts.md).

## 1. Общая оболочка

Панель открывается только на этом компьютере после операторского входа.
Слева — семь областей; сверху постоянно видны выбранная личность, рабочая
или тестовая память, активный запуск, состояние агента и STOP. Отдельные
управления: пауза деятельности, голос, гейммастер. В текстовом MVP голос
показывает «не подключён»; его управление не имитирует работающий адаптер.

Рабочая область: заголовок/фильтры → основное содержимое → боковая карточка
деталей по выбору. При узком окне карточка открывается отдельно; STOP остаётся
доступным. Интерфейс по умолчанию русский, клавиатурная навигация, контрастные
статусы с текстом, время в выбранной зоне и UTC в технических деталях.
Цвет не является единственным признаком теста, ошибки или допуска.

Запуск и профиль просмотра имеют разные индикаторы. Просмотр другой личности
не меняет запущенную. Для переключения сначала завершить/остановить текущий
экземпляр, затем явно запустить выбранный. Подтверждение нужно для операций
с последствиями: удалить, восстановить, применить откат, расширить права.
Обычное чтение, вводная или допустимая правка не требуют общего окна «вы уверены».

## 2. Экраны и их владельцы

| Область | Основное содержимое | Действия | Владелец/API |
| --- | --- | --- | --- |
| Диалог | Лента реплик, предварительный stream, сохранённый итог; текущая цель/краткое основание/ожидающие дела | Текст, вводная с областью/сроком, новая/законченная сессия | Dialogue, вводные, supervisor; session/messages/operations |
| Персонаж | Канон/стиль, слои, принятая версия, живое состояние; различия редакций | Создать/копировать профиль, проверить проект правки, применить версию | Persona owner; profiles/state/changes |
| Память и люди | Поиск, эпизоды, люди, встречи, отношения, темы и обещания | Открыть источники, исправить, связать подтверждённые аккаунты, экспорт/удаление | Memory/social owners; sources/episodes/people/topics/promises |
| Сюжет и развитие | Обзор, линии, изменения, границы | Интенсивность/пауза GM, решение, исправление интерпретации, откат | Story/development owners; arcs/opportunities/change decisions |
| Лаборатория | Сценарии, изолированная область, шаги/виртуальное время, отчёт | Подать событие, прогнать/остановить, сравнить, перенести настройки явно | Test runner + обычные владельцы в test scope |
| Рабочее пространство | Запуск, подключения, права, ресурсы, задания, ошибки, очереди, backup/restore | Запуск/пауза/STOP/возобновление, настройки, допустимая отмена | Supervisor, registry, operations, lifecycle |
| LLM и расходы | Подключения без секретов, роли/модели, тарифы, токены, попытки, агрегаты | Назначения, версия цены, preview пересчёта, уведомления/лимиты | Provider registry и usage ledger |

Названия ресурсов здесь обозначают семейства операций, не готовые маршруты.
Панель не пишет в БД и не рассылает внутренние события от имени владельца.

## 3. Первый запуск

1. Войти; увидеть состояние служб, локальное хранение и отсутствие активного агента.
2. Выбрать заменяемый [тестовый профиль](22-reference-persona.md) либо создать свой.
3. Проверить несекретные назначения LLM. Ключ/URL настраиваются в локальном
   `.env`; интерфейс показывает только наличие и результат проверки.
4. Без API доступен deterministic mock в лаборатории; он проверяет интерфейсы
   и сбои, но не доказывает качество личности. Реальный вызов запускается явно.
5. Запустить тестовую область, пройти знакомство/повторную встречу/опыт/развитие.
6. Создать отдельную рабочую область, когда оператор готов. Тестовые эпизоды
   не переносятся; перенос выбранных настроек показывает diff и последствия.

Не скрываем нужные зависимости за бесконечным spinner. Недоступный worker,
модель или индекс имеет отдельное объяснение и допустимое действие.

## 4. Детали взаимодействия

**Диалог.** Видны отправлено/сохранено/генерируется/предварительно/завершено/
отменено. При повторе после timeout читается квитанция, не создаётся новый
ответ. После обрыва панели загружается сохранённый итог с признаком неполного
stream. Кнопка STOP доступна во время генерации. Вводная имеет тип, область,
срок, статус и автора; её текст не меняет канон или права автоматически.

**Персонаж.** Редактор показывает определения свойств, пределы автономности
и статичное/живое значение отдельно. Ошибки у полей, diff до применения.
Конфликт версии показывает актуальную редакцию и предлагает пересмотреть
правку; автоматического перезаписывания нет. Новая личность получает новое
состояние/память; копирование опыта — отдельный импорт с происхождением.

**Память и люди.** В поиске фильтры по личности, области, человеку, типу,
периоду и доступности. Карточка: наблюдение/чужое сообщение/гипотеза/
интерпретация, источники, уверенность, конфликт, срок хранения. Для человека
показаны подтверждённые platform IDs, история встреч, темы/вопросы/обещания
и основания отношения; совпадение ника не соединяет людей.

При удалении preview перечисляет исходники, выдержки, сводки, индексы,
кэши, связи и обработку копий. После исполнения видны выполненные и ожидающие
части. Для внешней публикации остаётся отдельный статус удаления у площадки.
Недоступный источник показан явно; он не заменяется выдуманным полным текстом.

**Сюжет и развитие.** Четыре представления следуют
[согласованной вкладке](09-development-oversight.md). Карточка изменения:
до/после, исходный опыт, интерпретация, проверка, решение, границы, ожидаемое
проявление и наблюдённые поступки. Отклонённое испытание не записывается как
случившееся. Откат предлагает новую компенсирующую версию и не стирает опыт.
Запрет истории сразу исключает новые возможности; активная линия показывает
необходимость остановки/пересмотра. Нет отдельного голоса гейммастера.

**Лаборатория.** Каталог включает знакомство, одинаковые ники, обещание,
конфликт фактов, спокойный период, интересную находку, нарушение границы,
обрыв API, STOP, удаление и restart. Seed/часы фиксируются в отчёте.
Реальные модельные вызовы подписаны как платные и учитываются в общем ledger.
Зелёный mock-сценарий не называется проверкой качества LLM.

**Рабочее пространство.** Видны отдельные состояния запуска/деятельности/
голоса/GM, занятые ресурсы, последняя связь/аренда, причины деградации,
дедлайн, попытки и состояние задания. После STOPPING перечислены неподтверждённые
ресурсы; панель не сообщает STOPPED по одному HTTP-ответу. После crash/сна/
restore запуск остановлен и требует явного возобновления.

**LLM и расходы.** Следует [спецификации учёта](16-llm-dashboard.md).
Фильтры: роль/модель/подключение/личность/test или work/период. Отдельно
известные токены, локальные оценки и неполные записи; неизвестная цена не
равна нулю. Валюты не суммируются без явного курса/даты. История показывает
смену назначения и версию тарифа, а не текущую цену для всех прошлых вызовов.

## 5. Состояния и формы

| Ситуация | Что видно | Что допустимо |
| --- | --- | --- |
| Пустая память/нет личности | Объяснение и первая конкретная операция | Создать профиль/сессию, без фиктивных воспоминаний |
| Нет API или назначенной модели | Роль и причина недоступности | Редактирование, mock; реальная генерация выключена |
| Индекс строится/отказал | Полнота, прогресс, точный/FTS fallback | Диалог с явным ограничением recall, повтор конечного задания |
| Модератор недоступен | Public draft ожидает проверки | Приватное чтение разрешённого черновика; публичный выпуск заблокирован |
| Конфликт/устаревший допуск | Версии и причина | Новая проверка/preview, без молчаливого принятия |
| Обрыв WebSocket | Индикатор связи и получение свежей проекции | STOP отдельным HTTP-путём; генерация не повторяется |
| БД/Redis/worker отказали | Раздельные статусы и сохранность последнего результата | Прямой STOP; чтение доступного; новые воздействия ограничены |
| Нет тарифа/usage | «Неизвестно» и источник оценки | Ввести тариф/сверить; без выдуманного счёта |

Формы имеют серверную валидацию, пределы размеров, сохранение проекта,
понятный результат операции и восстановление после ошибки. Клавиатурная
кнопка не обходит полномочия. Markdown/текст участников показываются как
неисполняемые данные; содержимое не задаёт HTML, команды или пути к файлам.

## 6. Проверка готовности экранов

Пройти весь цикл с клавиатуры: вход → профиль → test dialogue → сохранение →
restart → повторная встреча → просмотр источника → допустимое развитие →
отклонение/откат → удаление → LLM ledger → STOP во время зависшего запроса.
Сравнить узкое/широкое окно, пустые/ошибочные состояния и тестовую маркировку.
Проверить чужой Origin/неавторизованное чтение/подписку. Это будущие сценарии
Playwright и ручной приёмки; интерфейс пока не реализован.
