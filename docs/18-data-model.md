# Данные первой версии: сущности, источники и связи

Дата: 2026-10-13. Статус: логическая модель и разделение источников согласованы
в D45 на основе контрактов D44. Физический stack —
[doc20](20-stack-recall-selection.md); SQL-миграции ещё не созданы.
Код, зависимости и реальные личные данные не создаются. Объём — текстовый MVP;
игровые/медиа-данные имеют точки расширения и не требуют полной реализации сейчас.

## 1. Идентичность и область данных

Личность, экземпляр агента, запуск и сессия имеют разные устойчивые ID.
Имя и модель не являются ключом биографии. Новый запуск той же личности
продолжает её память; новая личность получает отдельную область. Создание копии
профиля не переносит биографию автоматически. Все ссылки сохраняют область
рабочего пространства и рабочей/тестовой памяти; тестовые данные изолированы.

Один workspace/активный агент в MVP не требует общего глобального профиля.
Несколько сохранённых личностей используют те же механизмы. Для записей
о людях, отношений, исходных диалогов и источников права проверяются отдельно
от совпадения идентификаторов. Общий ID собеседника не даёт доступ к чужой истории.

Каждый тип записи имеет владельца из [контрактов](17-module-contracts-state.md),
версию схемы, ID, область, время создания/изменения и необходимые ссылки.
Для изменяемого состояния добавляется версия; для значимого результата —
причинная связь/доказательства. Исправление создаёт новую редакцию; удаление
личных данных — отдельная операция, которая может удалить содержимое старых
редакций и производных представлений. Версионирование не делает текст вечным.

## 2. Основные группы сущностей

Имена условные; несколько сущностей могут физически оказаться в одной таблице
или разных хранилищах. Общая форма платформы фиксирована, поля конкретных
характеров, целей и инструментов задаются версионируемыми схемами расширений.

| Группа | Главные данные и связи | Владелец / назначение |
| --- | --- | --- |
| Рабочее пространство | ID, настройки, версии политик, пути/квоты, разрешённые подключения | Сервис workspace / общая область |
| Личность и версии профиля | ID личности, описание, стиль, схема слоёв, границы, начальные значения, принятая версия | Сервис персонажа / канон и правила развития |
| Состояние персонажа | Версия профиля и состояния, текущие свойства/состояния, ID применённых изменений | Сервис персонажа / текущая личность после опыта |
| Экземпляр, запуск и сессия | ID личности/области памяти, новый ID запуска, поколение управления, режим, состояние, время | Supervisor / запуск и отмена |
| Подключения и возможности | ID адаптера/версии, схема операции, capabilities, параметры, ссылки на локальные переменные окружения | Workspace / настраиваемые инструменты, без значений секретов |
| Исходные записи | Тип/источник, время, внешний ID при наличии, автор и уверенность идентификации, происхождение, текст/ссылка, срок хранения | Сервис памяти / доказательства сказанного или наблюдаемого |
| Эпизоды опыта | ID сессии, источники, выбор/действие, подтверждённый исход, собственная интерпретация отдельно от наблюдения | Сервис памяти / прожитое в своей области |
| Факты и утверждения | Субъект, содержание, тип знания, источники/уверенность, версии, противоречия, область доступа | Сервис памяти / факты, сообщения людей и гипотезы различаются |
| Сводки и фрагменты | Период/эпизоды, удержанные выдержки, ссылки на сохранившиеся источники, версия/автор анализа | Сервис памяти / долговременная непрерывность и RAG |
| Люди и встречи | Внутренний ID, привязки аккаунтов с подтверждением, встречи и участники | Социальная память / узнавание без объединения по нику |
| Отношения | Личность, область памяти, собеседник, настраиваемые аспекты/версии, основания изменений | Социальная память / отношения конкретного персонажа |
| Темы, вопросы и обещания | Собеседник/участники, смысловая тема, резерв обращения, статус ответа/доставки, срок, основания закрытия | Социальная память / продолжение разговора и обязательств |
| Сюжетные линии и возможности | Источники, направление/границы, статус линии, предложение/выбор/исход, cooldown/история повторов | Гейммастер / предложение отличается от опыта |
| Рефлексия и изменения | Проанализированные эпизоды, версия, интерпретация, адресат-владелец, до/после, статус/проверки/решение | Анализ — рефлексия; применение — соответствующий владелец |
| Цели, команды, задания и попытки | Основание, ID операции, аргументы/ссылки, условия завершения, статус, deadline, аренда, результаты | Контроллер/владелец задания; попытка отделена от смысловой цели |
| Реплики, редакции и доставки | Один ID реплики, текст/медиа-редакция, аудитория, проверки, статусы каждого канала, внешние ID | Шлюз/адаптеры; социальные последствия фиксирует социальная память |
| Политики, проверки и допуски | Версии правил, конкретная редакция/действие, результат модератора, область, срок, решение оператора | Политика / модерация / шлюз с разными полномочиями |
| LLM-задания и расходы | Роль/назначение, запрошенная/сообщённая модель, попытка, usage/полнота, время, версия тарифа, расчёт | Служба LLM / отдельный дашборд |
| Каталог артефактов | ID файла, тип, локальная ссылка, checksum, размер, происхождение, срок/защита, связи с эпизодом/проектом | Каталог владельца медиа / ссылки вместо копий в событиях |
| Outbox, обработанные операции и история переходов | Причинные ID, версия/статус доставки, ключ дедупликации, минимальная трасса | Владелец состояния / восстановление без повторного эффекта |

Роли LLM и имена свойств профиля конфигурируются; платформе не требуется
фиксированный список эмоций, отношений или игровых команд. Общие ID/версии/
области и статусы остаются проверяемыми, а расширяемые данные имеют схему
и предел размера. Произвольный JSON не заменяет проверку владельца/источников.

## 3. Авторитетные источники и представления

| Вид данных | Согласованный авторитетный источник | Другие представления |
| --- | --- | --- |
| Канон, стиль, схема свойств/границы | Проверенный snapshot принятого локального Markdown/параметров профиля | Редактор панели; читаемый исходник |
| Текущее состояние, отношения, обещания, задания, допуски и расходы | Точная структурированная БД соответствующих владельцев | Проекции панели и экспорт |
| Разговоры/наблюдения, удержанные фрагменты | Каталог и разрешённый архив источников | Эпизоды, сводки, поиск |
| Дневник и обзор биографии | Записи с источниками; автоматически созданный дневник — представление этих записей | Markdown для чтения/экспорта |
| Поисковые фрагменты/векторы | Разрешённые сохранившиеся источники | Заменяемый производный индекс |
| Аудио, снимки, видео | Файлы и каталог артефактов | Ссылки в памяти/проектах |

Выбрана SQLite для точных записей; FTS5/sqlite-vec — baseline recall,
MemPalace — comparative adapter, LightRAG — последующий knowledge tool.
[Выбор и пробы](20-stack-recall-selection.md) не требуют серверной БД или локальной LLM.
Redis доставляет задания; он не становится единственным архивом памяти/расходов.

Возможное размещение MVP: БД/профили/архив обслуживает core, worker получает
задания и сдаёт результаты через владельцев. Worker не монтирует живую БД
для самостоятельной записи в чужие области. Конкретный локальный протокол
и размещение индекса выбираются при проектировании API/проверке стека.

## 4. Профиль и развитие

Принятая версия профиля задаёт канон, свойства, исходные значения, стиль,
границы и правила развития. Живое состояние содержит результат применения
опыта и ссылается на этот профиль. Правка Markdown предлагает новую версию
профиля; она не сбрасывает накопленные отношения/привычки молча. Изменение
схемы или пределов показывает конфликт и нужную миграцию/решение оператора.

Изменение связывает доказательства, базовую версию, конкретную правку,
проверки, автора/роль и ожидаемое проявление. Применение создаёт новую версию
у владельца; откат создаёт следующую запись с зависимостями. Изменения разных
владельцев связаны причинно, но не объявляются одной общей транзакцией.
Редактирование отношения через панель использует те же проверки версий.

Утверждение пользователя о прошлом, операторский канон, вымысел гейммастера
и наблюдённый опыт имеют разные происхождения. Импорт дневника/Markdown
сохраняет это различие и не создаёт подтверждённую встречу или обещание
из любого прочитанного предложения. Значения секретов в профиль не входят.

## 5. Люди, обещания и история выходов

Привязка аккаунта хранит площадку и подтверждённый ID, а отображаемый ник —
изменяемый атрибут. Связывание аккаунтов разных площадок требует основания;
неуверенная связь остаётся гипотезой. Тестовый человек не объединяется с рабочим.
Подтверждённое объединение/разделение пересматривает зависимые встречи/
отношения и сохраняет историю исправления; имя человека не служит ключом.

Отношения принадлежат сочетанию личности, области памяти и собеседника.
Встречи и реплики имеют ID; голос и чат одной реплики не удваивают опыт.
Тема вопроса, ожидаемый ответ и резерв обращения хранятся точно, независимо
от задержки RAG. Открытое обещание ссылается на подтверждённый выход,
участников, содержание, срок при наличии и критерий выполнения. У него
отдельный статус; удаление полного разговора не означает выполнение обещания.

Редакции реплик и проверки привязаны к конкретному содержанию/аудитории.
Доставки хранятся отдельно для каналов, включая частичный/неизвестный исход.
Рабочие посты, монтажные проекты и медиа имеют собственные ещё открытые
правила хранения; 30 дней текста не задают им срок автоматически.

## 6. Сроки, удаление и восстановление

Полный текст разговора хранится 30 дней; затем остаются значимые фрагменты
и сводки по согласованной политике. До сокращения формируются допустимые
фрагменты и обновляются ссылки долговременных записей. Если основание
удалено и замены нет, запись показывает отсутствие источника; система
не делает вид, что полный разговор по-прежнему доступен.
Если консолидация не завершилась вовремя, ошибка видна; исходный текст
не получает бессрочного продления. Уже сохранённые точные обещания/ответы
остаются доступными, а утраченная часть источника отмечается явно.

Долговременный эпизод, обещание и связь с человеком не являются скрытой
бессрочной копией всего текста. Сводки сохраняют атрибуцию/неопределённость,
а известный ответ и тема вопроса не исчезают только из-за истечения сырого текста.
Отдельный запрос на удаление учитывается независимо от возраста записи.

Удаление/исправление затрагивает исходники, выдержки, сводки, индексы, кэши
и ещё ожидающие контексты/изменения по зависимостям. Поисковый индекс можно
перестроить из оставшихся разрешённых источников. Права чтения, передачи
в API и публичного раскрытия проверяются отдельно; доступ в панели не
разрешает автоматически включить запись в публичную реплику.

Отладочные логи: 14 дней и квота. Точная финансовая история/агрегаты имеют
отдельную политику doc23: metadata 90 дней, агрегаты 12 месяцев; дашборд не исчезает вместе
с логами. Она не требует полных prompt/ответов. Сроки технических квитанций,
ключей дедупликации и истории версий задаются с учётом окна восстановления
и срока повторной доставки, без бессрочного копирования приватных данных.

Резервирование связывает согласованную копию БД, принятые профили и каталог
артефактов. Восстановление учитывает позднейшие удаления; индекс перестраивается
из разрешённых источников. Механизм совместимой копии остаётся отдельной
проверкой до реализации; копирование работающих файлов не считается готовой стратегией.

## 7. Версии, повторы и расходы

Команда правки указывает ожидаемую версию. Конфликт возвращает текущую версию
и понятную причину; исходная правка не перетирает новый опыт. Повтор логической
операции/применённого изменения возвращает известный результат. У источников
с внешним ID проверяются источник и область; один только ник/совпадение текста
не подтверждает, что два реальных события являются одним событием.

Для применения изменения состояние, версия и outbox фиксируются владельцем
согласованно. Индекс/Markdown-представление обновляются повторяемым заданием;
их отставание видно и не меняет авторитетное состояние. Проект не требует
журнала всех кадров/порций streaming как постоянного источника всей системы.

Учёт LLM отделяет смысловое задание от попыток. Назначение роли и тарифная
версия относятся к конкретной попытке; usage провайдера и локальная оценка
различаются. Реальный повтор учитывается, повтор квитанции — нет.
Незаполненный тариф или отсутствующий usage оставляют неизвестную сумму.
Поздняя финансовая сверка после STOP не меняет допуск действий. Подробности
редактора тарифов и валют — в [плане дашборда](16-llm-dashboard.md).

## 8. Проверки будущей реализации

Проверить: повтор входного сообщения/квитанции; два параллельных вопроса;
смену ника и ошибочное связывание аккаунтов; изоляцию личности/тестов;
истечение 30 дней при открытом обещании; удаление источника до применения
изменения; правку профиля после рефлексии; отставание индекса; перезапуск
после коммита и до доставки outbox; месячные расходы после очистки логов;
восстановление копии после позднейшего удаления. Испытания ещё не выполнялись.

### Источники нового события и контекст — 2026-10-19

`Episode.sources` сохраняет все зависимости ответа, включая справочную историю,
для повторной проверки прав, версий, TTL и удаления. Необязательный
`experience_source_ids` — уникальное подмножество этих ссылок, указанное владельцем
для источников самого события. Приватный диалог заполняет его текущей входящей
репликой и подтверждённым собственным ответом. Контекст из прежних бесед при этом
не становится новым независимым основанием. Собственный ответ остаётся производным.

Группировка независимого опыта и recall используют это подмножество. Общий первичный
источник по-прежнему объединяет пересказы; минимум оснований, диапазоны и бюджет
развития не ослабляются. Старые эпизоды без поля сохраняют прежнюю консервативную
группировку по всем sources; старые данные автоматически не переинтерпретируются.
Новое поле не выдаёт доступа: все sources остаются зависимостями состояния и
проверяются владельцем. Миграция таблиц для необязательного JSON-поля не требуется.
