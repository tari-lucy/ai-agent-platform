# Спецификация последующих интеграций

Дата: 2026-10-13. Статус: запланированные границы, начальные кандидаты и
приёмка после текстового MVP. Реальные интеграции не подключены. Exact versions,
устройства, модели и права уточняются на входе соответствующего эпика F из
[списка задач](24-mvp-implementation-plan.md).

## 1. Общий договор адаптера

Входные наблюдения имеют источник, время, внешний ID, scope и уверенность.
Нормализация не выдаёт частичный обзор мира за полное знание. Исходящая команда
имеет capability/binding/resource lease, epoch, deadline, проверенный результат
и cancel. Адаптер возвращает принято/исполняется/выполнено/ошибка/неизвестно;
не пишет канон или отношения напрямую. Disconnect освобождает управление,
reconnect не повторяет эффекты без сверки.

Ресурсы: игровой ввод, физический аудиовыход, VTS-параметры, эфир, канал,
рендер. У каждого один текущий владелец и приоритет ручного управления.
Модули речи/движения/игры/аватара продолжают работать независимо в рамках
своих допусков; задержка одного не блокирует аварийную остановку остальных.

## 2. Голос F1

Маршрут: capture → VAD/segmentation → STT → проверенное входное событие →
диалог → точная редакция → модерация при публичной аудитории → TTS → playback.
Вход от оператора, игрока и зрителя имеет разные источник/атрибуцию/полномочия.
Speaker recognition не считается подтверждением личности без надёжной привязки.

| Компонент | Стартовый выбор/кандидат | Контракт/проверка |
| --- | --- | --- |
| Capture/playback | Нативный Windows audio bridge | Stable endpoint IDs, отдельные потоки mic/game/agent/monitor, volume/mute/cancel |
| Локальный STT | faster-whisper, CPU int8; small как первая проба RU | Модель/latency/RAM выбираются по шуму и совместной нагрузке, GPU опционален |
| STT API | Заменяемый transcription adapter | Формат/язык/attribution, timeout/отмена, политика внешней передачи аудио |
| Локальный TTS | Piper как первый CPU-кандидат в отдельном runtime | RU voice/model card, права использования, естественность и задержка — gate до выбора голоса |
| TTS API | Заменяемый synthesis adapter | Voice binding, формат/rate, chunk cancel, data disclosure; провайдер не зашит |
| Voice profile | Конфигурация голоса/произношения/манеры | Разные реализации могут звучать по-разному; переключение видно оператору |

faster-whisper использует CTranslate2 и показывает CPU int8; GPU-совместимость
зависит от конкретных CUDA/cuDNN/пакетов. Наличие CUDA 12.9 на Windows не
доказывает готовность Linux image или CPU voice bridge.
[faster-whisper](https://github.com/SYSTRAN/faster-whisper).

Текущий Piper — GPL-3.0; его код и конкретный голос требуют отдельных notices/
проверки условий распространения. Не считаем все скачиваемые голоса свободными
для любого эфира. До выбора разрешённого голоса кандидат не становится
готовым voice preset. [Piper](https://github.com/OHF-Voice/piper1-gpl).

Обязательная матрица: local STT/local TTS; local STT/API TTS; API STT/local TTS;
API STT/API TTS. Offline режим может вести локальные STT/TTS, но при API LLM
не обещает полноценный автономный разговор без сети. Fallback между голосами
явный/разрешённый; большой GPU-моделью система сама себя не заменяет.

VB-CABLE — выбранный физический маршрут после проверки endpoint IDs.
Simple Voice Chat требует отдельного игрового пути/совместимого клиента;
наличие виртуального кабеля не гарантирует передачу голоса на сервер.
Не захватываем собственный TTS как новую речь участника. Barge-in зависит
от политики; публичная речь отменяется и освобождает очередь на STOP/mute.
Субтитры/lip sync опираются на фактическое воспроизведение, а не готовность
синтеза. Raw audio по умолчанию удаляется после обработки.

## 3. Minecraft F2

Fabric client bridge управляет именно запущенным игровым персонажем оператора.
Основной канал — структурированные client-side события/доступное состояние;
изображение/скриншот дополняет его при необходимости. Серверный мод не обязателен.
Версии Minecraft/Loader/API/Simple Voice Chat/JDK фиксируются по реальному
экземпляру; скриншот списка модов их не определяет.

Восприятие: position/dimension/world/server, доступные блоки/объекты/события,
видимые игроки, chat, ограниченная карта посещённого и наблюдаемые изменения.
Scope сервера/мира обязателен; недоступные/незагруженные области неизвестны.
Игрок привязывается к проверяемому идентификатору конкретного подключения;
перенос идентичности между разными серверами не предполагается автоматически.

LLM выбирает исследование/следование/разговор и смысловую цель. Навигационный
исполнитель строит локальный путь и держит задачу без LLM на каждом тике.
Первый набор: двигаться к допустимой точке, следовать в диапазоне дистанции,
остановиться, осмотреть/исследовать достижимую область. Строительство,
бой/разрушение, торговля и управление inventory — отдельные capabilities,
не подразумеваются разрешением двигаться.

Застревание определяется по прогрессу/скорости/повтору позиции/маршрута и
deadline, с учётом ожидания/объектов мира. Recovery: снять ввод → коротко
отступить/сменить локальную точку → перестроить путь → отказаться от цели
и сообщить. Начальный лимит 3 recovery попытки за задачу, до 20 секунд
каждая, затем cooldown цели; параметры зависят от среды. Прыжок не является
постоянным способом восстановления. Опасные действия не разрешаются recovery.

Manual takeover немедленно отзывает lease ввода; adapter снимает удерживаемые
клавиши при STOP/disconnect/crash/heartbeat loss. Начальный heartbeat 0,5 с,
lease ввода 2 с, проверяются в игровой пробе. Видимая панель/локальная клавиша
остановки остаются доступны без модельного решения.

Перед каждым чужим сервером: правила автоматизации/ботов/клиентских модов,
съёмки и голосового взаимодействия, доступные возможности и точный binding.
Первый прогон — локальный мир/разрешённая среда, затем допущенный сервер.
Не планируем обход античита, скрытую автоматизацию или сбор недоступных данных.

Приёмка: лестница/дверь/яма/низкий потолок, потеря пути, движущийся игрок,
disconnect/dimension change, ручное управление, соседние игроки/повторная
встреча, ограниченная инициатива и совпадающие имена.

## 4. VTube Studio F3

Отдельный WebSocket adapter, штатная авторизация plugin, health/reconnect;
секрет binding хранится локально. Mapping из профиля rig: параметры,
диапазоны, expressions/hotkeys, приоритеты и neutral state. Cubism Editor
служит подготовке rig, не является обязательным runtime-контроллером.
VTS API позволяет подавать параметры, переключать модели/выражения и получать
события. [VTube Studio API](https://github.com/DenchiSoft/VTubeStudio).

Emotion state не копирует поток LLM напрямую в каждую facial-команду.
Микшер выражений ограничивает частоту/амплитуду, учитывает приоритеты ручного
управления, реальную речь и взгляд. Mouth envelope/visemes берутся из
фактически воспроизводимого аудио; при отмене/обрыве возвращаются к neutral.
Переподключение не повторяет давний hotkey. Смена модели перепроверяет mapping.

## 5. Эфир и аудитория F4

OBS через obs-websocket: scene, source mute, record/stream status, markers и
явные команды. Начало/конец эфира — отдельные операторские действия;
STOP персонажа не выдаётся за завершение эфира.
[obs-websocket](https://github.com/obsproject/obs-websocket).

Входы Twitch/YouTube нормализуются в общий social event: platform IDs,
channel/thread/message, автор/время, edit/delete и дедуп. Twitch EventSub и
YouTube liveChat API подключаются с реальными OAuth scopes/квотами; доступный
streaming live chat не следует путать с LLM streaming.
[Twitch EventSub](https://dev.twitch.tv/docs/eventsub/),
[YouTube streamList](https://developers.google.com/youtube/v3/live/docs/liveChatMessages/streamList).

Приоритеты/агрегация сообщений ограничивают нагрузку; обязательная модерация
и важное обращение не вытесняются бесконечным chat backlog. Зритель не получает
operator role. Собственная отправка и её echo не являются новыми сообщениями
человека. Комментарии после эфира/под публикацией продолжают ту же память.

Публичный gate охватывает точную речь/текст персонажа и медиа. Отдельно
планируется чужой голос, игровой chat overlay, usernames/приватные координаты,
видеокадр и music rights: проверка собственной реплики не модерирует весь
сигнал OBS. Default до настройки — отключённый чужой audio/непроверенные
overlays, приватная репетиция. Для full live path выбрать буфер/задержку,
mute/blanking/emergency scene и допустимую деградацию. Нельзя обещать
предварительную проверку каждого игрового кадра обычной text LLM.

До выпуска уточнить применимое право/территории, аудиторию, disclosure AI,
данные участников и актуальные правила площадок; ЕС/США/СНГ/РФ не являются
одним policy pack. Отдельная модель снижает риск, но не гарантирует законность.
Точная матрица норм/решений фиксируется до реального публичного выхода.

Одновременный YouTube/Twitch требует выбора uplink/encoder/multistream route,
битрейта и проверки действующих условий площадок. OBS command сама этого
не обеспечивает. Приёмка начинается с закрытого прогона и замера CPU/RAM/
VRAM/задержки/пропускной способности при совместной игре/аватаре/голосе.

## 6. Telegram и иллюстрированные посты F5

Capture выбирает интересное место по событию/оценке, соблюдая screenshot
cooldown (начально 60 с) и квоту. В metadata: мир/место/эпизод/время,
участники/видимость/правила, original/preview и происхождение подписи.
Нельзя выдавать гипотезу или постановочное событие лаборатории за реальную находку.

Post pipeline: подтверждённые эпизоды → draft текста и выбранные изображения →
редактура/приватность/права → moderation exact text+media revision → preview →
операторский выпуск → квитанция/внешний ID → собственная публичная история.
При timeout неизвестный результат сначала сверяется; draft не публикуется
вторично слепым retry. Поправка/удаление публикации имеют отдельный статус.
[Telegram Bot API](https://core.telegram.org/bots/api).

Комментарии читаются из доступных обсуждений/веток с правами бота. Пост
и исходный эпизод — связанные источники одного опыта; комментарий — новый
опыт общения. Отдельный approval на пост не включает автономные ответы от
канала. Расширение прав оформляется позже конкретным binding/action.

## 7. Монтаж F6

Отдельный интерфейс проекта и render pipeline. Минимум: ingest записей/
скриншотов, markers по событиям, выбор отрезков, trim, последовательность,
простой переход, subtitle corrections, уровни речи/музыки, preview и export
preset. Это конечный набор операций, не универсальный профессиональный NLE.

Project хранит JSON EDL с версиями, исходными asset IDs, timebase/trim/track/
subtitle/level, export settings. Монтаж не разрушает originals; источники,
используемые проектом, protected. LLM предлагает структуру/таймкоды,
оператор правит. Render worker получает валидированную EDL; аргументы
FFmpeg строятся из allowlist, без shell string, произвольного пути или
текстовой команды модели. ffprobe проверяет входы; progress/cancel/error
и нехватка диска показываются в UI.

FFmpeg build/кодеки имеют свои лицензионные условия: версия и build flags
включаются в инвентарь. [FFmpeg legal](https://ffmpeg.org/legal.html).
Рендер по умолчанию не идёт одновременно с реальным эфиром на этом ноутбуке;
разрешить совмещение можно после замера. Export не означает upload/publication.
Перед публичным размещением итоговый файл проходит отдельный release gate.

## 8. Что требуется на входе эпиков

| Эпик | Данные оператора / проверка | До появления данных |
| --- | --- | --- |
| F1 | Язык/голос, права voice assets, API bindings, endpoint IDs, capture rules | Контракты/mock и CPU-пробы, без реальной записи участников |
| F2 | Exact Minecraft/Fabric/voicechat/JDK, сервер и правила | Игровой bridge проектируется и проверяется локально |
| F3 | Live2D rig/model rights/параметры и VTS разрешение | Mapping schema/mock, без обещания движения конкретной модели |
| F4/F5 | Реальные каналы/scopes/bot rights, право/аудитория, public safety path | Только приватные draft/rehearsal; секреты в `.env` |
| F6 | Формат записей, export preset, licensed music, disk budget | Тестовые media fixtures, non-destructive editing |
| F7 | Реальные сценарии нескольких активных персонажей | Один активный экземпляр; разработчики могут работать параллельно независимо от этого |

Эти данные не мешают завершить нынешнее планирование. Они не подменяются
догадками и не требуют сейчас ключей, доступа к каналам или нового железа.
