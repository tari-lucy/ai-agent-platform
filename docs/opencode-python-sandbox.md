# Python-песочница: как дать персонажу разобрать архив

Python работает в отдельном Docker-контейнере без сети. Персонаж пишет скрипт,
получает выбранные файлы через владельца хранилища и возвращает отчёт в свою
файловую систему. Это не доступ к диску Windows и не запуск загруженного JAR.

## Что нажать

1. Откройте панель → **Обращения**. Найдите технический запрос на возможность
   `workplace.scripts` (на подготовленном запуске — «Разрешить Python-песочницу»).
2. Нажмите **Разрешить…**. Проверьте возможность, срок и области.
   Для загруженного архива и отчёта нужны как минимум `inbox` и `projects`.
   Уровень — **автоматически**; срок не больше потолка хоста.
3. Посмотрите план и подтвердите выдачу доступа. Это одно разрешение на
   возможность в выбранных областях и на выбранный срок, а не на каждую реплику.
   Оно не запускает агента.
4. Нажмите **START**, откройте свой разговор в OpenCode и напишите, например:

   > Разбери ранее загруженный архив в inbox. Не исполняй код архива. Сначала
   > посмотри состав, затем прочитай нужные небольшие метаданные через Python
   > zipfile. Учитывай размеры записей и не распаковывай всё без необходимости.
   > Сохрани понятный отчёт в projects и сообщи путь к нему.

5. Результат откройте в дереве файлов OpenCode → `projects`.
   Уже загруженный файл заново прикладывать не требуется.

Если обращение ещё не создано, попросите персонажа использовать Python-песочницу:
без права он должен запросить его обращением. При ошибке проверьте код в панели;
не выдавайте доступ к сети или компьютеру ради разбора ZIP/JAR.

## Ограничения

- Доступны Python и стандартная библиотека образа. Java-декомпилятор,
  сторонние пакеты и распознавание сканов автоматически не появляются.
- Размер загружаемого файла и размер входа скрипта — разные ограничения.
  Передача входа сейчас целиком в памяти (base64); пик памяти хоста может
  достигать примерно 3–4 размеров входа.
- Контейнер ограничен по времени, CPU, памяти, числу процессов, входам и выходам.
  **STOP** отзывает допуск и останавливает контейнеры. Поздний результат не
  сохраняется. Неизвестный исход скрипта не запускается заново автоматически.
- Скрипт, навык и текст разговора не выдают новых прав. Если средств не хватает,
  персонаж просит помощь через обращение.

## Для настройки запуска

При остановленном сервере используйте `enable-work-sessions --helper` с
проверенным helper-образом и явными лимитами. Пропущенные параметры сохраняют
предыдущие настройки. `--no-helper` отключает подключение; отсутствие флага
сохраняет состояние. Команда не выдаёт Permission.

Для обновления только доверенного harness поверх уже имеющегося pinned-образа:

```text
python scripts/refresh_opencode_harness.py --base-image sha256:<64 hex> --tag ai-agent-platform:opencode-helpers
```

Скрипт использует локальные слои и копирует только три доверенных модуля,
проверяет исходный образ и префикс его слоёв в результате. Зависимости и модели
не устанавливает, личное хранилище не монтирует. Полученный immutable image ID
укажите в `enable-work-sessions`. Старый образ остаётся доступен.
