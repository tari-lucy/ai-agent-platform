# Переезд платформы и Опечатки на сервер

План 2026-10-30, предложение на утверждение оператора. Основа — [doc33](33-harness-owns-the-turn.md).
Цель оператора: чтобы личность жила, когда комп выключен. Реализует Claude Code (сервер),
Codex проверяет приёмку; Windows-сторона (запуск, туннели) остаётся у оператора и Codex.
Адреса серверов, ключи и пароли в Git не пишутся: это локальные настройки оператора.

## 1. Куда переезжаем

Сервер `srv-213`: KVM, 4 ядра, 5,8 ГБ памяти, диск 40 ГБ, Ubuntu, Docker и Compose.
На нём уже работает стек n8n (7 контейнеров, нагрузка спокойная). Подготовка 2026-10-30:

| Что | Было | Стало |
| --- | --- | --- |
| Свободно на диске | 11 ГБ | 15 ГБ (чистка кэша сборки) |
| Лимиты памяти n8n-стека | нет | транскрайбер 2 ГБ, browserless и n8n 1,5 ГБ, postgres и qdrant 1 ГБ, shotter 0,75 ГБ, прокси 0,5 ГБ |
| `vm.swappiness` | 60 | 10 |
| Своп | занят 1,9 из 2 ГБ | свободен 1,74 из 2 ГБ (перезапуск транскрайбера) |

Лимиты `docker update` слетают при пересоздании контейнеров (`compose up`): для постоянства
нужны `mem_limit` в compose n8n. Доступно после этого около 4,5 ГБ памяти и 15 ГБ диска.

Бюджет памяти Опечатки: контейнер агента 3 ГБ (`memory_mb`), платформа и шлюзы около 1 ГБ.
Это впритык: сборки мода идут в пределах лимита, а не пока не упадёт. Запас по диску тоже
небольшой, большие кэши (`.gradle`) чистим по расписанию. Если станет тесно, правильный
шаг — отдельный сервер, а не новые лимиты.

## 2. Что переезжает и что остаётся

| Часть | Решение |
| --- | --- |
| Платформа (`serve`), шлюз модели, egress, контейнер агента | Переезжают. Работают как служба пользователя на сервере |
| Данные хоста (`platform.sqlite`, память, права, обращения, будильники, журналы) | Через штатные резервную копию и восстановление (`finish-restore`), не копированием файлов |
| Папка `/workspace` (проекты, навыки, GOALS.md, DIARY.md) | Копируется целиком |
| Том `/persist` (сессии OpenCode, навыки `--user`) | Копируем `.harness/data`, `.local`, `.npm-global`. Кэши сборки (`.gradle`) не переносим, они пересоздадутся |
| Образ агента | Собирается на сервере (`scripts/build_opencode_sandbox.py`, закреплённый архив с проверкой SHA-256). Новый ID образа записывается в настройки |
| Ключи (модель, Telegram, Soniox) | Новый локальный `.env` на сервере, пишет оператор. Через чат не передаются |
| Telegram-прокси через сервер | Не нужен: Telegram оттуда доступен напрямую. Docker-туннель на компе отключается после приёмки |
| Minecraft с модом | Остаётся на компе (см. §5) |

## 3. Подготовка сервера (один раз)

1. `uv` и Python 3.14 в профиле пользователя (без прав администратора).
2. Клон репозитория, зависимости из блокировки (`uv sync --locked`). Сборку панели (нужен Node) делаем на другой машине и копируем `apps/panel/dist`.
3. `sudo loginctl enable-linger <пользователь>`: без этого служба пользователя останавливается при выходе из ssh.
4. Папка агента принадлежит пользователю контейнера (uid 65532) или имеет ACL для него: один раз `sudo setfacl`/`chown`. Иначе агент не сможет писать в `/workspace`.
5. Новых публичных портов не открываем. Панель (8765) и OpenCode (4096) слушают только `127.0.0.1`.
6. Образ агента и проверка `docker run` без сети, проверка лимитов.

## 4. Перенос (окно один раз, платформа на компе в STOP)

1. STOP на компе. Резервная копия и её проверка (`verify`) штатными средствами панели.
2. Копия, папка агента и выбранные части тома едут на сервер по защищённому каналу. Промежуточные копии на любых машинах после проверки удаляются.
3. На сервере: восстановление (`preview`, затем `restore`), затем `finish-restore` (предпросмотр и применение). Платформа поднимается **только в STOPPED**.
4. Новый `.env`, `configure-harness` под сервер (`files_dir`, порты, цены, канал, голос, `life_mode`), образ и проверка конфигурации (`enable-work-sessions` с новым ID образа).
5. Первый запуск без START: панель отвечает, обращения и память на месте, секретов нет в журналах.
6. Пробный START в режиме «тихая». Проверка по §6.

Платформа на компе после переноса не запускается, пока приёмка не закончена: **две платформы
на одну личность одновременно запрещены** (два писателя памяти, два владельца будильников и
Telegram-токена).

## 5. Доступ с компьютера, файлы и игра

- **Панель и OpenCode:** ssh-туннель с компа на `127.0.0.1` сервера (порты 8765 и 4096),
  один ярлык Windows. Пароль OpenCode и вход в панель остаются.
- **Папка агента:** Syncthing между сервером и компом или SFTP-диск. Решает оператор (§8).
- **Игра:** мод слушает порт на компе. С сервера до него нужен обратный туннель комп → сервер.
  Но контейнер агента ходит к «хосту» по адресу `host-gateway`, а это docker-мост сервера, не
  `127.0.0.1`. Нужен слушатель на мосту (настройка sshd `GatewayPorts` с правами администратора)
  либо маленький ретранслятор. Открывать порт всем сетевым интерфейсам не будем.
  Пока этого нет, Опечатка играет только в рамках компьютера: решаем отдельным пакетом.
- **Картинки:** вход ChatGPT делается на сервере кодом (`codex login --device-auth`), токен
  лежит на хосте, не в контейнере. Страна сервера — Казахстан: пустит ли вход, покажет сам вход.

## 6. Приёмка (Codex, Linux/Docker)

START и STOP с первого нажатия, контейнеры и сети убираются; файлы из папки агента;
память и повтор разговора без дублей; будильник и слот ритма (`life_mode`); пост в канал
текстом и голосом (с проверкой и лимитом); отказ шлюза при исчерпании бюджета; перезагрузка
сервера: платформа поднимается STOPPED и ничего не запускает сама; нехватка памяти (OOM)
не уносит n8n.

## 7. Эксплуатация

- Служба пользователя с автоперезапуском. После перезагрузки сервера личность остаётся в
  STOPPED до START оператора (правило проекта). Оповещение «платформа перезапущена» — отдельный
  пакет.
- Резервные копии: суточная на сервере, раз в неделю копия на другую машину (не на тот же диск).
- Журналы с ротацией, учёт диска и памяти раз в сутки, порог по месту на диске.

## 8. Решения оператора до начала

1. Папка агента: Syncthing или SFTP-диск?
2. Игра через обратный туннель: делаем сразу или после переезда?
3. Куда копировать недельную резервную копию?
4. Согласие на `sudo`-шаги из §3 (одноразовые команды, которые вводит оператор).
5. Время окна переезда.

## 9. Откат

До приёмки компьютер остаётся рабочим: остановить платформу на сервере, запустить на компе.
Данные на компе не менялись. После приёмки откат — обратным восстановлением из свежей копии с
сервера. Серверные настройки n8n (лимиты, swappiness) откатываются независимо:
`docker update --memory 0 --memory-swap -1 <имя>` и удалением `/etc/sysctl.d/99-swappiness.conf`.

## 10. Риски

Тесная память (§1); Python 3.14 и образ собираются впервые на этом сервере; неофициальный
вход ChatGPT; игра без туннеля недоступна; секреты на сервере требуют прав `0600` и резервной
копии вне диска сервера.
