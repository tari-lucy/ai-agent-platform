# Claude: панель управления без второго чата

Дата: 2026-10-23. Основание: D67, [doc30 §1.1](../30-opencode-user-interface-plan.md).
Статус: подготовленный пакет для передачи Claude. Эта запись не объявляет код
реализованным и не занимает окно ещё выполняемой задачи. Сначала закончить
текущее поручение, затем сверить свежий origin/main и назначения ниже.

## Продуктовый результат

OpenCode — единственное обычное окно общения и поручений для выбранного агента,
с его личностью, памятью и сессиями. Панель — управление платформой и наблюдение.
Обращения остаются полноценным разделом панели: оператор читает, отвечает,
закрывает, отказывает или явно выдаёт права. Это не второй чат с моделью.
Новая возможность/помощь/проблема/идея создаёт тикет; обычная реплика и действие
в пределах начального допуска не создают новую заявку на разрешение.

Использовать уже принятую tickets-UX и проекцию прогресса, не переписывать их.
Если критерий уже выполнен, подтвердить его существующей проверкой и описать
минимальный оставшийся diff. Не добавлять новую абстракцию ради таблицы задач.

## Задачи и порядок

| ID | Зависимости | Работа и приёмка |
| --- | --- | --- |
| PUI-01 | актуальный main; свободное окно оболочки панели | Навигация: обзор, персонаж/развитие, память, обращения, возможности/права, расходы/лимиты, библиотека, диагностика. Можно группировать разделы без перестройки всех экранов. Понятные русские вводные: что смотреть и когда действовать. Технические поля раскрываются в деталях. Пока OpenCode не готов, старый разговор остаётся явно временным входом. Нет мёртвой ссылки или утверждения «подключено» без готового bridge. START/STOP и активный исполнитель доступны при прокрутке/узком окне |
| PUI-02 | существующие tickets/permissions owners; независимо от OC | Довести полноценные обращения: понятный предмет/причина/ожидание, ответ обычным текстом, завершение/отказ. Для права — отдельный preview с возможностью, областями, сроком и ограничениями, затем явное подтверждение. ID/версии заполняет клиент, не оператор. Ошибка не теряет черновик; повтор того же запроса не дублирует решение. Scope выбранного профиля явно виден. Нет прав из текста ответа; устаревший preview/чужая область отклоняются сервером. Обновление/открытие карточки не вызывает модель и не запускает агента |
| PUI-03 | OC-06 и OC-07 приняты, опубликованы launcher/адрес и mapping | Завершить переход: убрать «Диалог», редактор «Разговор о работе» и создание поручения из обычной панели. Дать рабочую ссылку «Открыть OpenCode» к выбранному агенту/сессии по принятому mapping. Старые разговоры доступны только как диагностическое чтение без нового архива. Не удалять историю/Source/Job, не отменять незавершённое ради уборки UI. Владельцы и ACK не меняются. Нет двух полей отправки для одной личности |
| PUI-04 | PUI-02/03 и OC-06; общий Linux/headless стык | Один браузерный путь: сообщение в OpenCode → агент создаёт обращение → ссылка на точную карточку панели → ответ/решение → продолжение прежней сессии в OpenCode. Один owner ticket, один receipt, без новой реплики/дублирования inference из-за reload. Отказ/STOP не обходятся. Проверить двух вымышленных персонажей: ссылка не меняет адресата и не открывает чужие данные. Переход назад сохраняет выбранную сессию. Не повторять уже закрытые OC-06 сценарии полностью |

Порядок: PUI-01 → PUI-02; PUI-03/04 ждут фактически готового входа. До этого
не отключать единственный работающий путь общения. При нехватке owner API —
конкретный gap и запрос окна Codex, без обходной реализации или фиктивного UI.

## Зоны и самостоятельность

Claude: `apps/panel/src/ui/**` (включая `Workspace.tsx`, tickets, conversation),
связанные стили, panel unit/browser tests, вводные тексты и свой отчёт.
Это окно нового пакета после освобождения текущего, не разрешение перетирать WIP.
Для shared API client, validation/events, контрактов `panel.py`, `catalogue.py`
и generated заранее перечислить необходимые файлы и согласовать одного writer.
Предпочтение — существующим DTO/API; не создавать новую схему прав ради UX.

Codex: OC-01/04, native bridge, model gateway, session runtime, sandbox/harness,
local_host/launcher, Docker и Windows-приёмка OC-07. Claude не меняет эти зоны
в данном пакете. Публикация OC-01 открывает независимую реализацию OC-02/03;
готовность панели не объявляет OC-01 или native OpenCode подключёнными.

Claude сам реализует, коммитит, пушит и интегрирует выданный пакет после проверки
свежего main по doc27 §8; постоянного одобрения Codex не требуется. Enforcement
прав остаётся у owners. Если изменение затрагивает его, нужен узкий перекрёстный
разбор до включения на личном host. Новые установки, платные вызовы, права,
публичная сеть и изменение личных данных данным brief не разрешены.

## Проверки и сдача

- Один affected gate на пакет: typecheck/lint/build для затронутой панели,
  существующие подходящие unit-тесты и один meaningful browser journey.
- Повторять после падения только затронутое; полный suite не запускать ради
  текстов/навигации. Проверить узкое окно, масштаб и видимость STOP.
- Синтетические данные/провайдер; Linux не доказывает Windows/Docker.
- Отчёт `docs/implementation-reports/panel-control-simplification.md`:
  base/HEAD, что изменено, что уже было, проверки и открытые зависимости.
- Отдельные небольшие commits для независимой подготовки и отключения старых
  форм. После каждого большого пакета остановиться и сообщить результат оператору.

## Короткое сообщение для передачи

После текущей задачи возьми PUI-01/02 из этого brief: упростить панель до
управления/наблюдения и сохранить полноценные удобные обращения. Общение и
поручения целево только в OpenCode. Старые формы пока не отключай: PUI-03/04
ждут OC-06/07. Используй уже сделанные tickets-UX/прогресс, свой clean worktree
от свежего main; коммить, пушь и интегрируй свои окна самостоятельно после
affected-проверок. Gateway/runner/launcher не трогай; shared-экспорт согласуй.
После PUI-01/02 остановись с отчётом, прежде чем брать следующий большой пакет.
