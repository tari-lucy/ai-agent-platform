# Задача для пробного запуска: связный диалог и рабочая долговременная память

## Цель

Довести повседневное общение Опечатки: персонаж узнаёт доступный прошлый опыт,
сохраняет атрибуцию фактов и неопределённость, не выдумывает общие воспоминания,
после суточной обработки действительно использует полезную память. Нужен
работающий путь от сообщения до следующего ответа, а не отдельный большой benchmark.

Техническая база уже в main: приватный диалог, последние 8 реплик, API Token,
настраиваемая модель, суточная extraction→summary→reflection, MemoryCycle,
контекст сводок/claims и автоматический ACK показанного окончательного ответа.
Лимит текущего pilot 300/сутки, резерв памяти 8 внутри него; это конфигурация.

Конкретная находка: реальная изолированная проба выполнила extractor/consolidator/
reflection, создала сводку, но приняла 0 claims. Это НЕ доказанная ошибка: ввод
прямо назывался вымышленным. Нужно отличить пустой ответ модели, отклонение
валидатором цитат/типов/источников и корректное отсутствие надёжных утверждений.
Не добивайся ненулевого числа claims ослаблением правил.

## Рабочие результаты

1. Диагностика реального pipeline: accepted/rejected/skipped и безопасные причины
   отличимы. Диагностика не должна выводить raw prompt/response, диалоги, endpoint
   или ключ. Не добавляй автоматические платные retry и скрытые вызовы другой модели.
2. Если факты теряются из-за prompts/передачи ID/точных цитат/выборки — исправь
   конкретную причину. Оригинальная цитата остаётся точной; утверждение «по словам
   собеседника» не превращается в observed/canon; модель не создаёт личность/права.
3. Полезная сводка не исчезает из контекста лишь потому, что она длиннее бюджета.
   Контекст ограничен, фрагменты помечены, данные не становятся system instructions.
   Проверь русские переформулировки, устаревший факт и противоречие. Не добавляй
   вторую память, полный dump биографии или новые embeddings/модели.
4. Суточная рефлексия использует подтверждённый опыт, может оставить характер
   неизменным; только bounded policy может принять изменение. После restart
   прошлые доступные эпизоды работают, частичная порция не повторяет платный этап.
5. Дай один воспроизводимый сквозной сценарий: подтверждённый разговор → выход
   за окно последних реплик → обработка памяти → новый разговор после restart.
   Должно быть видно, какие данные увидит модель и какие были исключены.

## Узкая приёмка

На временном host/SQLite, через настоящие owners/HTTP и scripted/synthetic provider:

- тестовый собеседник сообщает предпочтение и договорённость; источник/citation
  проходит до памяти, claim имеет корректный тип, сводка сохраняет атрибуцию;
- деталь старше последних 8 реплик попадает в следующий context по доступной
  памяти; модель не получает выдуманной общей истории;
- противоречие не затирает старое как будто его не было; собственный ответ/сводка
  не дают независимого подтверждения факта;
- API-transfer revoke, TTL/delete, смена версии и отзыв во время генерации:
  закрывают использование/сохранение производного ответа; WORK/TEST разделены;
- один суточный цикл и его replay/restart не удваивают calls/records; STOP и
  пауза независимы, общий лимит/резерв не обходятся;
- реальный публичный профиль используется как fixture без его переписывания.
  Ошибка провайдера, неверный JSON, недостаточные основания — честный отказ,
  не выдуманное воспоминание и не принудительное изменение характера.

Нельзя доказать качество свободного ответа scripted-ответом — отмечай это.
Реальные API-вызовы на VPS НЕ требуются и ключи координатора не передаются.
Подготовь для координатора один отдельный opt-in probe с явным max-calls (до 6),
нормальным local env loader, публичным профилем и только synthetic conversation.
Он не использует рабочую биографию, не ставит зависимости и не запускается
автоматически из pytest. Отчёт без содержимого/секретов, usage unknown не равно 0.
Координатор выполнит его на Windows после review; paid LLM judge не нужен.

что исправлено, какие проверки пройдены, что осталось непроверенным, точную

минимальная сигнатура/семантика и тест; независимую часть продолжай.
