# GLM: независимая приёмка OpenCode перед личным запуском

Назначение оператора: подключить GLM к параллельной работе на выходные.
Цель — снять оставшиеся проверяемые препятствия запуска, а не менять архитектуру.

## База и границы

Прочитать AGENTS.md, doc27, doc30, протоколы `opencode-bridge-v1.md` и
`opencode-delivery-v1.md`, отчёты OC-04-runtime-readiness и OC-03-render-diagnosis.
Работать в отдельном checkout, ветка `codex/glm-opencode-acceptance`.

Кандидат для проверки: `origin/codex/oc-03-render-diagnosis`, код не раньше
**bda569a**. Здесь четыре патча к upstream OpenCode v1.19.3, исправления native
рендера/отправки и Windows/Docker browser smoke. Это кандидат, **не integrated main**.
Зафиксировать точные SHA кандидата и свежего origin/main; не подмешивать изменения
молча и не считать незавершённую ветку принятым runtime-интерфейсом.

Уже проверено Codex: 77 затронутых Bun-тестов; native Edge + настоящий Docker
OpenCode + синтетический HTTP-провайдер, отправка/START/доступ/ответ/ACK/reload/STOP.
Не повторять это целиком вместо трёх пакетов ниже.

## GLM-OC-A — независимый разбор границ, первым

Нужен узкий cross-review по doc27 §8, до включения нового клиента на личном host.
Читать реальный код и проверять инварианты, а не только повторять отчёты:

- HTTP/SSE: cookie, Host/Origin, Scope, чужие directory/session/utterance,
  logout/expiry, медленный клиент, конечные очереди. SSE не выдаёт тексты памяти,
  не держит модельный lease и не делает START/ACK.
- Статика: traversal/encoding, symlink/junction, overlap с host, manifest/hash/size,
  отсутствие выдачи БД/секретов и широкого SPA fallback для native API.
- Runner/model gateway: допуск и epoch перед действием/выпуском, STOP, таймаут
  проверки допуска и unknown, отсутствие повторного платного вызова при unknown.
  Docker не даёт обхода к провайдеру, host FS, терминалу или дополнительным mounts.
- Native adapter: неизвестный route не идёт в настоящий native server; browser
  persistence не хранит частный текст; точный ответ, scope и текущая редакция
  проверяются перед ACK; никакой ACK скрытой вкладки/чужого текста.

Для каждой существенной находки: файл/место, воспроизводимый сценарий, ожидаемый
и реальный результат, минимальное исправление, влияние на личное включение.
Если нарушения нет — явно указать, какой инвариант и на каком SHA просмотрен.
Называть результат reviewed, а не «вся система безопасна».

## GLM-OC-B — изоляция личности и жизненный цикл

Создать компактный дополнительный acceptance-набор на production owners,
только вымышленные профили, уникальные маркеры памяти и синтетический провайдер:

1. A и B имеют разные истории/память. Переключение просмотра не меняет активного
   исполнителя: MVP всё ещё допускает только одного активного персонажа.
2. Модельный запрос A содержит разрешённый профиль/маркер A и не содержит маркер B;
   доступ к памяти B и подмена ID отклоняются. Проверять тело синтетического
   запроса, а не заявление scripted-модели «я помню».
3. Reload/reconnect не дают START, дубль команды, вызова, ACK или опыта.
   Отзыв/TTL основания во время ожидания закрывают поздний результат.
4. STOP и restart сохраняют установленные границы; unknown не становится retry.

По возможности использовать имеющиеся fixtures/owners. Не строить второй
реестр сессий, прав, памяти, событий или подтверждений. Недоступный интерфейс
описать как конкретный gap, не обходить прямой записью в чужую БД.
Если нужен новый публичный порт — предложить минимальную сигнатуру и пример.

Это дополнительная независимая проверка, а не передача всего OC-02/06 от Claude.
Native journey с обращением/возвратом и клиентские UX-доделки остаются его зоной,
пока оператор явно не передаст её другому исполнителю.

## GLM-OC-C — Linux-сборка, если среда позволяет

На точном upstream-теге применить **все четыре** патча, использовать frozen
зависимости и Bun 1.3.14. Проверить typecheck и прежний Linux-сценарий пустой
страницы после START/reload. Windows typecheck у Codex остановился на upstream
symlink `custom-elements.d.ts`, поэтому успешная сборка не объявлена typecheck.

Дефекты адаптера и неподготовленную среду разделить. Если typecheck падает,
сравнить с чистым закреплённым upstream при одинаковых зависимостях; не ослаблять
tsconfig и не переписывать пакеты ради зелёного отчёта. Не нужны повторная сборка
после docs-only, многократный полный suite или очередной платный probe.

## Файловая зона и самостоятельность

Твои файлы: `tests/opencode_acceptance/**` и
`docs/implementation-reports/GLM-opencode-acceptance.md`. Можно самостоятельно
создавать fixtures/тесты/отчёт, исправлять свой код, делать небольшие commits
и push. Зависимости/lockfiles, core, contracts/generated, runner, launcher,
панель и native patches пока read-only: Codex/Claude не прекращают владеть ими.
Это предотвращает одновременную запись; согласование результатов каждого
теста с Codex не требуется. Изолированные production-исправления при необходимости
передаются отдельным именованным окном, не обходной копией реализации.

Не менять личный host, `.env`, права, лимиты, историю или рабочий launcher.
Не использовать личные данные/платный API, не скачивать модели, не запускать
второй runtime на общей памяти. Для tests — только новые временные host.
Не делать force push, reset/clean, не сливать кандидат в main самостоятельно.
Если Docker/Bun/browser недоступны, продолжать независимые A/B; пропуск не passed.

Сдать: base/HEAD, точные команды и результаты, найденные/исправленные дефекты,
пропуски и конкретное заключение «что блокирует личное включение». Один
affected-прогон на итоговый пакет, повтор только упавшего после исправления.
Не объявлять весь OC-06/07 закрытым своим отчётом.
