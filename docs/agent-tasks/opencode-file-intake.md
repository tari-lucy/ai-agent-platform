# OpenCode: файлы агента — просмотр, передача и уведомление

2026-10-25. Решения оператора: **выбор области** при загрузке; **до 100 МиБ на
файл** (сейчас потолок конфига 64 МиБ — поднимается); **уведомление агента** о
новых материалах в следующем ходе. Основание: концепция личного файлового
пространства (doc28 §4), родное окно как основной вход (doc30), bridge
`aw-opencode/1` и инвентаризация маршрутов 1.19.3 (`/api/fs/*`, `/file*` есть в
upstream и закрыты от native passthrough — их отвечают проекциями адаптера).
Обычная загрузка не требует новых прав агенту: это действие оператора, агент
читает файлы правами своей области.

## Результат для оператора

В родном окне OpenCode: дерево областей и файлов агента (только чтение),
загрузка файлов **вложением в сообщение** и **кнопкой «Пополнить»** с выбором
области, до 100 МиБ на файл. Агент в следующем ходе видит уведомление о
материалах и работает с ними. Панель не меняется: «Библиотека» показывает те же
файлы того же владельца.

## Задача A — платформа/bridge

Владелец окна: access/surface + local_host + workspace-файлы (окно свободно).
Всё через существующего файлового владельца (`ManagedFiles`), без второго
каталога и без raw-путей.

1. **Дерево-проекция**: чтение областей и логических путей из каталога
   (расширение `WorkplaceLibrary` или отдельный view) для адаптера; права и
   release/TTL/ledger-проверки — как у существующих файловых чтений bridge.
2. **Бинарная загрузка**: один новый ограниченный endpoint (потоково, сессия
   оператора + CSRF, параметры: область, имя, необязательный вложенный путь).
   Области для выбора: `inbox | knowledge | projects`; валидирует владелец
   (`exports` — направление агент→оператор, `scratch` — TTL-эксперименты
   агента — недоступны для загрузки оператором). Разрешена в STOPPED и не
   выполняет START. Provenance — «operator».
3. **Квоты**: поднять потолок `max_file_bytes` до 100 МиБ (104 857 600);
   scope-квота не меньше файловой; сверх квоты — честный отказ с кодом.
4. **Уведомление**: запись о материалах через существующего владельца —
   тикет-уведомление или расширение сессионного контекста (R2); конкретный
   механизм выбирает исполнитель. Критерий: следующий ход агента перечисляет
   новые файлы (имя, область, digest) без отдельного сообщения оператора.
5. **Потребление**: проверить чанковое чтение workspace-инструментом
   (offset/длина, digest) и подачу каталогизированного файла входом задачи;
   целый файл в модельный контекст не попадает.
6. **Тесты**: приёмка ниже + негативные (чужая область/scope, сверх квоты,
   без авторизации, во время записи).

## Задача B — адаптер родного окна (следующий патч серии)

1. `/api/fs/list`, `/api/fs/find`, `/api/fs/read/*`, `/file*` → мост в
   дерево-проекцию: виртуальные папки = области, пути — из каталога. Текст —
   содержимым; бинарные — карточка (размер/digest) со ссылкой на скачивание,
   без попытки рендера.
2. Вложение в поле ввода → загрузка endpoint'ом задачи A; с сообщением уходит
   ссылка на файл (вход хода), не base64 в промпт.
3. Кнопка «Пополнить» рядом с деревом: выбор области, имя, прогресс, честные
   ошибки. CSP и отсутствие браузерной персистентности не меняются; прочие
   неизвестные маршруты по-прежнему 501.

## Приёмка (один affected-прогон, синтетический провайдер, две личности)

- бинарный файл ~90 МиБ загружен из родного окна в выбранную область; дерево
  показывает его; панель «Библиотека» — тот же файл с происхождением «оператор»;
- следующий ход агента называет файл и читает содержимое чанками или в задаче —
  не в контексте модели;
- загрузка не выдаёт агенту прав, не делает START, работает при остановленном
  агенте; вторая личность не видит чужие файлы в дереве;
- отказы: чужая область, чужой scope, сверх квоты, без авторизации;
- localStorage/sessionStorage по-прежнему пусты; в UI и API нет реальных путей
  диска.

## Не цели

Монтирование папок host, второй реестр файлов, публичная передача, base64 в
чате, изменение панели, новые runtime-права агенту. Перенос личного host —
отдельным порядком по runbook.
