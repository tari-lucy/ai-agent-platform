# Claude: безопасный вывод старого runtime из эксплуатации

Поручение оператора 2026-10-29. Claude выполняет сквозную уборку кода;
Codex проверяет поставки на Windows/Docker Desktop и занимается выкладкой.
Цель — уменьшить количество действующих механизмов, сохранив рабочую схему
[doc33](../33-harness-owns-the-turn.md), данные и необходимые функции панели.

## База и границы владения

При выдаче задания `origin/main=140551c`, а работающий Windows deployment и
`origin/claude/personal-diagnostics=0caa05c`. В main ещё **нет harness_host.py**.
Сначала fetch и сверка актуальных SHA: старый main нельзя считать рабочей базой.

Ветка — `claude/legacy-runtime-cleanup` от проверенной рабочей линии
`origin/claude/personal-diagnostics` (явно разрешённый stacked workflow).
Запиши base SHA. Сведение исходного принятого baseline в main — отдельный
checkpoint без удаления кода, не смешивай исправление интеграционной базы
с рефакторингом. Не делай force push и не переписывай историю общих веток.

Claude владеет нужными для пакета backend/UI/contract изменениями после
сверки текущих писателей и объявления списка shared-файлов. Codex в это время
не правит эти файлы: его зона — Windows-пробы, отчёт и deployment. Одобрение
Codex каждого внутреннего коммита не требуется; Windows acceptance относится
к поставке пакета и выкладке. При конфликте с другим writer передай окно.

Личный host, его конфигурацию, launcher, .env и файлы оператора не меняй.
Не удаляй Docker volumes, историю, backups или ветки. Не подключай внешние
каналы, игру и платные API. Не изменяй настройки безопасности ради теста.

## 1. Сначала карта зависимостей

Кандидаты: старый native UI bridge/proxy/SSE и серия его patches, обёртка
рабочего хода, `work_session_*`, warm runner и прежний harness адаптера.
Это **кандидаты на исследование, не список разрешённого массового удаления**.

Для каждого блока запиши: входы CLI/HTTP/UI, импортирующие его модули,
используемые DTO/схемы, настройки, владельцев записей, тесты, актуальные
скрипты сборки/запуска и backup/restore. Проверь не только прямые импорты,
но и dispatch/регистрацию по строкам и fallback-ветки.

Раздели блоки: используется doc33 / нужен для чтения старых данных /
нужен старой конфигурации / доказанно не используется / неясно.
Для «неясно» сохрани код и конкретно опиши недостающую проверку.

Особенно важно: новый `local_host/harness.py` использует настройки
`work_sessions` (образ, egress, будильники и другие параметры). Старое имя
не означает неиспользуемый компонент. Не удаляй SessionBook, JobOwner,
Supervisor или весь sandbox целиком: у них могут оставаться другие потребители.

## 2. Маленькие самостоятельные поставки

1. Убери доказанно мёртвые импорты, регистрацию и недостижимый glue, сохранив
   активные пути и чтение данных. Один связный блок — один обозримый коммит.
2. Затем убирай старое исполнение/bridge/warm код только там, где зависимости
   закрыты. Общую реально используемую логику сохрани у существующего владельца;
   не создавай дубликат владельца или второй реестр ради удаления старого файла.
3. Совместимость оставляй минимальной и явной. Если старый host больше нельзя
   безопасно запускать, предложи миграцию или понятный отказ, не молчаливое
   переключение и не автозапуск. Отключение поддерживаемого fallback либо
   изменение пользовательского поведения сначала вынеси оператору как решение.
4. Устаревшие build scripts, patches, зависимости и тесты удаляй лишь после
   доказательства, что они не нужны текущему запуску, откату или поддерживаемому
   чтению истории. Не убирай падающие проверки просто ради зелёного результата.

Старые таблицы/записи/контракты чтения не уничтожай. Не делай DROP, переписывание
личной истории и разрушительную миграцию в этом пакете. Сохрани versions/CAS,
request_id/replay и ранее доступные пользовательские данные. Исторические
implementation reports не удаляй как якобы ненужную архитектуру.

## 3. Что обязано остаться рабочим

- Native OpenCode сам ведёт разговор; платформа не возвращается в каждый ход
  с lease/renew. Шлюз держит ключ и денежный бюджет; ключ не попадает агенту.
- START/HTTP readiness и независимый STOP/epoch; поздние эффекты запрещены;
  restart остаётся STOPPED, контейнеры и сети корректно завершаются.
- Постоянные файлы /workspace и inbox с диска, настройки рабочего места.
- MCP памяти/знаний/навыков/обращений; права выдаются штатным решением.
- Импорт native-разговоров в память без дублей, отзыв/TTL/ledger и жёлтая
  пометка старой сессии после удаления; удалённое не воскресает из restore.
- wake_me, продолжение в том же разговоре и отсутствие повторного срабатывания
  после STOP/restart/START; egress, его лимиты и учёт расходов.
- Настройки персонажа и чтение нужной истории, обращения с ответами и правами,
  наблюдение в панели, backup create/verify и поддерживаемый restore.
- Модерация публичного выхода и другие активные потребители jobs/sandbox.

## 4. Экономные проверки и передача Windows

На каждый пакет — затронутые тесты и нужные регрессии. Не повторяй полный
suite после каждого изменения. Lint/typecheck/import/export запускай по
реальному изменению; экспорт контрактов нужен только при изменении контракта.
Один объединённый проход в конце, без повторов при отсутствии новых изменений.
Синтетический провайдер предпочтителен, длинные и платные пробы не нужны.

После каждого самостоятельно проверяемого крупного пакета push и handoff
Codex: ветка/HEAD/base, список удалённого, сохранённая совместимость,
результаты и ограничения, точные Windows-команды, нужен ли новый образ/UI,
что меняется при откате. Пока Codex проверяет пакет, можно готовить следующий
в отдельной stacked-ветке, не переписывая уже переданный HEAD.

Codex проверяет на отдельном Windows test root: запуск/restart STOPPED,
native Web и разговор с синтетическим ответом, файлы, память/повтор,
MCP-будильник, отзыв источника/пометку, права/egress и STOP во время инструмента.
Повторять 30-минутную живую пробу после каждого удаления не требуется:
это нужно только при изменении жизненного цикла/долгого исполнения.
Личный host обновляется только в согласованное окно после STOP оператора;
сначала backup/verify и сохранённый путь отката. Удалённо его не обновляй.
