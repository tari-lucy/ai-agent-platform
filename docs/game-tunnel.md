# Мост комп ↔ сервер: игра и панель

Платформа и личность живут на сервере, а мод Minecraft (MCP на порту 25350) работает внутри игры на
компьютере оператора. Один постоянный SSH-мост с компьютера на сервер несёт две вещи, ничего не открывая наружу:

- **игру:** «обратный» туннель, сервер достаёт мод на компе (игровой трафик по нему не идёт, только команды мода);
- **просмотр:** панель (8765) и окно OpenCode (4096) сервера появляются на компе по тем же адресам `127.0.0.1`.

После входа в Windows мост поднимается сам, пароль и открытые окна не нужны.

```
мод (комп:25350) <- ssh -R <- сервер 127.0.0.1:25350 <- ретранслятор <- 172.17.0.1:25350
                                                      <- шлюз агента (host.docker.internal) <- контейнер Опечатки
```

## Что установлено

| Где | Что | Права |
| --- | --- | --- |
| Сервер, root (один раз; `--update` при изменении) | пользователь `aw-game-tunnel` без оболочки, ключ только его, `PermitListen 127.0.0.1:25350`, `PermitOpen 127.0.0.1:8765 127.0.0.1:4096`, `ClientAliveInterval 30` | `deploy/game-tunnel/install-game-tunnel-account.sh` |
| Сервер, пользователь | служба `ai-game-relay` (мост Docker → loopback), источники только сеть `172.17.0.0/16`, не больше 8 соединений | `deploy/game-tunnel/game_relay.py` |
| Комп, пользователь | задача Windows «AI Agent Platform - Game Tunnel» при входе, повтор каждые 15 секунд, закреплённый ключ сервера; настройки в `local.game-tunnel.json` (`port`, `bridge_ports`) | `scripts/start_game_tunnel.ps1`, `register_game_tunnel.ps1` |

Токен мода по-прежнему лежит у Опечатки (в её папке). Ретранслятор открывает порт на мосту Docker, куда
доходят и другие контейнеры сервера, но пускает только источники из сети моста по умолчанию (контейнеры
n8n живут в своей сети и отклоняются), а доступ к моду всё равно требует токена.

Если на компе уже висит вручную открытый `ssh -L 8765…`, его надо закрыть: порт занят, и мост не поднимется.

## Обрыв без предупреждения (свет, сон, сеть) и сторож на сервере

Когда компьютер пропадает внезапно, сервер до 15 минут считает старое соединение живым: оно молчит,
но держит обратные порты (8001, 4455, 8003, 8004, 25350). Новое соединение с компьютера находит порты
занятыми, `ssh` выходит (`ExitOnForwardFailure`), и ярлык «включить» перебирает попытки впустую.
Проверка живости в `sshd` на такое соединение не действует, потому что ядро застряло на пересылке в пустоту.

Поэтому на сервере стоит сторож (`deploy/game-tunnel/aw_tunnel_reaper.py`, таймер systemd раз в 20 секунд,
от root): он закрывает только процессы `sshd: aw-game-tunnel`, от которых не было ни байта 75 секунд
(живой туннель присылает весть каждые 15 секунд). Установка один раз:
`sudo bash deploy/game-tunnel/install-tunnel-reaper.sh`. Снять: `sudo systemctl disable --now
aw-tunnel-reaper.timer` и удалить `/usr/local/sbin/aw-tunnel-reaper`, `/etc/systemd/system/aw-tunnel-reaper.*`.
Журнал: `journalctl -u aw-tunnel-reaper`.

## Мост звука вместе с туннелем

Ярлыки «включить/выключить» запускают и останавливают заодно мост звука (скрытно, без окон), если в
`local.game-tunnel.json` есть раздел `audio`:

```
"audio": {"script": "C:/ai-pers2/runtime/pc_audio_bridge.py", "port": 8003, "device": "6"}
```

Для слуха добавляются `capture_port`, `capture_device`, `capture_rate`. Ошибки моста звука пишутся в
`audio.err`, ошибки `ssh` в `ssh.err` рядом со скриптом туннеля (`C:\ai-pers2\runtime\game-tunnel`).

## Откат

На компе: отключить и удалить задачу «AI Agent Platform - Game Tunnel». На сервере: остановить и выключить
`ai-game-relay`; для полного удаления учётной записи убрать `/etc/ssh/sshd_config.d/81-aw-game-tunnel.conf`
и `/var/lib/aw-game-tunnel`, затем `sshd -t` и `systemctl reload ssh`.

## Если панель или OpenCode не открываются

Цикл (`start-game-tunnel.ps1`) сам следит за туннелем: один экземпляр на машину (mutex),
свой `ssh` пишет PID в `ssh.pid` рядом со скриптом, раз в 10 секунд смотрит TCP-соединение
`ssh` с сервером. Если сервер его уже закрыл (CLOSE_WAIT и подобное), а `ssh` завис (известное
поведение OpenSSH на Windows) и держит порты 8765/4096, цикл через три проверки завершает
свой `ssh` и запускает новый; быстрые отказы повторяются с растущей паузой до минуты.
Журнал: `tunnel.log` рядом со скриптом (время и фиксированные слова, без адресов и ключей).

Ручной перезапуск: `schtasks /run /tn "AI Agent Platform - Game Tunnel"`. Задача в состоянии
«Готово» значит, что цикл не работает; запуск поднимет его. Старый зависший `ssh.exe`
завершается по номеру (`taskkill /PID <номер> /F`), поиска и убийства чужих процессов нет.

## Как открывать и закрывать

Обычно ничего делать не нужно: задача «AI Agent Platform - Game Tunnel» стартует при входе в
Windows, сама переподключается (около минуты) и пробрасывает порт мода `25350` на сервер.
Наружу ПК не открывается: вход только по ключу ограниченной учётной записи сервера.

Порядок игры: войти в Windows (туннель уже есть) → запустить Minecraft с модом и зайти в мир →
START агента в панели.

Проверка: `schtasks /query /tn "AI Agent Platform - Game Tunnel"` (должно быть «Выполняется»;
«Готово» значит, что цикл не работает) и последние строки `tunnel.log`.

Открыть вручную: `schtasks /run /tn "AI Agent Platform - Game Tunnel"`.

Закрыть: сначала STOP агента или выход из игры, закрыть Minecraft, затем
`schtasks /end /tn "AI Agent Platform - Game Tunnel"`. Убедиться, что `netstat -ano | findstr :25350`
пуст; если остался `ssh.exe`, его номер в `ssh.pid` рядом со скриптом
(`taskkill /PID <номер> /F`). Закрывать каждый раз не обязательно: без открытой игры порт мода
мёртв.

Если агент пишет «таймаут» или «мод не отвечает»: открыт ли Minecraft и в мире ли игрок (в меню
мод может молчать); жив ли туннель (проверка выше); не включена ли автопауза при потере фокуса
(F3+P).
