# Голос личности: стримы, войс-чат Minecraft, голосовые в Telegram

План 2026-10-29. Решения D84–D87 — **предложение на утверждение оператора**. Основа —
[doc33](33-harness-owns-the-turn.md): разговором владеет харнес, платформа — сервис вокруг
него. Реализация — Claude Code.

## 1. Что нужно

Оператор хочет, чтобы Опечатка говорила вслух и слышала:

- на **стримах**;
- в **голосовом чате Minecraft** (мод войс-чата у оператора есть, у бота — свой клиент);
- **голосовыми сообщениями в Telegram-канале**.

Провайдер — **Soniox**: распознавание и синтез речи, 60+ языков, потоковый WebSocket.
Его выбрал оператор: устраивают цена и качество.

## 2. Решения (предложение)

| ID | Решение | Следствие |
| --- | --- | --- |
| D84 | Голос — сервис платформы на хосте. Синтез и распознавание через Soniox, ключ только в `.env` | В контейнере агента нет ни звуковых устройств, ни ключа. Агент получает MCP-инструменты: «сказать» в выбранное место и «что я слышу» текстом |
| D85 | Голосовое в Telegram-канал — публикация от имени личности | Модератор проверяет точный текст до синтеза; недоступен модератор — голосовое не уходит. Подключение Telegram (бот, канал) выдаёт оператор, токен бота лежит в `.env` |
| D86 | Живая речь на стриме и в войс-чате — **решает оператор** | Вариант А: модератор на каждую фразу, +1–2 с к фразе. Вариант Б: без построчной модерации, под журналом, с лимитом и STOP, как работа в сети по D75 |
| D87 | Слушать не постоянно, а когда к ней обращаются: по имени или по кнопке | Каждая распознанная фраза — сообщение в сессию харнеса и вызов модели, то есть деньги. Постоянное слушание — отдельное решение |

### Решение оператора 2026-10-29

- **Канал — бот**, а не аккаунт. Аккаунт оператор заведёт позже: для групп, лички и голосовых чатов Telegram.
- **Посты уходят сразу**, без одобрения в панели.
- **Защита от запрещённого по закону — два уровня:**
  1. Список тем в описании личности.
  2. Перед каждым постом — облегчённая проверка (D85). Это один короткий вызов той же модели по этому списку. Проверка отказала, ответила непонятно или недоступна — пост не уходит, агент получает причину.
- **Список тем** правит оператор: `data/harness/public-rules.txt` в корне host. Он действует всегда, для всего публичного: чат игры, стрим, канал. Файл создаётся с черновиком при первом запуске.
- **Живая речь (D86):** без построчной модерации. Действуют список тем в описании, журнал и STOP.

Включение:

- в локальном `.env`: `AI_PLATFORM_TELEGRAM_BOT_TOKEN`, а для голосовых — `AI_PLATFORM_SONIOX_API_KEY`;
- команда: `configure-harness --channel @имя [--channel-voice <голос>]`;
- выключение: `--remove-channel`.

Журнал постов — `data/harness/channel.jsonl`. Он локальный и в Git не попадает.

Для закрытого выхода через собственный VPS — [SSH-прокси Telegram](telegram-proxy.md).
Токен остаётся у платформы; настройка маршрута не меняет проверку постов и STOP.

## 3. Как устроено

```
Опечатка (OpenCode в контейнере)
   │ MCP platform_speak(target, text) / platform_heard()
   ▼
платформа на хосте ── модератор (D85; D86-А) ── Soniox TTS ──┬─▶ Telegram sendVoice (канал)
                                                             ├─▶ аудиовыход «Опечатка → стрим» (OBS)
                                                             └─▶ виртуальный микрофон бот-клиента Minecraft
вход «то, что она слышит» ── Soniox STT (поток) ── по имени ──▶ сообщение в сессию харнеса
```

- **Звук на компе** идёт через виртуальные аудиоустройства, например VB-Cable. Их ставит оператор.
  - **Стрим:** выход «Опечатка» подключается в OBS как источник звука.
  - **Minecraft:** бот-клиент получает виртуальный микрофон с её голосом и виртуальные динамики, которые она слушает. Это работает с любым модом войс-чата, без правок мода.
- **Голос Soniox** выбирается в настройках, один на личность. Подбирают оператор и Опечатка.
- **STOP** обрывает речь на полуслове, прекращает слушание и отменяет неотправленные голосовые.
- **Журнал речи:** что сказано, куда, сколько стоило. Он локальный: может содержать личное, в Git не попадает.
- **Деньги:** синтез и распознавание считаются в тот же суточный бюджет D76 по тарифу Soniox.

## 4. Этапы

| Этап | Содержание | Приёмка |
| --- | --- | --- |
| V1. Голосовые в Telegram | Подключение Telegram (бот, канал); `platform_speak(target="telegram")`: модератор → Soniox TTS → OGG/Opus → `sendVoice` | Голосовое её голосом появилось в канале; без модератора не уходит; STOP отменяет |
| V2. Голос на стриме | Аудиовыход на выбранное устройство; `platform_speak(target="stream")` с решением D86 | Фраза слышна в OBS; STOP обрывает |
| V3. Слушать | Потоковое распознавание с выбранного входа, срабатывание по имени или кнопке; фраза уходит в сессию | Сказанное с её именем доходит до неё текстом и получает ответ голосом |
| V4. Войс-чат Minecraft | Виртуальный микрофон и динамики бот-клиента; цели `minecraft` для speak и heard | В войс-чате игры она отвечает голосом на обращение |

## 5. Что проверить до кода

- Есть ли у Soniox русский для синтеза и какие голоса. Цена синтеза и распознавания за минуту или символ: для тарифа и бюджета.
- Какой мод войс-чата стоит у оператора (Simple Voice Chat или другой), и умеет ли его бот-клиент выбирать аудиоустройство.
- Чей бот в Minecraft: второй аккаунт или аккаунт оператора. Это вопрос doc33 о подключении игры.
- Telegram: есть ли бот, и какой канал.
