# Выбранный стек и составная память

Дата: 2026-10-13. Статус: базовый выбор для реализации в рамках поручения
завершить планирование. Совместимость storage/MiniLM и малый resource probe проверены в M0-03;
60-query/1k/10k acceptance остаётся M0-05. Ниже выбор, основания и условия замены.
Это продолжение [исследования памяти](12-memory-research.md), а не перенос
зависимостей предыдущего проекта.

## 1. Базовый стек текстового MVP

| Область | Выбор | Граница ответственности |
| --- | --- | --- |
| Runtime | CPython 3.14, обычная сборка с GIL; uv | Linux-образ Docker; точный patch и digest после проверки M0 |
| Ядро/API | FastAPI, Pydantic 2, pydantic-settings, Uvicorn | HTTP JSON, OpenAPI, WebSocket; один процесс владеет состоянием |
| Точные данные | SQLite, SQLAlchemy 2, aiosqlite, Alembic | Транзакции владельцев, явные миграции, оптимистические версии |
| Recall | SQLite FTS5 + sqlite-vec за заменяемым интерфейсом | Производные индексы; проверка источников перед выдачей |
| Embeddings | FastEmbed/ONNX Runtime CPU | Один загруженный embedder; ограниченные batch/потоки |
| LLM | HTTPX AsyncClient + httpx-sse в собственном адаптере | OpenAI-совместимый Chat Completions, streaming, отмена, usage |
| Очередь | Redis Streams; redis-py asyncio | Broker-адаптер; задания/outbox и решения остаются у ядра |
| Панель | TypeScript, React 19, Vite, Mantine, React Router, TanStack Query | Один SPA; типы API из серверной схемы при реализации |
| Сборка панели | Node.js 24 LTS | Только build stage; отдельный Node-сервис не требуется |
| Проверки | pytest и Playwright; синтетические fixtures | Контракты, сбои, сценарии персонажа, браузерный цикл |
| Развёртывание | Docker Compose: core, worker, Redis | Windows-приложения позже подключаются нативными мостами |

CPython 3.14 находится в ветке bugfix с поддержкой до октября 2030 года;
Node.js 24 отмечен LTS. Это основания выбора веток, не обещание совместимости
всего набора. [Python](https://devguide.python.org/versions/),
[Node.js](https://nodejs.org/en/about/previous-releases).

FastAPI предоставляет OpenAPI и интеграцию с Pydantic. Асинхронный SQLAlchemy
поддерживает SQLite через aiosqlite; режим транзакций зададим явно и проверим
на выбранном Python. [FastAPI](https://fastapi.tiangolo.com/features/),
[SQLAlchemy/SQLite](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html),
[Alembic](https://alembic.sqlalchemy.org/en/latest/).

Выбор SPA с Vite соответствует документации React; Mantine даёт компоненты,
TanStack Query обслуживает серверные проекции, Router — навигацию.
Состояние агента принадлежит API, состояние формы — панели.
[React](https://react.dev/learn/build-a-react-app-from-scratch),
[Mantine](https://mantine.dev/getting-started/),
[TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview),
[React Router](https://reactrouter.com/start/declarative/installation).

Не вводим обязательный framework агентной оркестрации. Владелец области,
команды, задания, допуски и событийные контракты уже определены проектом;
выбранные библиотеки их обслуживают. Для HTTP/SSE повтор запроса определяет
наша политика: библиотека httpx-sse не обеспечивает автоматическое
переподключение. [HTTPX](https://www.python-httpx.org/async/),
[httpx-sse](https://github.com/florimondmanca/httpx-sse).

## 2. Что где хранится

| Вид данных | Авторитетный источник | Поиск и читаемое представление |
| --- | --- | --- |
| Принятый профиль, канон и правила развития | Версия профиля, принятая владельцем; ссылка на snapshot | Markdown — редактируемый проект/принятый snapshot, без самовольного hot reload |
| Живые свойства, отношения, обещания, вопросы, права, состояния и расходы | SQLite соответствующего владельца | Точные фильтры и проекции панели; recall не решает, выполнено ли обещание |
| Разговоры, наблюдения, эпизоды и источники | Каталог источников в SQLite и разрешённое содержимое в локальном архиве | FTS5/векторы по допустимым фрагментам; полные разговоры — 30 дней |
| Дневник, сводки, значимые выдержки | Принятые записи с происхождением и версиями | Markdown-экспорт удобен человеку; производная сводка не становится новым независимым свидетельством |
| Медиа | Локальные файлы + каталог/права/ссылки в SQLite | Превью и описания; файлы не помещаются в Redis или prompt автоматически |
| Индексы/кэш | Производные данные | Можно перестроить из ещё допустимых источников; удалённое не восстанавливается |

Профиль и история конкретного экземпляра разделены. Изменение инструмента
recall не переносит канон или отношения во внешний движок. Правки Markdown
проходят импорт, проверку и применение новой версии; живую БД не синхронизируем
с файлами двунаправленно без явной команды.

SQLite работает в WAL; запись сериализуется короткими транзакциями.
БД находится в Linux named volume Docker, не в Windows bind mount и не на
сетевом диске. Worker возвращает результат через API владельца, не открывает
основную БД для записи. WAL допускает одного writer одновременно и не
подходит сетевой файловой системе. [SQLite](https://www.sqlite.org/wal.html).

## 3. Выбор recall и моделей

Базовый embedder — `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`:
384 измерения, штатная модель FastEmbed. В списке проекта указан артефакт
около 0,220 GB; это размер модели, а не измеренная RAM процесса.
[Список FastEmbed](https://qdrant.github.io/fastembed/examples/Supported_Models/).

`intfloat/multilingual-e5-small` включаем в сравнительную пробу. FastEmbed
показывает его через регистрацию custom model; это дополнительная настройка
адаптера и корректного формата query/document. Не считаем его штатным
переключателем или уже проверенной связкой.
[FastEmbed](https://github.com/qdrant/fastembed).

В текущем manifest FastEmbed для Python 3.14 предусмотрен ONNX Runtime
не ниже 1.24.2. Это аргумент для проверки Python 3.14, а не готовый lockfile.
[Manifest проекта](https://raw.githubusercontent.com/qdrant/fastembed/main/pyproject.toml).

sqlite-vec остаётся до версии 1.0: upstream предупреждает о возможных
несовместимых изменениях. Загружаем только поставленное и закреплённое
расширение, без пути из пользовательского текста. Совместимость, загрузку
на каждой нужной DB connection и миграцию проверяет M0.
[sqlite-vec](https://github.com/asg017/sqlite-vec).

Recall состоит из: точного контекста незавершённых дел/участников → фильтров
области/прав → FTS5 и векторного поиска → объединения рангов и удаления дублей →
проверки актуальных источников. Начальный предел — 8 фрагментов, до 2 000
токенов контекста памяти; значения конфигурируемы. Не добавляем отдельный
нейросетевой reranker в первую версию. При отказе embeddings остаются точные
запросы и FTS5, а неполнота явно видна. Такой режим не подменяет проверку
качества окончательно выбранного recall.

## 4. Почему не MemPalace или LightRAG в основе

MemPalace — сравнительный адаптер архива/recall. Он предлагает локальный поиск
и организацию памяти; default backend — Chroma, есть альтернативы. В manifest
Chroma остаётся обязательной зависимостью даже при иной настройке backend.
Отсюда необходимость измерить весь фактический набор, а не считать его
заведомо легче нашей базы. [MemPalace](https://github.com/MemPalace/mempalace),
[его manifest](https://raw.githubusercontent.com/MemPalace/mempalace/develop/pyproject.toml).

Для пилота используем только синтетический корпус этого проекта. Автоматический
импорт архивов Codex, NetTyan или личных диалогов не нужен. Собственные форматы
движка должны уважать 30-дневный срок, удаление, изоляцию и происхождение.
Если они обходят эти правила, адаптер не допускается независимо от recall.

LightRAG сохраняем как последующий инструмент базы знаний для документов,
описаний миров и материалов. Это наш вывод о роли в платформе: граф поиска
не должен владеть отношениями и устойчивым состоянием персонажа.
[LightRAG](https://github.com/HKUDS/LightRAG).

Не устанавливаем все конкурирующие движки сразу. Mem0, Graphiti, Letta,
Qdrant/PostgreSQL остаются материалом [сравнения](12-memory-research.md),
а не скрытыми зависимостями MVP.

## 5. Проба с заранее заданными критериями

| Проверка | Данные и метод | Критерий/решение |
| --- | --- | --- |
| Совместимость | Целевой образ, FTS5, расширение, embedder, restart, delete, rebuild | Все операции проходят; иначе закрепить совместимую комбинацию или адаптер |
| Recall | 60 размеченных русских запросов; 1 000 и 10 000 фрагментов; точные имена, перефразировки, даты, конфликты | Recall@8 ≥ 0,85 для запросов с допустимым ответом; точные обязательства проверяются отдельно |
| Достоверность | Слепая оценка ответов по выбранным источникам | ≥ 90% вопросов с корректной атрибуцией/отказом при нехватке данных; ни одного недопустимого раскрытия |
| Изоляция/удаление | Похожие ники, разные личности/площадки, просроченные и удалённые источники | Ноль попаданий чужих/удалённых данных, включая кэш и восстановление |
| Ресурсы | Отдельно cold start, peak indexing, warm query + query embedding | Цель p95 ≤ 500 мс на 10 000 фрагментов; recall/embedding worker ≤ 1,5 ГиБ RAM |
| MemPalace/E5 | Те же вопросы и допустимые источники; одинаковый embedder, где возможно | При разных embeddings сравниваем конфигурации целиком и отмечаем различие |

Пороги — принятые цели будущей проверки, не опубликованный результат. Если
baseline проходит их, MVP не ждёт необязательного MemPalace-пилота. Если
baseline не проходит, сравнение становится задачей до приёмки памяти. Замена
backend оформляется записью решения, экспортом источников и повтором проверок.
100 000 фрагментов — последующий тест роста, не требование MVP.

## 6. Бюджет машины и политика версий

Проверено 2026-10-13: i5-12450H, 8 ядер/12 потоков, 15,71 ГиБ доступной
системе RAM, RTX 3050 Laptop 4 ГиБ. Во время снимка свободно 4,69 ГиБ RAM
и около 506,84 ГиБ на диске C. Свободный ресурс меняется; это не benchmark
платформы и не запас для одновременно запущенных Minecraft/VTS/OBS.

Начальные бюджеты: core до 768 МиБ; worker до 1,5 ГиБ; Redis container до
256 МиБ, `maxmemory` 128 МиБ с `noeviction`; один embedder, 2 CPU threads,
batch 4. Цель общей текстовой платформы с Docker/WSL — до 4 ГиБ RAM.
Разница между суммой контейнеров и всей платформой проверяется измерением.
При нехватке памяти сначала прекращаем фоновую индексацию/сравнения и снижаем
batch; не запускаем вторую модель автоматически.

Выбираем стабильную поддерживаемую ветку Redis 8 и фиксируем patch/image digest
в M0. Redis 8 имеет варианты лицензии RSALv2/SSPLv1/AGPLv3; запись выбранного
варианта и notices входит в инвентаризацию зависимостей. Приложение планируется
под MIT, зависимости сохраняют свои условия. Сам факт использования отдельного
Redis-сервиса не даёт основания переобъявить его лицензию MIT.
[Redis licenses](https://redis.io/legal/licenses/),
[MIT](https://opensource.org/license/mit).

M0 фиксирует exact versions, lockfiles, image digests и model revision/checksum
после реальной сборки/проб. Если Python 3.14 не проходит совместимость,
первый запасной вариант — Python 3.13 с записью причины. Обновления проходят
backup, совместимость/миграцию и сценарные проверки; плавающий `latest` не
является принятой эксплуатационной конфигурацией.
