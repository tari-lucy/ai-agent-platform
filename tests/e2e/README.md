# Сквозной синтетический набор (M5-03)

Один непрерывный цикл **вход → диалог → перезапуск → повторная встреча → развитие → удаление → STOP**,
только синтетические данные и скриптованная mock-модель; реальная SQLite, FTS5/sqlite-vec и файлы на диске,
без сети, платных вызовов, публикации и `.env`.

- `test_cycle.py`: цикл в **одном мире** через `LabRunner` (M3-04): диалог и память, перезапуск без самозапуска,
  узнавание человека и известный ответ без повторного вопроса, развитие по двум независимым опытам, удаление через
  `RetentionService` (M5-01) с проверкой **байтов** БД, WAL и индекса, STOP посреди генерации. Автоматические жёсткие
  инварианты раннера (только тест-область, изоляция от рабочей, никаких неописанных вызовов модели, STOP соблюдён,
  нет секретов в отчёте), повтор по seed с тем же отпечатком, другой seed — другой отпечаток, рабочая память не тронута.
  Вход, STOP и выход идут через **настоящее** ядро (ASGI): вход не запускает агента, повторный STOP ничего не меняет,
  бизнес-команды остаются закрыты (503) до композиции владельцев, секреты не попадают в ответы.
- Браузерный вариант того же пути: `tests/panel/test_journey.py` (настоящие вход/STOP/выход, проекции и бизнес-команды — mock).

## Запуск

Из `scripts/check_combined.py` (каталог входит в общий набор). Отдельно:

```text
PYTHONPATH=<источники>:tests/e2e:tests/laboratory:tests/retention:tests/memory:tests/usage \
  python -m pytest tests/e2e --import-mode=importlib -q
```

Браузерный сценарий — как остальной `tests/panel`: нужны собранная панель и установленный Chromium
(`tests/panel/README.md`).

## Что набор не доказывает

Зелёный mock-цикл проверяет согласованность владельцев и границы безопасности, а не качество личности или LLM
(это M5-04). Бизнес-маршрутов в core нет: HTTP-путь «сообщение → ответ» не проверяется, диалоговая часть идёт
внутри процесса через лабораторию.
