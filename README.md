# AI Agent Platform

Рабочее место для ИИ-персонажей: с характером, памятью, отношениями, собственными
занятиями и инструментами. Персонаж может общаться, накапливать опыт, вести
заметки и создавать навыки в пределах разрешений и бюджета.

Первый персонаж проекта — **Опечатка**, корреспондентка «Вестника Четвёртой
Стены». Её [публичный пример профиля](profiles/examples/opechatka/profile.md)
лежит в репозитории. Платформа рассчитана и на другие личности и задачи;
сейчас одновременно работает один активный персонаж.

## Что уже есть

- Настраиваемый профиль: канон, манера речи, черты и границы развития.
- Текстовый разговор через LLM API, история и долговременная память:
  факты, сводки, опыт, отношения и обещания.
- Автоматические циклы памяти и рефлексии при включённом автономном режиме.
  Изменения характера опираются на сохранённый опыт и ограничения профиля.
- Рабочие сессии через OpenCode в Docker: разрешённые операции с файлами,
  заметками, навыками и обращениями к оператору.
- Веб-панель: настройки, память, библиотека, расходы, разрешения и START/STOP.
- Обращения: агент сообщает о проблемах, предлагает идеи и запрашивает новые
  возможности; оператор отвечает и принимает решения в панели.
- Локальное хранение, сроки хранения, резервные копии и контролируемое
  восстановление. Рабочие и тестовые данные разделены.

**Состояние на 23 октября 2026:** текстовый агент и панель работают.
Родной **Web-интерфейс OpenCode ещё подключается**. Серверная часть подготовлена;
браузерный клиент ещё нужно собрать и проверить вместе с платформой.
Пока общение доступно через временные разделы панели.

Minecraft, Telegram, голос, аватар и стримы — следующие интеграции.
Вход рабочего контура через аккаунт ChatGPT пока не подключён.

## Где общаться и где управлять

| Интерфейс | Для чего | Сейчас |
| --- | --- | --- |
| **Web OpenCode** | Основное окно общения и поручений, выбор персонажа и сессии, работа с материалами | Подключается |
| **Панель платформы** | Персонаж, память, настройки, расходы, диагностика, START/STOP и полноценные обращения | Работает |
| **Временные формы разговора в панели** | Общение до подключения нового входа | Сохраняются на время перехода |

После приёмки нового входа обычное общение переедет в OpenCode. Панель останется
местом управления и наблюдения; отвечать на обращения и выдавать права можно
будет в ней. История и память сохраняются у платформы.

## Как запустить

### Если рабочее место уже настроено на Windows

1. Запустите Docker Desktop и дождитесь его готовности.
2. В корне проекта откройте **`start-panel.cmd`**.
3. Оставьте окно сервера открытым. Браузер откроется автоматически;
   адрес также появится в окне сервера. Войдите с паролем оператора.
4. После запуска сервер держит персонажа в состоянии **«Остановлен»**.
   Нажмите **«Старт»**, когда будете готовы разрешить работу.

Для остановки нажмите **«Стоп»**, затем закройте сервер через **Ctrl+C**.
Закрытие вкладки браузера само по себе сервер не останавливает.

Скрипт запуска берёт пути из локального `config/local.launcher.json`. Он не обновляет
рабочую установку и не пересобирает интерфейс: новый `git pull` в соседней копии проекта
сам по себе не обновит работающую версию. Не запускайте второй сервер на тех же
личных данных и не повторяйте `init` для существующего host.

Подробнее: [проверка настроенного MVP](docs/manual-mvp-check.md).
Подключение нового интерфейса:
[порядок обновления OpenCode](docs/opencode-deployment-runbook.md).

### Если это новая копия проекта: технический пример без API

Нужны **Python 3.14.8**, **uv 0.12.23**, **Node.js 24.19.0** и **npm 11.17.0**.
Команды ниже предназначены для PowerShell в корне своей копии репозитория.
Установка зависимостей может обращаться к пакетным репозиториям.

```powershell
uv sync --locked --python 3.14.8
npm.cmd ci --prefix apps/panel
npm.cmd run build --prefix apps/panel

$DemoRoot = Join-Path $PWD 'runtime\demo-host'
uv run --locked --no-sync python -m ai_agent_core.local_host init --root $DemoRoot --port 8877
uv run --locked --no-sync python -m ai_agent_core.local_host serve --root $DemoRoot --provider mock --panel-dir (Join-Path $PWD 'apps\panel\dist')
```

`demo-host` должен быть новым пустым каталогом. Откройте
**http://127.0.0.1:8877**. Пароль входа находится в
`runtime/demo-host/secrets/operator-password.txt`; не публикуйте его.

Это mock-режим для знакомства с системой: без платных вызовов, настоящей модели
и рабочего контура OpenCode. Docker для этого примера не нужен.
Живой API и рабочая среда настраиваются отдельно по
[инструкции local host](docs/local-host-setup.md).

## Как устроен агент

У одной личности два связанных контура:

- **Личность и опыт:** профиль, память, отношения, обещания, рефлексия и развитие.
- **Деятельность:** рабочие разговоры, задачи, файлы, навыки и инструменты.

OpenCode — рабочая среда персонажа. Платформа хранит его личность и опыт,
проверяет доступ и управляет исполнением. Модели назначаются по ролям:
разговорный и рабочий контуры могут использовать разные подключения.
Изменение памяти и поведения не означает обучение весов LLM.

После явного запуска агент может сам выбирать занятия в пределах выданных
прав и общего бюджета. Каждый обычный шаг не требует ручного подтверждения.
Новый инструмент, расширение доступа или помощь оператора запрашиваются
обращением. Созданный агентом навык сам по себе никаких прав не даёт.

## Данные и границы доступа

Локальный сервер доступен только с этого компьютера (`127.0.0.1`). OpenCode исполняется
в ограниченном Docker-контейнере; файлы и инструменты доступны через проверяемые
операции платформы. Доступа ко всему диску компьютера у агента нет.
STOP и проверка прав не зависят от ответа модели; перезапуск не делает START.

Ключи и адрес API хранятся в локальном `.env`. Пароли, личные профили, диалоги,
базы и резервные копии не входят в Git. В репозитории — код, документация и
публичные примеры. Тестовая память отделена от рабочей.

## Для разработки

Backend — **Python / FastAPI / Pydantic**, панель — **TypeScript / React / Vite**,
основное локальное хранилище — **SQLite**. Версии зависимостей закреплены
в `uv.lock` и `apps/panel/package-lock.json`.

| Каталог | Содержание |
| --- | --- |
| `apps/core`, `apps/worker`, `apps/panel` | Приложения и панель |
| `packages/` | Контракты, предметная логика, сценарии и адаптеры |
| `profiles/examples/` | Публичные примеры персонажей |
| `docs/` | Концепция, планы, протоколы и отчёты проверок |
| `deploy/` | Docker и инфраструктура развёртывания |
| `runtime/` | Локальные данные и окружения; не входят в Git |

Перед изменениями прочитайте [AGENTS.md](AGENTS.md) и
[правила параллельной работы](docs/27-coding-agents-workflow.md).
Разработчики работают в отдельных ветках и checkout. Проверки выбираются
по затронутой области; полный suite не нужен для каждой небольшой правки.
